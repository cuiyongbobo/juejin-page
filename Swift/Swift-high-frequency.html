一、类型与可选值

1. 类、结构体、枚举有什么差别？赋值之后谁和谁共享状态？

口述版

  • 类是引用类型。赋值时复制引用，两个变量可以指向同一个实例；通过其中一个变量修改这个实例，另一个变量也能看到。用 === 判断两个引用是否指向同一个实例。
  • 结构体和枚举是值类型。赋值后，两份值可以独立修改。不过，值里面如果保存了类引用，引用指向的对象仍可能共享。
  • “独立修改”是语言行为，不代表赋值时一定立即复制全部底层内存。Array 等类型会利用写时复制减少开销，见第 26 题。
  • 一般优先考虑结构体。需要共享同一个对象、判断对象身份或使用类继承时，可以选择类。

解析

先分清“修改变量”与“修改对象”。引用就像对象的地址信息。类赋值复制的是这份信息，并没有因此创建第二个对象。结构体赋值则得到可独立修改的值；结构体内部的类属性仍然保存引用。

class Room {
    var name = "A"
}
struct Note {
    var title: String
    var room: Room
}

let a = Room()
let b = a
b.name = "B"
print(a.name)       // B，a 和 b 指向同一个 Room
print(a === b)      // true

let first = Note(title: "第一份", room: Room())
var second = first
second.title = "第二份"
print(first.title)  // 第一份，外层的值可独立修改
second.room.name = "新房间"
print(first.room.name) // 新房间，里面的 Room 仍然共享

枚举用来表达几种可能状态，例如加载中、成功、失败；一个枚举值在同一时刻只能是其中一种状态。结构体和枚举不支持类继承。它们的实例方法需要修改自身属性或整个值时，通常要标记 mutating。

对象身份是“是不是同一个实例”，不同于“内容是否相等”。类可以用 deinit 在实例销毁时收尾；本题讨论普通、可复制的值类型，非复制类型的特殊生命周期规则属于进阶内容。

值类型不等于一定放在栈上，引用类型也不能仅凭一个变量的位置来判断对象位置。栈和堆是内存管理方式，具体存储受使用场景和编译器优化影响，不应拿来定义值类型与引用类型。

2. 枚举的关联值和原始值有什么区别？

口述版

  • 原始值是枚举选项在声明时确定的固定值，所有选项的原始值类型相同。通过 init?(rawValue:) 查找对应选项，匹配失败返回 nil。
  • Int 原始值可自动推导：首个选项未指定时默认为 0，后续选项未指定时取前一个原始值加 1。
  • 关联值是在创建枚举值时附带的数据，不同选项可以声明不同类型、不同数量的关联值，同一选项的不同实例也可以携带不同数据。
  • 同一个枚举不能同时声明原始值类型和带关联值的选项。

解析

case 是枚举中的一个选项，例如下面的 north、east。原始值在声明枚举时确定，同一个选项总是对应同一个原始值。所有选项的原始值类型相同，例如都用 Int。想从整数查到对应选项，可以调用 Direction(rawValue: 整数)；返回的是 Direction?，查不到就得到 nil。

关联值到创建这个值时才放进去。不同 case 可以带不同的类型，运行时这个枚举值只处于其中一个 case。

import Foundation

enum Direction: Int {
    case north // 0，第一个省略才是 0
    case east  // 1，前一个加 1
    case south = 5
    case west  // 6，接前一个，不是回到 0
}
print(Direction(rawValue: 0) == .north) // true，0 对应 north
print(Direction(rawValue: 3) as Any)    // nil，没有选项对应 3

enum LoadState {
    case success(Data)
    case failure(Int)
}
let state = LoadState.success(Data())

同一个枚举不能一边写 : Int 声明原始值类型，一边又给 case 声明关联值。原始值例如 north 永远对应 0；关联值例如 success 可以在这次保存一份 Data，下次保存另一份 Data。

3. 可选值是什么？接口边界怎么处理，什么情况下 ! 是合理的？

口述版

  • 可选值表示“这里可能有一个值，也可能没有”。String? 是 Optional<String> 的简写。
  • Optional 是枚举：.some(value) 表示有值，.none 表示没有；平时用 nil 表示没有值。
  • 用 if let 或 guard let 取出值；用 ?. 在有值时继续访问，用 ?? 提供没有值时的默认值。
  • ! 是强制解包：有值就取出，没有值就产生运行时错误并使程序崩溃。它不会帮你补一个默认值。

解析

例如，用户可能没填昵称，那么昵称的类型可以是 String?。空字符串 "" 表示有一个内容为空的字符串，nil 表示没有字符串，这两者不同。

let nickname: String? = nil
print(nickname ?? "游客") // 游客
print(nickname?.count as Any) // nil，不会访问不存在的字符串

let enteredName: String? = "小明"
if let name = enteredName {
    print(name) // 小明；这里 name 的类型是 String
}

func greet(_ name: String?) {
    guard let name else {
        print("没有填写名字")
        return // guard 失败时必须离开它所在的作用域
    }
    print("你好，\(name)") // 之后的 name 已经是 String
}
greet(nil)

// let missing = nickname! // 取消注释会崩溃：nickname 是 nil

if let 适合“有值就做一件事”；guard let 适合“没有值就提前返回，后续代码都需要这个值”。作用域指变量有效的代码范围，例如一个函数体。

只有在程序已经可靠保证有值、缺值意味着代码本身有错误时，才考虑 !。对网络响应、用户输入等无法保证的内容，应判断或处理缺值。与其先检查再反复写 !，通常直接绑定成非可选值更清楚。

Optional 是语言中的“有或没有”模型，不必把 nil 理解为空指针。它实际如何占用内存属于底层实现，不影响上面的使用规则。

4. is、as、as?、as! 分别做什么？

口述版

  • is 用于检查值是否符合指定类型或协议，返回 Bool，不改变原值的声明类型。
  • as 用于编译期可确定成立的类型转换，不执行可能失败的条件转换。
  • as? 尝试转换类型，成功返回目标类型的可选值，失败返回 nil，不会因为转换失败而抛错或崩溃。
  • as! 强制转换类型，转换失败会触发运行时错误并终止程序。只有能够可靠保证转换成功时才考虑使用；失败属于正常情况时应使用 as?。

解析

例如一个 Animal 变量可能保存 Dog，也可能保存其他动物。is Dog 只回答它是不是 Dog；as? Dog 尝试得到 Dog 类型的值，不是就返回 nil；as! Dog 则在转换失败时使程序崩溃。把 Dog 当成父类 Animal 使用是一定可行的，可以用 as Animal。

class Animal {}
class Dog: Animal {
    func bark() { print("汪汪") }
}
let pet: Animal = Dog()
print(pet is Dog) // true；is 只检查，不会把 pet 变量改成 Dog 类型
if let dog = pet as? Dog {
    dog.bark() // 汪汪；成功后这里的 dog 是 Dog 类型
    let animal = dog as Animal // 把 Dog 当成父类 Animal 使用
    print(animal is Dog) // true，实际对象仍然是 Dog
}
let other: Animal = Animal()
print(other as? Dog as Any) // nil，转换失败但不崩溃
// let wrong = other as! Dog // 取消注释会崩溃：实际对象不是 Dog

is 不做转换。as 只接受编译期能证明的转换，包括子类转父类，以及语言规定一定成功的桥接，例如 String 到 NSString。向下转、转协议，失败是正常输入时用 as?，结果是可选值，不会抛 Error，也不会崩。

如果检查完就要使用 Dog 的方法，通常直接用 if let dog = pet as? Dog，不用先写 is 再强制转换。所谓“已经保证成功”，指代码中有可靠的类型保证，而不是“我猜框架这次会返回 Dog”。拿不准就用 as? 并处理 nil。

5. throws、try?、try!、Result 怎么选？defer 什么时候执行？typed throws 适合用在哪？

口述版

  • 函数声明 throws，表示执行时可能抛出错误。调用方可以用 do-catch 处理，也可以在自己的 throws 函数中用 try 继续把错误交给上层。
  • 普通 try 不负责处理错误；try? 把抛出的错误变为 nil；try! 在发生错误时使程序崩溃，不能用它忽略正常的失败。
  • Result 用 .success(value) 或 .failure(error) 把成功或失败保存为一个值，适合保存结果或传给回调。
  • defer 在离开当前作用域时执行；同一作用域有多个 defer，后执行到的先运行。程序因致命错误直接终止时，不能依赖 defer 收尾。
  • Swift 6 的 throws(MyError) 可以指定错误类型。是否用于公开接口取决于 API 设计，没有“公开接口一律不能用”的规则。

解析

throw 是“抛出一个错误”，throws 是“声明这个函数可能抛错”。错误可以逐层交给调用者，并不要求每一层都写 do-catch。

enum InputError: Error {
    case notANumber
}
func parse(_ text: String) throws -> Int {
    guard let number = Int(text) else {
        throw InputError.notANumber
    }
    return number
}
func loadNumber() throws -> Int {
    try parse("x") // 不在这里处理，继续向上抛
}
do {
    let number = try loadNumber()
    print(number)
} catch {
    print("读取失败：", error)
}
let number = try? parse("x") // Int?，这里得到 nil
let result: Result<Int, InputError> = .failure(.notANumber)
switch result {
case .success(let value): print(value)
case .failure(let error): print(error)
}

func demonstrateDefer() {
    defer { print("最后执行") }
    defer { print("倒数第二执行") }
    print("先执行")
}
demonstrateDefer()

defer 只有在执行到声明处后才会生效。之后正常走到作用域末尾，或因 return、throw 等离开该作用域，都会执行它；break、continue 只有在离开它所属的作用域时才触发相应清理。

try! 的失败、强制解包 nil、fatalError 等会终止程序。这种崩溃不是普通 Swift 错误，不能靠 do-catch 捕获，也不能指望 defer 一定执行。

普通 throws 可以抛出任何符合 Error 的错误。throws(InputError) 则限制为这一种错误类型，让调用方了解具体失败方式。对外公开具体类型意味着要考虑以后更换错误类型、增加错误情况对现有调用方的影响；这是设计取舍，不是禁止使用。

6. 指定初始化器、便利初始化器、required、可失败 init 各做什么？两阶段初始化是什么？

口述版

  • 指定初始化器和便利初始化器主要是类的初始化器分类。指定初始化器负责初始化本类的存储属性；有父类时，再调用父类的指定初始化器。
  • 便利初始化器用 convenience 标记。它先写 self.init(...)，让同一个类的另一个初始化器完成创建工作；这次调用返回后，再继续修改 var 属性。这种调用另一个初始化器的做法叫“委托”。
  • required 要求子类提供该初始化器。子类可以按规则自动继承，也可以自己实现。
  • init? 表示初始化可能失败；失败时 return nil，调用者得到可选值。它和 throws 是不同的失败表达方式，也可以组合使用。
  • 类的两阶段初始化先保证整条继承链的存储属性都有初值，再允许把完整的 self 用来调用实例方法等操作。给自身属性赋初值时可以写 self.property。

解析

初始化器就是创建实例时执行的入口，例如 Car(name: "小车")。self 代表当前正在创建的实例；self.name = name 是给它的属性赋值，不等于已经可以把整个实例传给其他代码。

class Vehicle {
    var name: String
    init(name: String) {
        self.name = name
    }
    required init() {
        self.name = "车辆"
    }
    convenience init(label: String) {
        self.init(name: label) // 先委托给本类指定初始化器
        self.name += "（默认配置）" // 完成后可以修改 var 属性
    }
}
class Car: Vehicle {
    var wheels: Int
    init(name: String, wheels: Int) {
        self.wheels = wheels // 先初始化子类自己的属性
        super.init(name: name) // 再让父类初始化自己的属性
        print(self.name)     // 现在可以读取实例属性、调用方法
    }
    required init() {
        self.wheels = 4
        super.init()
    }
}
print(Vehicle(label: "小车").name)
let car = Car()
print(car.wheels) // 4

struct Age {
    let value: Int
    init?(_ value: Int) {
        guard value >= 0 else { return nil }
        self.value = value
    }
}
print(Age(-1) as Any) // nil

两阶段不是“完全不能写 self”与“可以写 self”的分界。第一阶段允许给本类的存储属性设置初值，但在整条继承链初始化完成前，不能调用实例方法、读取实例属性或把 self 作为完整实例使用。第二阶段再进行进一步定制。

例如上面的 Vehicle(label:) 先调用 self.init(name:)，让它设置 name；返回后再给 name 加上“默认配置”。它也可以先调用另一个便利初始化器，但沿着 self.init 的调用链，最终必须调用到本类的指定初始化器，不能绕开实际设置初值的步骤。

结构体也有初始化器，能使用 init?，也能通过 self.init 复用另一个初始化器；它没有类继承，不使用 convenience 和 required 这套类继承规则。

二、属性、访问控制与泛型

7. 存储属性、计算属性、lazy、属性观察器有什么区别？扩展为什么不能加存储属性？

口述版

  • 实例存储属性保存每个实例自己的数据，类和结构体可以有；枚举不能声明实例存储属性，但可以有 static 存储属性。枚举的关联值是另一种携带数据的机制。
  • 计算属性通过 getter 计算或返回结果，可以用 setter 处理写入；它自身不保存独立的属性值，只能用 var 声明。
  • lazy 是延迟初始化的存储属性，第一次访问才求初值，必须用 var。并发首次访问时，lazy 本身不保证只初始化一次。
  • willSet 在赋值前得到 newValue，didSet 在赋值后得到 oldValue。本类型初始化器中直接初始化自己的属性不触发观察器。
  • 扩展不能添加实例存储属性，但能添加计算属性、方法等，也可以添加 static 存储属性。

解析

实例成员属于某一个对象或值；static 成员属于整个类型。例如每辆车各有一个 speed，而 Car.count 可以记录所有车辆共享的计数。计算属性可以读取其他存储属性，但不因此多保存一份结果。

struct Meter {
    var value = 1 {
        willSet { print("即将写入", newValue) }
        didSet { print("旧值是", oldValue) }
    }
    var doubled: Int { value * 2 }
    lazy var history: [Int] = [0, 1, 2]
}
extension Meter {
    var description: String { "数值：\(value)" }
    static let unit = "米" // 类型存储属性，可以放在扩展中
    // var note = "备注"   // 错误：扩展不能增加实例存储属性
}
enum Status {
    case ready, loading
    static let title = "状态" // 枚举也能有类型存储属性
}
var meter = Meter()
meter.value = 3 // willSet 得到 3，didSet 得到 1
print(meter.doubled) // 6
print(meter.history) // 此时首次初始化 history
print(Meter.unit)    // 米

实例存储属性会影响每个实例需要容纳哪些数据。Swift 不允许扩展随意增加这一部分；static 存储属性属于类型，不是在每个实例中追加字段。理解这条语言限制即可，不必先掌握实例大小和字段偏移等内存细节。

初始化阶段与后续修改要区分。子类初始化器调用 super.init 后，再修改继承来的属性，会触发该属性的观察器；通过普通方法等间接赋值也不能简单套用“初始化器里永远不触发”。

如果多个任务可能同时首次读取同一个 lazy 属性，应在外部协调访问，例如使用 actor 或锁；不能仅靠 lazy 获得并发安全。

8. static 和 class 修饰类型成员有什么区别？

口述版

  • static 和 class 都用于声明通过类型访问的成员；实例成员则通过实例访问。
  • static 可用于类、结构体、枚举和 actor 的类型属性或方法。类中的 static 成员可以继承，但不能被子类重写。
  • class 用于类的类型方法和计算类型属性，允许子类重写，不能用于存储类型属性。
  • 协议使用 static 声明类型成员要求，具体实现由遵循类型提供，协议声明本身不提供属性存储。
  • 类型需要存储数据时使用 static 存储属性；类的类型成员需要支持子类重写时使用 class。禁止整个类继承则使用 final。

解析

重写（override）是子类替换父类提供的实现；继承是子类获得父类的成员。static 禁止的是重写，并不是说子类完全看不到它。

protocol Titled {
    static var title: String { get } // 属性要求，没有为它分配存储
}
class Vehicle {
    static let wheels = 4
    static func category() -> String { "车辆" }
    class func description() -> String { "普通车辆" }
    class var title: String { "车辆" }
}
class Car: Vehicle {
    override class func description() -> String { "小汽车" }
    override class var title: String { "汽车" }
    // 不能 override static func category()
}
struct Book: Titled {
    static let title = "Swift 入门" // 用存储属性满足协议要求
}
print(Car.wheels)         // 4，继承而来
print(Car.description())  // 小汽车
print(Book.title)         // Swift 入门

类型只需要保存一份值时，用 static 存储属性；类的类型属性需要让子类改变计算结果时，用 class var。结构体、枚举没有类继承，所以使用 static，而不使用 class。

9. 访问控制从宽到窄是什么？private 和 fileprivate 差在哪？

口述版

  • 访问控制规定声明可被哪些代码访问。常见级别从宽到窄是 open、public、package、internal、fileprivate、private；普通顶层声明和类型成员未指定时通常为 internal，成员的有效访问范围还受所属类型限制。
  • 模块是可被 import 的编译单元，可以包含多个源文件；package 可以包含多个模块，两者不能仅按文件夹判断。
  • public 允许其他模块访问；对于类及可重写的类成员，open 进一步允许其他模块继承或重写。public 类在本模块内仍可继承，除非标记为 final。
  • package 允许同一 Swift package 内访问，internal 允许同一模块内访问，fileprivate 允许同一源文件内访问。
  • 类型的 private 成员可在类型内部及同一源文件中该类型的扩展内访问，不对同文件的无关类型开放。
  • private(set) 单独缩小 setter 的访问范围，不会自动扩大属性的读取权限。

解析

例如 Account 类型没有对外公开，即使它的某个属性标了 public，其他模块也不能因此直接访问这个 Account 的属性。需要对外使用时，类型本身及相应成员都要具有合适的访问权限。

先区分三个范围：文件是一个 .swift 源文件；模块是能作为一个单元被 import 的库或应用代码；package 是 Swift 包，可以包含多个模块。它们不是同一个概念，也不能只看磁盘文件夹判断。

// 以下代码放在同一个 Account.swift 文件里
struct Account {
    private var pin = "1234"
    fileprivate var identifier = "A01"
    private(set) var balance = 0 // 当前默认 internal 可读，private 可写
    mutating func deposit(_ amount: Int) {
        balance += amount
    }
}
extension Account { // 虽然是另一对花括号，仍是同类型、同文件
    func readPin() -> String { pin } // 可以访问 private
}
struct Audit {
    func read(_ account: Account) -> String {
        account.identifier // 可以访问同文件的 fileprivate
        // account.pin     // 不可以：Audit 不是 Account
    }
}
func inspect(_ account: Account) {
    print(account.identifier) // 同文件顶层函数也可以访问 fileprivate
    print(account.balance)    // 可以读
    // account.balance = 1    // 不可以在这里写
}
var account = Account()
account.deposit(10)
inspect(account)

如果把 extension Account 移到另一个文件，它就不能访问 pin。若仍在同一个模块，则可以访问 internal 成员。若希望其他模块能读余额，还要给类型和相应属性标上 public；单独写 private(set) 不会自动让外部模块可读。

因此不能用“只有这一对花括号里可见”概括 private，也不能用“任何地方都不能继承”概括 public。open 只适用于允许开放继承或重写的类及相应成员，不适用于结构体和枚举。

10. 泛型解决什么问题？它和 Any 有什么差别？

口述版

  • 泛型通过类型参数复用函数或类型定义，在支持多种具体类型的同时，保留参数、返回值及成员之间的类型关系。
  • 泛型约束规定类型参数必须具备的能力或继承关系，由编译器检查；需要额外限制时可使用 where。
  • Any 可以保存任意类型的值，但不保留可直接使用的具体静态类型信息，使用具体类型的能力前通常需要类型检查或转换。AnyObject 只表示类实例。
  • 泛型适合需要类型安全和明确类型关系的通用实现；Any 适合需要统一容纳不同类型、且可以接受额外类型判断的场景。

解析

例如 let number = identity(3)，编译器知道 number 是 Int，所以可以直接写 number + 1。若函数只声明返回 Any，就不能直接使用 Int 的加法，需要先确认并转换类型。编译器根据声明和类型推断能知道的类型，称为“静态类型”。

func identity<T>(_ value: T) -> T {
    value
}
let number = identity(3)    // 编译器知道 number 是 Int
let text = identity("hi")   // 编译器知道 text 是 String
print(number + 1)          // 4
print(text.uppercased())   // HI

func erase(_ value: Any) -> Any { value }
let unknown = erase("hi")  // 声明类型是 Any
// unknown.uppercased()    // 不可直接使用 String 专有方法
if let string = unknown as? String {
    print(string.uppercased())
}

func areEqual<T: Equatable>(_ left: T, _ right: T) -> Bool {
    left == right // Equatable 协议保证 T 支持相等比较
}
print(areEqual(1, 1)) // true
// areEqual(1, "1")   // 错误：这次调用的两个参数需要是同一种 T

把具体类型放进 Any，常称为擦除具体的静态类型信息；并不是对象真的忘掉了自己的运行时类型。AnyObject 限制为类实例，不能和“泛型参数必须是类”的约束 T: AnyObject 混为一谈。

协议中的 associatedtype 称为关联类型，表示“由遵循协议的类型决定一个相关类型”，例如集合决定自己的元素类型。泛型函数的 T 则由调用时的类型关系确定。where 用来继续补充这些类型必须满足的条件。

三、内存与闭包

11. ARC 是什么？strong、weak、unowned 怎么选？

口述版

  • ARC 是自动引用计数，负责管理类实例等引用对象的生命周期。强引用会保持对象存活；没有强引用保留对象后，对象可以被销毁。它不是定期扫描所有对象的垃圾回收。
  • strong 是通常的默认引用方式。weak 和 unowned 都不增加强引用计数，不能让对象保持存活。
  • weak 必须是可选的 var。对象释放后，它自动变成 nil；这次自动清空不触发属性观察器。
  • unowned 可以是非可选引用，也可以是可选引用；对象释放后不会自动变成 nil。通过普通 unowned 访问已释放对象，会出现运行时错误并使程序崩溃，不能用 do-catch 捕获。
  • 对方可能先释放、希望届时读到 nil，用 weak；能保证每次访问时对方仍存活，才考虑 unowned。不确定时通常选择 weak。

解析

强引用计数可以理解为“目前还有多少所有者要求这个对象活着”。实际计数操作由编译器和运行时管理，也可能被优化；不需要把每一次源码赋值都理解成必然执行一次机械的加一。

class Person {
    let name: String
    init(_ name: String) { self.name = name }
    deinit { print("Person 已释放") }
}
func demonstrateReferences() {
    var person: Person? = Person("小明") // 强引用保留对象
    weak var observer: Person? = person
    unowned let reference: Person = person!
    unowned var optionalReference: Person? = person // unowned 也可以是可选

    print(reference.name) // 小明，此时对象还活着
    print(optionalReference?.name as Any)
    optionalReference = nil // unowned 可选引用需要自己维护是否有效
    person = nil // 此例没有其他强引用，对象被释放
    print(observer as Any) // nil，weak 自动清空
    observer = nil // weak 变量也允许主动清空
    // print(reference.name) // 取消注释会崩溃：访问已经释放的对象
}
demonstrateReferences()

程序不会仅因为对象释放后还有 unowned 引用就立刻崩溃，错误发生在之后通过失效引用访问对象时。“触发陷阱（trap）”就是运行时检测到非法操作并终止执行。即使 unowned 的类型带 ?，它也不会自动置 nil，?. 不能保护已经失效的引用。

这里讨论默认的安全 unowned。unowned(unsafe) 会省去相应安全检查，访问失效对象产生未定义行为，不能保证以明确错误退出，入门代码不应使用它。

循环引用是对象互相强持有、导致计数无法归零。例如对象保存闭包，闭包又强捕获对象；需要根据所有权关系改用弱引用或主动断开连接。普通结构体和枚举本身不按类实例进行 ARC 管理，但它们内部的类引用仍参与 ARC。

不要依赖局部变量的花括号结束时刻来精确预测销毁时间。Objective-C 互操作中的自动释放池还可能延后某些对象的释放；deinit 是销毁时的回调，不是业务流程的固定计时点。

12. 这段代码为什么循环引用？weak 和 unowned 怎么选？

口述版

  • 对象的属性保留闭包，闭包里的 self 又保留同一个对象。如果一直不清空闭包或断开其中的强引用，对象就无法释放。
  • 捕获列表写在参数列表前面：{ [weak self] in }。不写捕获列表，捕获的就是强引用。
  • 对象可能先释放，用 weak。对象释放后 self 变成 nil，里面用 self? 或 guard let self。
  • 只有能保证闭包每次使用对象时，对象都还活着，才考虑 unowned。写 self.doWork() 只是明确表示调用当前对象的方法，不会自动变成弱引用；要弱引用，需要写 [weak self]。

解析

下面的 Owner.work 属性保存闭包，闭包内的 self.doWork() 又让闭包保留这个 Owner。假如一直不清空 work，也没有其他方式断开这两个强引用，它们就会互相保留，Owner 无法释放。闭包使用外部的 self，叫作“捕获 self”；这里默认是强引用。[weak self] 才会将这次捕获改为弱引用。

class Owner {
    var work: (() -> Void)?
    func start() {
        work = { self.doWork() }          // 属性强引用闭包，闭包强引用 self
    }
    func startSafely() {
        work = { [weak self] in self?.doWork() }
    }
    func doWork() {}
}

闭包存在属性、回调、定时器里，页面或对象可能先消失，用 [weak self]，里面用 self? 或 guard let self。闭包只被这个对象持有，而且不会被拷给更长寿的一方，对象释放前不可能再调用，才可以 [unowned self]。闭包一旦逃到对象外面，这个前提通常就不成立。

13. 闭包是引用类型吗？@escaping 改变了什么？为什么逃逸闭包不能捕获 inout？

口述版

  • 闭包是可以保存和传递的代码块，也是引用类型。赋给另一个变量后，两个变量引用同一个闭包；不要把“复制代码体”当作区分值类型与引用类型的标准。
  • 捕获是闭包在内部使用外面的变量。捕获外部可变局部变量时，通常能看到它后续的变化；[n] 捕获的是创建闭包时 n 的值。
  • 直接写成函数类型的参数默认非逃逸：函数返回后不能再通过该参数使用闭包。@escaping 允许保存闭包并在函数返回后调用，不保证一定晚调用。可选闭包参数不受这个默认非逃逸限制，也不再标 @escaping。
  • inout 让函数在这次调用期间修改调用者传入的变量。函数返回后，闭包可能还会执行，但不能再通过已经结束的 inout 参数继续修改原变量，所以编译器禁止逃逸闭包直接捕获该参数。
  • @escaping 不决定引用强弱，也不自动创建异步任务。类实例通常按强引用捕获；需要弱捕获时使用 [weak self]。

解析

下面先看捕获变量与保存值的区别。这一段适用于局部 Int 变量；如果捕获的值本身是类引用，[object] 保存的仍是对象引用，并不会深复制对象。

func demonstrateCapture() {
    var n = 1
    let later = { n }
    let snapshot = { [n] in n }
    n = 2
    print(later())    // 2，读取同一个外部变量
    print(snapshot()) // 1，保存了创建闭包时的值
}
demonstrateCapture()

func run(_ body: () -> Void) { body() }
func makeAction(_ body: @escaping () -> Void) -> () -> Void {
    body // 允许把闭包返回，由外部以后调用
}
let action = makeAction { print("以后也能执行") }
action()

func increase(_ value: inout Int) {
    run { value += 1 } // 真正捕获了外层的 inout 参数，非逃逸，合法
}
var count = 1
increase(&count)
print(count) // 2

// 以下写法不合法：函数返回后，闭包还想通过 value 修改原变量
// func invalid(_ value: inout Int) -> () -> Void {
//     return { value += 1 } // 编译错误：逃逸闭包捕获 inout 参数
// }

func makeSnapshot(_ value: inout Int) -> () -> Int {
    { [value] in value } // 合法：只保存当前 Int 的副本，不再访问原变量
}
let readSnapshot = makeSnapshot(&count)
count = 9
print(readSnapshot()) // 2

“独占访问”表示修改这一个变量期间不允许发生冲突的重叠访问。inout 的修改权限仅在函数调用期间有效，函数结束后不能靠逃逸闭包继续修改原变量。如果只是需要当前值，可以像上面一样显式捕获副本；这与继续持有 inout 参数不同。

14. map、flatMap、compactMap 有什么区别？

口述版

  • 对数组等序列，map 对每个元素做转换并保留每次结果，结果个数与输入相同。转换可以返回可选值，结果数组中也就可以有 nil。
  • compactMap 也逐个转换，但去掉转换结果中的 nil，并取出非 nil 结果里的值。
  • 序列的 flatMap 把每个元素转换成一个序列，再按顺序把这些序列的元素合并到一层。
  • Optional 也有 map 和 flatMap：有值时转换，没有值时不执行转换。flatMap 接收返回可选值的转换，避免额外套一层 Optional。

解析

“序列”可以先理解为能逐个遍历元素的集合，例如数组；“拍平一层”就是把一组小数组的元素依次放进一个数组。相同方法名用在 Array 和 Optional 上时，具体签名与用途要分别看。

let input = ["1", "x", "3"]
let mapped = input.map { Int($0) }
print(mapped)    // [Optional(1), nil, Optional(3)]，类型 [Int?]
let compacted = input.compactMap { Int($0) }
print(compacted) // [1, 3]，类型 [Int]

let groups = [[1, 2], [3]]
let flattened = groups.flatMap { $0 }
print(flattened) // [1, 2, 3]

let text: String? = "x"
let nested: Int?? = text.map { Int($0) }
let single: Int? = text.flatMap { Int($0) }
switch nested {
case .some(.none): print("外层有值，但转换结果是 nil")
default: break
}
print(single as Any) // nil，没有额外的外层 Optional
let missing: String? = nil
let result = missing.map { $0.count } // 闭包不执行，结果 nil
print(result as Any)

上面的 $0 表示闭包收到的第一个参数；Int("x") 转换失败会返回 nil。map 保留这个 nil，compactMap 丢弃它，这正是两者最直观的区别。

旧版 Swift 曾用序列的 flatMap 处理过滤 nil，Swift 4.1 后用 compactMap 表达这件事。但 Optional.flatMap 仍然处理可选转换，不能把所有同名方法都说成只拼接数组。

15. @autoclosure 是做什么的？和普通闭包参数有什么区别？

口述版

  • @autoclosure 将实参表达式自动包装为无参数闭包，调用者无需显式编写闭包。
  • 表达式的求值推迟到闭包被调用时；未调用则不求值，是否调用以及调用次数由被调用函数的实现决定。
  • 普通闭包参数要求调用者显式提供闭包，@autoclosure 则允许直接传入表达式，适合需要按条件求值的接口。
  • 自动闭包默认非逃逸；需要保存并允许在函数返回后调用时，应同时标记 @escaping。它不改变捕获规则，也不自动创建异步任务。
  • 使用时应控制范围，避免隐藏求值时机或副作用，影响调用代码的可读性。

解析

“延迟求值”就是推迟计算表达式的结果。用打印日志观察先后顺序，比只说“看起来传值，实际传闭包”更容易理解：

func loadData() -> String {
    print("开始读取数据")
    return "读取结果"
}
func show(_ enabled: Bool, _ value: @autoclosure () -> String) {
    print("进入 show")
    if enabled {
        print(value()) // 只有这里调用闭包时，才执行 loadData()
    }
}
show(false, loadData())
// 只输出“进入 show”，不会执行 loadData()
show(true, loadData())
// 依次输出：进入 show、开始读取数据、读取结果

func showWithClosure(_ enabled: Bool, _ value: () -> String) {
    if enabled { print(value()) }
}
showWithClosure(true, { loadData() }) // 普通闭包版本要明确传入闭包

let nickname: String? = "小明"
let displayName = nickname ?? loadData()
print(displayName) // 小明；左侧有值，所以右侧 loadData() 不执行

?? 的右侧以及 && 的右侧，都利用类似的自动闭包实现按需计算。它们是否调用闭包由各自的实现决定；@autoclosure 只负责把表达式包起来，不会自动决定走哪个分支，也不保证闭包最多只调用一次。

这种写法简洁，但调用者仅看 loadData() 可能误以为它会立刻执行，因此自定义 API 不宜滥用。闭包捕获外部变量的规则仍然适用。

四、协议

16. 为什么说 Swift 是面向协议编程的？

口述版

  • 面向协议编程通过协议定义能力与约束，使用泛型和协议类型组织接口，减少对具体实现及共同父类的依赖。
  • 类、结构体和枚举等类型都可以遵循协议；协议扩展可以提供默认实现，使无继承关系的类型复用行为。
  • 需要通过协议接口调用时支持各类型提供不同实现的方法，应声明为协议要求；默认实现可以放在协议扩展中。
  • 面向协议与面向对象可以结合使用。需要共享对象身份或使用类继承时，仍应根据实际需求选择类。

解析

例如下面的 Named 要求类型提供 name 和 greeting()。User 和 Book 分别代表用户与书，没有父子类关系；它们都提供自己的 name，就可以直接使用扩展中现成的 greeting()。把这段生成文字的代码写一次，让多个类型使用，就是这里所说的复用。

protocol Named {
    var name: String { get }
    func greeting() -> String
}
extension Named {
    func greeting() -> String { "介绍：\(name)" }
}
struct User: Named { var name: String }
struct Book: Named { var name: String }
print(User(name: "小明").greeting())    // 介绍：小明
print(Book(name: "Swift 入门").greeting()) // 介绍：Swift 入门

协议声明列出必须提供什么，扩展可以给这些要求提供现成实现，也叫默认实现。如果某个类型需要不同的介绍，可以自己实现 greeting()。希望通过 Named 协议调用时仍选择各类型自己的 greeting()，就应像本例一样把它写进协议要求；只写在扩展里的同名方法有不同调用规则，见第 27 题。

17. Codable 是什么？Encodable/Decodable 怎么自动合成？自定义 key 怎么处理？

口述版

  • Codable 是 Encodable 与 Decodable 的组合，分别约定编码和解码能力，可配合相应编码器与解码器完成数据转换。
  • 编译器可在满足自动合成条件时生成 encode(to:) 和 init(from:)；参与处理的属性需要满足相应协议，具体条件还取决于类型形式与 CodingKeys 声明。
  • CodingKeys 用于指定参与编解码的属性，并建立属性名与外部字段名的映射。
  • 自动合成的解码通常将缺失或为 null 的可选字段解为 nil；类型不匹配仍会抛错，非可选字段缺失通常也会抛错，不会仅因属性有默认值就自动使用该值。
  • 子类继承父类的 Codable 实现时，新增属性不会自动参与编解码，需要手动补充子类字段的处理，并按数据格式约定处理父类部分。

解析

编码可以先理解为“把 Swift 值变为可传输或保存的数据”，解码是反方向。JSON 只是常见格式之一，Codable 本身不限定为 JSON。

import Foundation

struct User: Codable {
    let id: Int
    let displayName: String
    let nickname: String?
    enum CodingKeys: String, CodingKey {
        case id
        case displayName = "display_name"
        case nickname
    }
}
let data = Data(#"{"id":1,"display_name":"小明"}"#.utf8)
let user = try JSONDecoder().decode(User.self, from: data)
print(user.displayName)    // 小明
print(user.nickname as Any) // nil，JSON 中没有 nickname
let encoded = try JSONEncoder().encode(user)
print(String(decoding: encoded, as: UTF8.self))

class Base: Codable {
    var name = "父类字段"
}
class Child: Base {
    var score = 100
}
let childData = try JSONEncoder().encode(Child())
print(String(decoding: childData, as: UTF8.self))
// 只包含 name，不包含 score：继承到的是父类的编码实现

nickname 缺失可以得到 nil，不代表所有错误都被忽略。如果 nickname 被传成数组而声明是 String?，仍会解码失败。手写 init(from:) 时，则由你选择 decode、decodeIfPresent 或其他策略；上面的缺值行为不是所有手写代码都自动具备的。

只需要 Encodable 时，属性只需满足编码所需条件；只需要 Decodable 时同理。通过 CodingKeys 排除属性还要满足初始化要求，例如被排除的存储属性具有可用默认值。枚举的自动合成规则与其 case、关联值有关，不能一概套成“所有存储属性可编码就够了”。

要处理子类新增字段，应实现子类的 required init(from:) 和 override encode(to:)，并按约定调用父类实现。通过 superDecoder、superEncoder 将父类数据放在独立位置，或与父类约定同层字段，都需要双方格式一致。

如果只需更改日期表示，优先检查 JSONEncoder.dateEncodingStrategy 和 JSONDecoder.dateDecodingStrategy。字段类型转换、动态字段名或复杂容错，再考虑手写编解码。

18. Swift 协议和 OC 协议有什么区别？

口述版

  • 协议要求描述遵循类型必须提供的属性、方法等能力。Swift 原生协议可由类、结构体、枚举等遵循，也可以声明关联类型。
  • 默认实现是协议扩展提供的现成实现：遵循类型没有自己实现某个要求时，可以使用适用的默认实现。协议不会凭空自动得到默认实现。
  • Swift 原生协议不能用 Objective-C 的 optional 关键字把要求设为可选。没有实现、也没有适用默认实现的要求，会导致遵循检查失败。
  • @objc 协议用于 Objective-C 互操作，只能由类遵循，成员必须能表示为 Objective-C 接口；可用 @objc optional 声明允许不实现的要求，不能声明关联类型。

解析

“遵循协议”就是承诺提供协议规定的能力；“可选要求”则允许遵循者完全不提供该方法。默认实现与可选要求不同：前者仍有一个可调用的实现，后者可能根本没有实现。

protocol Drawable {
    func draw() // 协议要求
}
extension Drawable {
    func draw() { print("默认绘制") } // 为该要求提供默认实现
}
struct Dot: Drawable {} // 不必自己再写 draw
Dot().draw()            // 默认绘制

import Foundation
@objc protocol Clickable: AnyObject {
    @objc optional func click()
}
class Button: NSObject, Clickable {} // 允许没有 click
let button: any Clickable = Button()
button.click?() // 方法存在才调用；此例没有，所以什么也不做

button.click?() 的 ? 是检查可选方法是否存在，不是强制调用。只需要给 Swift 类型复用一份行为时，通常使用原生协议和扩展；需要对接 Objective-C 委托或可选回调时，再考虑 @objc 协议。

进阶机制：通过 Swift 协议调用要求时，运行时可以利用“见证表”找到该类型对应的实现，见证表可以理解为类型对协议要求提供实现的对应表。通过 Objective-C 协议发消息时，则按方法名对应的选择子查找实现。编译器也可能优化调用，不必先记住底层表结构才能使用协议。

19. some 和 any 差在哪？

口述版

  • 返回位置的 some P 表示返回某个遵循 P 的具体类型，但接口隐藏它的名字。普通非泛型函数的所有返回路径必须对应同一种底层类型。
  • 参数位置的 some P 是泛型参数的简写，由调用者在每次调用时决定具体类型，不要与返回位置混为一谈。
  • any P 表示能容纳某个 P 遵循者的协议值。一个可变的 any P 变量可以先保存一种遵循者，之后再换成另一种。
  • 返回一种固定的实现但希望隐藏细节时，考虑 some；需要用统一的协议类型保存不同实现时，考虑 any。两者不是单纯性能高低之分。

解析

假设 Pirate 和 Robot 都能打招呼。some Greeter 可以表示“函数始终制造同一种角色，只是不公开是哪一种”；any Greeter 则可以表示“这个位置可以换着放不同角色”。

protocol Greeter {
    func hello() -> String
}
struct Pirate: Greeter {
    func hello() -> String { "Ahoy" }
}
struct Robot: Greeter {
    func hello() -> String { "Beep" }
}
func makeGreeter() -> some Greeter {
    Pirate() // 底层固定是 Pirate
}
print(makeGreeter().hello()) // Ahoy

var current: any Greeter = Pirate()
print(current.hello()) // Ahoy
current = Robot()     // 合法：同一个变量换一种遵循者
print(current.hello()) // Beep
let crowd: [any Greeter] = [Pirate(), Robot()]
for person in crowd { print(person.hello()) }

func greet(_ value: some Greeter) { print(value.hello()) }
// 等价形式：func greet<T: Greeter>(_ value: T) { ... }
greet(Pirate())
greet(Robot()) // 两次调用可以选择不同类型

current 的静态类型，即编译器根据声明看到的类型，是 any Greeter；它运行时装着的实际值先是 Pirate，后来是 Robot。静态类型被统一为协议类型，不代表实际值失去了自己的类型。

some 常称“不透明类型”，强调接口隐藏底层具体类型；any 常称“存在类型”，表达存在某个符合协议的具体值。这些是上述行为的术语名称，不必把术语当成使用方法。

普通函数不能在一个分支返回 Pirate、另一个分支返回 Robot，却声明返回 some Greeter。泛型函数的底层返回类型可以随泛型参数改变；SwiftUI 的结果构建器还可能把不同分支组合成一个统一类型，属于另一层机制。

[any Greeter] 是保存不同遵循者的一种常见方案，也可以用枚举等方式统一不同实现，并不是唯一方案。某些涉及关联类型或 Self 的协议能力，通过 any 调用还有额外限制；some 与 any 并非可以随意互换。

五、方法调用

20. Swift 方法调用是如何实现的？

口述版

  • 方法派发是确定方法调用所执行的具体实现的过程。常见方式有静态派发、虚表派发、见证表派发和 Objective-C 消息派发。
  • 静态派发：编译期确定目标方法，直接调用对应实现。
  • 虚表派发：运行时根据对象的实际类型，通过类的虚表找到对应的方法实现，支持类的继承和方法重写。
  • 见证表派发：通过协议接口调用协议要求时，利用具体类型的协议见证表，找到该类型为协议要求提供的实现。
  • Objective-C 消息派发：运行时根据接收对象和选择子查找方法实现，必要时沿父类链继续查找。
  • 在 Objective-C 互操作场景中，@objc 用于暴露接口，@objc dynamic 要求使用 Objective-C 动态派发。仅添加 @objc 或继承 NSObject，不会让所有 Swift 调用都变成消息派发。
  • 编译器在能够确定目标实现时，可以将部分动态派发优化为直接调用，并进一步内联；应区分语言的派发规则与优化后的调用形式。

解析

例如 animal 的声明类型是 Animal，实际保存 Dog 对象。调用 sound 时需要遵守重写关系，因此应执行 Dog 的版本。虚表可以理解为按固定位置保存可重写方法实现的表。

class Animal {
    func sound() -> String { "Animal" }
}
class Dog: Animal {
    override func sound() -> String { "Woof" }
}
let animal: Animal = Dog()
print(animal.sound()) // Woof，根据实际类体现重写行为

protocol Speaker { func speak() -> String }
struct Robot: Speaker {
    func speak() -> String { "Beep" }
}
let speaker: any Speaker = Robot()
print(speaker.speak()) // Beep，根据协议遵循找到 Robot 的实现

import Foundation
class Demo: NSObject {
    func ordinary() {}                // 普通 Swift 方法
    @objc func exposed() {}           // 可被 Objective-C 调用
    @objc dynamic func replaceable() {} // Objective-C 动态派发
}

协议见证表记录“这个类型怎样满足这个协议的要求”，与类用于重写的虚表不同。结构体直接调用自身方法时通常可直接确定实现，但把结构体放入协议值、或通过泛型使用时，不能只凭它是结构体就断言所有调用一定相同。

Objective-C 的 objc_msgSend 会先利用缓存等信息查找；需要时还会查本类与父类的方法实现。因此“消息派发不再问父类”是不对的。运行时替换实现、KVO 等机制依赖相应的动态行为，但不是只要标记属性就自动具有所有功能。

final、static 等限制了重写，使实现更容易在编译期确定；private 主要限制访问，不应只凭它解释所有最终派发结果。编译器还可能把原本需要动态查找的调用优化成直接调用，再把短函数展开到调用处（内联）。先理解调用应该执行谁，再了解这些优化更稳妥。

本题的 dynamic 说明针对 @objc dynamic 互操作。Swift 还有其他动态替换机制，不能把所有语境中的 dynamic 都无条件等同于 objc_msgSend。

六、并发

21. Swift async/await 和 GCD 有什么区别？await 会不会堵住当前线程？

口述版

  • async 表示函数可以进行异步操作；await 标记一次可能挂起的调用，不保证这次一定挂起，也不等于创建新线程。
  • 挂起的是任务：它暂时停止继续执行，运行时可以把线程用于其他工作，而不是让线程阻塞在那里等结果。
  • GCD 把工作提交到队列；async 提交通常不等待工作完成，sync 则要等工作完成才返回。它与 Swift 的 async 函数不是同一个概念。
  • 异步函数里的同步耗时工作仍会占用执行它的线程。Thread.sleep、同步 I/O、信号量等阻塞操作不会因为外面写了 async 或 await 就变为非阻塞。

解析

任务是 Swift 管理的一段异步工作，线程是系统执行代码的资源。任务挂起后可以以后恢复；恢复时不应假设还是原来那条线程。主 actor 的工作在 Apple 平台主线程上执行，耗时同步工作会影响 UI 响应。

func fetchName() async -> String {
    // 示例省略真实网络请求；async 函数也可以直接返回
    "小明"
}
func refresh() async {
    let name = await fetchName() // 可能挂起，此示例不必实际等待
    print(name)                 // 同步执行的一小段代码
}
await refresh()

真实网络请求可能在等待响应时挂起任务，让运行时有机会执行其他工作；但不能把图示理解为“每写一个 await 就必定切换到另一个任务”。await 本身也不能保证被调用函数的实现没有阻塞操作。

两个实际挂起点之间的同步代码不会自动替任务增加新的挂起点，但系统仍可调度、抢占线程。这里的“任务主动挂起”与“操作系统暂时调度其他线程”不是同一层面的事情。

不要用信号量在异步函数中等待尚未完成的异步任务，这可能占住有限的工作线程，使被等待任务无法运行。旧回调 API 需要桥接时，可以使用 continuation 等机制；CPU 密集计算则要明确安排执行位置，见第 25 题。

22. actor 和类有什么差别？赋值之后谁和谁共享状态？

口述版

  • actor 与类一样是引用类型，赋值复制引用，多个变量可以共享同一个实例。
  • actor 通过隔离规则协调内部可变状态的访问。同一 actor 上访问隔离状态的代码不会并发执行，从而防止对该状态的数据竞争；普通类本身不自动提供这层保护。
  • 从其他隔离上下文访问 actor 的隔离成员通常需要 await，因为调用可能等待 actor 调度；同一 actor 内调用同步隔离方法则不需要 await。
  • actor 内部在 await 处实际挂起时，其他任务可能进入并改变状态。恢复后必须重新确认依赖的状态条件，不能把整个异步方法视为不可打断的操作。
  • actor 自动满足 Sendable，可以安全传递引用，但访问内部状态仍须遵守隔离规则。普通 actor 不保证专用线程，也不保证严格按提交顺序执行。

解析

“隔离”可以理解为把这份可变数据的读写入口交给 actor 管理。“数据竞争”是多个并发执行同时访问同一份内存、至少一方写入且缺乏适当同步的问题；类也可以自己加锁或使用全局 actor，并非所有类都天然不安全。

actor Counter {
    private var value = 0
    func increment() { value += 1 }
    func currentValue() -> Int { value }
    func incrementTwice() {
        increment() // 同一个 actor 内调用同步隔离方法，不需要 await
        increment()
    }
}
func example() async {
    let first = Counter()
    let second = first // 共享同一个 Counter
    await withTaskGroup(of: Void.self) { group in
        for _ in 0..<100 {
            group.addTask { await second.increment() }
        }
    }
    let count = await first.currentValue()
    print(count) // 100
    // first.value = 0 // 不能在外部直接修改隔离状态
}
await example()

increment 没有 async，但外部调用仍要写 await，因为调用方可能要等 actor 处理完其他工作。这种等待允许挂起当前任务，不是要求线程停住等待。

重入要特别留意“先检查、异步等待、再修改”。例如先检查余额足够，再 await 网络授权；授权期间可能有另一笔取款，恢复时必须重新检查余额，不能凭旧检查扣钱。没有挂起点的一段同步检查和修改，可以在同一个 actor 隔离中连续完成。

await 仅表示可能挂起，不是每次必定让出；actor 也不保证严格按调用提交顺序处理任务。不带 actor 隔离的成员属于另一种规则，不能把“整个对象上所有代码都串行”当成 actor 的含义。

23. async let、TaskGroup、Task、Task.detached 分别是谁的子任务？

口述版

  • async let 和任务组创建结构化子任务。父任务结束前必须等这些子任务结束，取消通常沿父子任务关系向下传播。
  • 未显式等待的 async let 在离开声明作用域时会被取消并等待结束。普通 withTaskGroup 正常退出时则等待剩余子任务，不会仅因退出就自动取消它们。
  • 任务组可通过 cancelAll() 请求取消；抛出错误离开 throwing 任务组的 body 时会取消并等待剩余子任务。取消是请求，任务需要配合响应，不能强行杀死同步代码。
  • Task { } 创建非结构化任务，不是当前任务的结构化子任务。它通常继承创建位置的 actor 隔离上下文、任务局部值与优先级；外层任务取消不会自动取消它。
  • Task.detached 也不是子任务，不继承创建位置的 actor 隔离或任务局部值，也不自动沿用当前任务优先级；可以显式指定优先级。

解析

例如 loadPair() 里创建两个 async let，loadPair() 返回前必须等它们结束。若在函数中写 let task = Task { ... }，这个函数返回后，任务仍可能继续运行。把返回的 task 保存下来，以后就能用 task.cancel() 请求取消，或用 await task.value 等待结果；这个 task 就是“任务句柄”。任务局部值则是沿任务传递的附加信息，例如记录一次请求的日志编号。

func fetch(_ id: String) async -> String { id }
func loadPair() async {
    async let left = fetch("A")
    async let right = fetch("B")
    let pair = await (left, right)
    print(pair)
}
func useGroup() async {
    await withTaskGroup(of: String.self) { group in
        group.addTask { await fetch("A") }
        group.addTask { await fetch("B") }
        // 即使不手动取结果，正常退出 body 时仍等待子任务结束
        // 如果不再需要结果，可主动 group.cancelAll()
    }
}
func startIndependentWork() async {
    let handle = Task { await fetch("C") }
    // 它不是结构化子任务；有需要时可 handle.cancel()
    let result = await handle.value
    print(result)
}
await loadPair()
await useGroup()
await startIndependentWork()

Task 的 actor 继承取决于创建位置的隔离上下文，不是“碰巧当前正在主线程上执行”。例如在 @MainActor 方法内直接写 Task { }，任务闭包通常继承主 actor；若绕到一个不隔离的同步辅助函数里创建，就不能仅凭调用者在主 actor 上作判断。

Task.detached 不表示“一定创建新线程”；在任何任务中调用隔离到其他 actor 的方法，仍需要遵守那个方法的隔离。固定数量、必须一起结束的工作适合 async let，动态数量的子工作适合任务组；明确需要由外部管理生命周期的工作再用 Task。

取消后，任务可能在 try Task.checkCancellation() 或支持取消的异步操作中抛出 CancellationError，也可以自行检查 Task.isCancelled。调用 cancel() 并不意味着任务已经停止；有结构化关系的父任务仍要等它真正结束。

24. Sendable 保证什么？@unchecked Sendable 在承诺什么？

口述版

  • Sendable 表示类型的值适合在并发隔离域之间安全传递或共享，由编译器结合并发规则检查；它不会自动加锁，也不允许无同步地并发修改同一个外部变量。
  • 隔离域是受同一组并发访问规则保护的代码与状态范围。Sendable 不改变值类型与引用类型的语义，也不保证业务操作顺序或流程完全正确。
  • 结构体和枚举在相关存储成员或关联值均满足 Sendable 等条件时，可以由编译器检查其遵循；部分类型可以自动推断遵循。
  • 普通类要获得编译器检查的 Sendable 遵循，一般需为 final、所有存储属性不可变且满足 Sendable，并且无父类或只继承 NSObject。具有全局 actor 隔离的类等另有规则。
  • @unchecked Sendable 表示开发者自行承担并发安全保证，跳过相应的编译器检查；必须通过正确的同步或其他安全设计履行该承诺。

解析

final 表示类不能再被继承；这可以避免子类额外添加未经检查的可变状态。不可变属性用 let 声明，但仅有 let 不够：它引用的对象本身也必须满足安全要求。

import Foundation

struct Point: Sendable {
    var x: Int
    var y: Int
}
final class Token: NSObject, Sendable {
    let value: String
    init(_ value: String) { self.value = value }
} // NSObject 是允许的父类例外，不需要因此强制使用 @unchecked

final class LockedCounter: @unchecked Sendable {
    private let lock = NSLock()
    private var value = 0
    func next() -> Int {
        lock.lock()
        defer { lock.unlock() }
        value += 1
        return value
    }
} // 开发者承诺所有对 value 的读写都遵守同一把锁
let counter = LockedCounter()
print(counter.next()) // 1

Point 可以修改自己的 x、y，不代表可以让多个任务无同步地同时修改同一个外部 Point 变量。Sendable 允许安全传递值，不会取消对共享变量访问的限制。actor 本身也满足 Sendable，因为共享它的引用后，访问隔离状态仍然受到保护。

NSLock 是互斥锁，同一时间只让一方进入受保护的同步代码。在 LockedCounter 中，如果以后新增一个不加锁就读 value 的方法，@unchecked 不会替你发现或修复它。

也不要把“不是 Sendable”理解成任何情况下都绝不能跨边界使用。现代 Swift 还可通过 sending、区域隔离分析等机制证明某些转移不产生共享；这些属于更进一步的规则。此题先掌握可安全共享的类型承诺。

25. @MainActor 保证的是什么？界面卡顿时先看什么？

口述版

  • @MainActor 将声明隔离到主 actor；在 Apple 平台，主 actor 上的代码由主线程执行，常用于保护 UI 状态与主线程限定的操作。
  • 跨越主 actor 隔离边界的调用通常需要 await；处于同一主 actor 隔离上下文时，调用同步隔离方法不需要 await。
  • @MainActor 不会自动拆分同步工作或提高计算速度；主线程上的耗时计算、同步 I/O 和阻塞等待会影响界面响应。
  • 去掉 @MainActor、仅添加 async 或创建继承主 actor 隔离的 Task，都不能保证耗时工作移出主 actor，执行位置还取决于隔离声明与编译设置。
  • Swift 6.2 可用 @concurrent 明确让异步函数离开调用方 actor 执行，再回到主 actor 更新 UI；旧版本应按对应的执行规则安排工作。

解析

例如 SummaryModel.total 是界面要显示的总数，给 SummaryModel 加 @MainActor 后，更新 total 的代码就在主 actor 上执行。在主 actor 之外调用其方法通常要写 await，可能需要等待轮到主 actor 处理；已经在主 actor 上调用它的同步方法，则不需要这次等待。主 actor 规定谁能访问数据，主线程负责实际执行代码，两个名称说的是不同层面的事情。

// 本例需要 Swift 6.2 或更新版本
@concurrent
nonisolated func calculateTotal(_ numbers: [Int]) async -> Int {
    numbers.reduce(0, +) // 在调用方 actor 之外执行计算
}

@MainActor
final class SummaryModel {
    private(set) var total = 0
    func reload(_ numbers: [Int]) async {
        let value = await calculateTotal(numbers)
        // 恢复到本方法所属的主 actor 后更新状态
        total = value
    }
}
func demonstrateMainActor() async {
    let model = await SummaryModel()
    await model.reload([1, 2, 3])
    let total = await model.total
    print(total) // 6
}
await demonstrateMainActor()

例子数据很小，只为演示执行边界。真实代码应先确认计算确实耗时，再决定是否需要移出主 actor；不要为每个微小操作创建任务。@concurrent 也不保证一条固定后台线程，更不表示被它调用的所有函数都忽略自身 actor 隔离。

Swift 6.2 引入的 NonisolatedNonsendingByDefault 设置启用后，普通非隔离 async 函数可以沿用调用方 actor；默认隔离设为 MainActor 时，未显式标注的声明还可能自动隔离到主 actor。因此不能用“没写 @MainActor 的 async 函数”作为跨项目通用的后台计算示例。

排查卡顿先看主线程上的长计算、同步文件操作、锁和信号量等待。await 表示可能挂起，不能靠在函数名旁加上 await 把其中的同步重活自动搬走。

七、加分题

26. 为什么 Array、String、Dictionary、Set 是值类型？copy-on-write 怎么发生？自定义结构体为什么不会自动有？

口述版

  • Array、String、Dictionary、Set 是值类型，赋值后的值可以独立修改；容器保存类引用时，不会因此深复制所引用的对象。
  • 写时复制是按需推迟复制的存储优化：在适用的存储表示下，复制值时先共享底层存储，修改时再确保当前值具有可独立修改的存储。
  • 底层存储仍被共享时，修改通常需要复制；已由当前值独占时通常可以原地修改，但扩容等操作仍可能重新分配内存。
  • 自定义结构体不会自动获得整份值的写时复制机制，各属性按自身类型的复制规则工作；需要共享自定义存储并保持值语义时，应自行管理修改前的存储分离。
  • 写时复制属于实现策略，不应将所有值类型赋值都理解为只复制地址，也不能依赖固定的底层存储形式。

解析

先观察结果，再理解优化。下面 b 的修改不影响 a，这才是使用者可以依赖的行为。赋值时内部是否已经复制、何时复制，由存储表示和实现决定。

let a = [1, 2, 3]
var b = a
b.append(4)
print(a) // [1, 2, 3]
print(b) // [1, 2, 3, 4]

final class Item {
    var name = "旧名称"
}
let first = [Item()]
let second = first
second[0].name = "新名称"
print(first[0].name) // 新名称，元素所指向的类实例并没有深复制

final class Storage {
    var items: [Int]
    init(_ items: [Int]) { self.items = items }
}
struct Queue {
    private var storage = Storage([])
    var items: [Int] { storage.items }
    mutating func append(_ value: Int) {
        if !isKnownUniquelyReferenced(&storage) {
            storage = Storage(storage.items)
        }
        storage.items.append(value)
    }
}
var q1 = Queue()
q1.append(1)
var q2 = q1
q2.append(2)
print(q1.items) // [1]
print(q2.items) // [1, 2]

Queue 用类 Storage 保存数据，所以复制 Queue 时可能先共享同一个 Storage。isKnownUniquelyReferenced 用来检查是否已知只有当前这一条强引用；不能确认唯一时，先创建新的 Storage，再修改。这段代码仅展示基本 COW，不是用于多个任务同时修改同一变量的同步方案。

新 Storage 初始化时，内部 Array 还可以继续共享自己的元素存储；随后 append 会按 Array 的规则分离或扩容。外层结构体的 COW 与内部 Array 的 COW 是两个层次。

不要说“赋值只复制一个地址”来描述所有情况，集合值还可能带有其他信息。短 String 可把字符直接放在值自身的表示中，不一定有共享的堆缓冲区。语言规定行为，标准库和编译器负责让这些行为尽量高效。

27. 协议扩展里写了方法，为什么有时调用不到类型自己的实现？

口述版

  • 方法是否声明为协议要求，决定了通过协议接口调用时能否根据类型的协议遵循选择实现。
  • 声明为协议要求的方法，通过协议类型或泛型约束调用时，依据具体类型对该要求的实现进行派发；协议扩展可以为要求提供默认实现。
  • 仅声明在协议扩展中的方法不属于协议要求。通过协议类型或仅具备相应协议约束的泛型调用时，按调用点可见的静态类型和约束选择扩展实现，不会自动调用具体类型的同名方法。
  • 静态类型是编译器根据声明与推断确定的类型，实际类型是运行时值所属的具体类型。需要通过协议接口支持不同实现时，应将方法纳入协议要求。
  • 类继承已有协议遵循时，子类新增同名方法不会自动替换父类采用的扩展默认实现；需要支持重写时，应由父类提供可重写的方法满足协议要求。

解析

下面 g 的声明类型是 any Greeter，但里面放的是 Pirate。hello 是协议要求，Pirate 提供了实现；bye 只是扩展方法，所以用 g 调用时选择的是扩展的 bye。

protocol Greeter {
    func hello() -> String // 协议要求
}
extension Greeter {
    func hello() -> String { "Hello" } // 要求的默认实现
    func bye() -> String { "Bye" }     // 仅扩展成员，不是协议要求
}
struct Pirate: Greeter {
    func hello() -> String { "Ahoy" }
    func bye() -> String { "Arr" }
}
let pirate = Pirate()       // 静态类型 Pirate
print(pirate.hello())       // Ahoy
print(pirate.bye())         // Arr
let g: any Greeter = pirate // 静态类型 any Greeter，实际值 Pirate
print(g.hello())            // Ahoy，使用 Pirate 满足协议要求的实现
print(g.bye())              // Bye，使用协议扩展的成员

func sayBye<T: Greeter>(_ value: T) -> String {
    value.bye() // 此处只通过 Greeter 约束知道 bye，仍用扩展版本
}
print(sayBye(pirate)) // Bye

如果希望所有遵循者通过协议接口调用 bye 时都能选择自己的实现，就把 func bye() -> String 加进 Greeter 的声明，再在扩展中提供默认实现。若只是通用的辅助方法、不需要这样的多态行为，才只放在扩展里。

补充一个类继承例外：父类遵循协议时如果直接采用扩展默认实现，子类后来新增同名方法，不会自动替换父类已建立的那项协议遵循。希望子类可重写时，应让父类自己提供可重写的方法来满足要求，再让子类 override。不能把“类型写了同名方法就一定会被协议调用”当作通则。

28. 什么是条件遵循？[String] 为什么可以是 Sendable？

口述版

  • 条件遵循是指泛型类型仅在类型参数满足指定约束时才遵循某个协议，通常通过带 where 条件的扩展声明。
  • 标准库 Array 在 Element 满足 Sendable 时满足 Sendable；由于 String 满足 Sendable，因此 [String] 满足这一条件。
  • 元素不满足 Sendable 不影响数组本身的声明与一般使用，但在要求数组满足 Sendable 的接口或并发场景中，需要按对应规则检查。
  • 条件遵循取决于类型参数的约束，不是运行时逐个检查集合元素来决定。
  • Sendable 是编译期并发安全标记协议，不提供普通协议方法的运行时见证表，也不提供自动加锁。

解析

where 可以理解为“还要满足以下条件”。用 Equatable 演示条件遵循，比使用没有方法的标记协议更直观：Equatable 要求类型支持相等比较。

struct Box<Value> {
    var value: Value
}
extension Box: Equatable where Value: Equatable {}
print(Box(value: 1) == Box(value: 1)) // true
// 此处 == 的实现可以由编译器按属性合成

func acceptSendable<T: Sendable>(_ value: T) {}
let titles: [String] = ["Swift", "ARC"]
acceptSendable(titles) // String 满足 Sendable，所以数组也满足

final class MutableItem {
    var name = "项目"
}
let items = [MutableItem()] // 合法：普通可变类也能放在数组中
print(items[0].name)
// acceptSendable(items) // 不满足此函数的 Sendable 泛型约束

标准库已经声明了 Array 对 Sendable 的条件遵循，这里使用它即可，不应在业务代码再写一次 extension Array: Sendable。也不是运行时逐个检查数组元素，再临时决定有没有这项遵循。

普通协议可以有方法要求及对应的见证表机制；Sendable 的作用主要是编译期标记，并不携带这种运行时方法表。元素本身带 actor 等隔离的特殊类型，还应按对应规则理解其并发安全，不能只凭是否有 var 判断。
