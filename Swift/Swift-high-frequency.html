1. 为什么说 Swift 支持面向协议编程（POP）？

重点理解

回答总结

Swift 可以把不同类型共有的能力写成一份协议。 类、结构体和枚举都能遵循协议。函数只要按协议里约定的方法和属性来使用这些值，同一份代码就能处理不同的类型。参数可以用带协议约束的泛型，也可以用 any 协议类型。

协议正文规定需要哪些属性和方法。遵循协议的类型可以自己实现这些要求，也可以采用协议扩展提供的默认实现。这样相同的实现只需要写一份。

代码示例（看注释与结果）

protocol Named {
    var name: String { get }
    // 声明为协议要求，show 才能根据协议遵循关系调用 greeting() 的实现
    func greeting() -> String
}
extension Named {
    func greeting() -> String { "你好，\(name)" } // 默认实现
}
struct User: Named { var name: String }
struct Robot: Named {
    var name: String
    func greeting() -> String { "编号：\(name)" }
}
func show<T: Named>(_ value: T) {
    // 只需要 Named 规定的 greeting()，User 和 Robot 都能传入
    print(value.greeting())
}
show(User(name: "小明"))  // 你好，小明
show(Robot(name: "R1")) // 编号：R1

别答错：方法只写在协议扩展中时，通过协议类型的值或带协议约束的泛型参数调用它，会使用扩展提供的实现；如果希望调用具体类型自己提供的方法实现，应先把方法写进协议声明。

2. 协议扩展的方法为什么有时调用不到自己的实现？

重点理解

回答总结

能不能通过协议调到类型自己的实现，要看这个方法是不是协议要求。 方法声明在协议正文里，就成了协议要求。通过协议调用时，Swift 会用这个类型为该要求选定的实现。这个实现可以是类型自己写的，也可以是扩展提供的默认版本。

如果方法是协议扩展额外加上的，Swift 就根据调用时使用的类型来选。 直接用具体类型调用，可以调到它自己写的同名方法。如果调用时只知道这个值遵循该协议，就会调到扩展里的版本。通过协议类型调用，或者在只知道参数遵循该协议的泛型函数里调用，都属于这种情况。

代码示例（看注释与结果）

protocol Greeter { func hello() -> String }
extension Greeter {
    func hello() -> String { "默认 hello" }
    func bye() -> String { "默认 bye" } // Greeter 声明里没有这个方法
}
struct Person: Greeter {
    func hello() -> String { "自己的 hello" }
    func bye() -> String { "自己的 bye" }
}
let person = Person()
let value: any Greeter = person
print(person.bye())  // 自己的 bye：变量声明为 Person，选择 Person.bye()
print(value.hello()) // 自己的 hello：协议记录由 Person.hello() 实现
print(value.bye())   // 默认 bye：协议没声明 bye()，选择扩展代码

func sayBye<T: Greeter>(_ value: T) -> String { value.bye() }
print(sayBye(person)) // 默认 bye：函数只知道参数遵循 Greeter

补充示例：“子类同名方法不会替换父类已选定的默认实现”，用前面同一个 Greeter 协议对比：

class DefaultGreeter: Greeter {} // hello 采用协议扩展的默认实现
class ChildGreeter: DefaultGreeter {
    func hello() -> String { "子类 hello" }
}
let child = ChildGreeter()
print(child.hello()) // 子类 hello：直接用子类类型调用
let asProtocol: any Greeter = child
print(asProtocol.hello()) // 默认 hello：父类仍记录使用扩展的 hello()

class BaseGreeter: Greeter {
    func hello() -> String { "父类 hello" } // 父类自己实现 hello()，子类才有方法可以 override
}
class OverridingGreeter: BaseGreeter {
    override func hello() -> String { "重写 hello" }
}
let polymorphic: any Greeter = OverridingGreeter()
print(polymorphic.hello()) // 重写 hello：通过协议也能调用到子类 override 后的代码

进一步理解

同一个 Person，为什么换成协议变量后 bye() 变了？

person 声明为 Person，编译器看得见 Person 自己的 bye()，所以调用它。value 声明为 any Greeter，编译器只知道它遵循 Greeter；Greeter 没有要求 bye()，这里就选择扩展提供的 bye()。所谓“静态类型”，就是编译器在这一处知道的变量类型，它会影响方法选择。

hello() 为什么又能调用 Person 的实现？

Greeter 在协议声明里写了 hello()。Person 遵循 Greeter 时，编译器会记下“hello() 由 Person.hello() 实现”。这份记录放在协议见证表中，所以通过 any Greeter 调用 hello() 时，也能调用 Person.hello()。如果 Person 没有自行实现 hello()，就使用 extension Greeter 中提供的 hello() 默认实现。

别答错：扩展写了默认 hello()，也不影响本例调用 Person 自己的 hello()，因为协议声明里有这个方法。

进阶补充：父类采用默认实现时，子类能重写吗？

DefaultGreeter 没写 hello()，编译器便记录“这个类用扩展的 hello() 满足协议”。ChildGreeter 后来写同名方法，并没有改掉父类已经建立的这份记录，所以通过 any Greeter 调用时仍执行扩展代码。要让子类重写后也影响协议调用，先在父类中实现 hello()，再让子类用 override 重写，就像 BaseGreeter 和 OverridingGreeter 那组代码。

3. Swift 协议和 Objective-C 协议有什么区别？

重点理解

回答总结

主要区别是哪些类型能遵循，以及要不要和 Objective-C 互通。 Swift 原生协议支持类、结构体和枚举，也能声明关联类型，让遵循者确定其中的具体类型。需要和 Objective-C 互通时，可以用 @objc 协议。这类协议只能由类遵循，成员用到的类型也要能被 Objective-C 表示。

Swift 的协议扩展可以给要求提供默认实现，采用默认行为的类型直接用这份代码。@objc optional 允许遵循者省略被标记的成员，调用方可以用可选调用来处理成员缺失的情况。

代码示例（看注释与结果）

import Foundation

protocol Drawable { func draw() }
extension Drawable {
    func draw() { print("默认绘制") } // 为 draw() 要求提供默认实现
}
struct Dot: Drawable {}
Dot().draw() // 默认绘制

@objc protocol Clickable: AnyObject {
    @objc optional func click() // Button 可以不实现 click()
}
class Button: NSObject, Clickable {}
let button: any Clickable = Button()
button.click?() // 先检查方法是否存在；本例什么也不做

补充示例：协议声明关联类型 Item，NumberSource 把它确定为 Int：

protocol Source {
    associatedtype Item // 协议声明一个待确定的类型名称
    func load() -> Item
}
struct NumberSource: Source {
    typealias Item = Int // typealias 给已有类型起别名，这里明确 Item 就是 Int
    func load() -> Int { 42 }
}
print(NumberSource().load()) // 42
// @objc 协议不能直接声明这样的 associatedtype

进一步理解

有默认实现，和允许不实现，区别在哪里？

Dot 没写 draw()，但 Drawable 扩展已经写好默认代码，所以 Dot().draw() 能直接执行。Button 没写 optional click()，就可能没有任何 click 方法可执行。button.click?() 会先检查，有方法才调用，没有就跳过。Swift 原生协议不能直接给方法加 optional。

associatedtype 怎样让遵循者决定数据类型？

Source 要求 load() 返回数据，但先不确定数据是什么类型，于是用 associatedtype Item 给这个类型起一个名字。NumberSource 把 Item 定为 Int，load() 就返回 Int。关联类型决定方法使用哪种类型；枚举关联值则是某次创建枚举值时传入的具体数据。

别答错：遵循 Swift 协议的类型没有自行实现协议要求的方法时，可以使用协议扩展提供的默认实现，例如 Dot 没有实现 draw()，仍能调用 Drawable 扩展中的 draw()；遵循 @objc 协议的类则可以不实现 optional 方法，例如 Button 没有实现 click()，调用 button.click?() 时会检查 click() 是否存在，不存在就跳过。

4. Swift 方法调用如何实现？四种派发怎么区分？

重点理解

回答总结

方法派发就是决定一次调用要执行哪份代码。 要判断用哪种派发，看方法是怎么声明的，也看调用时用的是什么类型。

静态派发是在编译时就选好要执行的方法。调用可重写的 Swift 类成员时，虚表派发会根据实际的类，从类的方法表里找到对应实现。

协议见证表派发用在通过协议类型或泛型约束调用协议要求时。Swift 可以通过见证表找到具体类型为这条要求选定的实现。只由协议扩展添加的方法，则按调用处能确定的类型在编译时选择。

Objective-C 消息派发由运行时根据接收者和方法选择器查找实现。Swift 调用 @objc dynamic 方法时会走这套机制。单独写 @objc 是让方法对 Objective-C 可见，Swift 侧的派发还要看方法声明和调用方式。

代码示例（看注释与结果）

import Foundation
protocol Speaker { func speak() -> String }
class Animal {
    func sound() -> String { "Animal" }
}
class Dog: Animal, Speaker {
    override func sound() -> String { "Woof" }
    final func speak() -> String { "Hello" }
}
class Demo: NSObject {
    @objc dynamic func run() { print("Running") }
}
let dog = Dog()
print(dog.speak()) // Hello：final 不允许子类重写，编译器可直接调用
let animal: Animal = dog
print(animal.sound()) // Woof：实际对象是 Dog，查方法表找到 Dog.sound()
let speaker: any Speaker = dog
print(speaker.speak()) // Hello：协议见证表记录调用 Dog.speak()
Demo().run() // Running：交给 Objective-C 运行时查找 run() 再执行

进一步理解

变量写成 Animal，为什么调用到了 Dog.sound()？

animal 虽然声明为 Animal，实际指向的却是 Dog 对象，sound() 又允许子类重写。Dog 的方法地址表中，这个方法对应的是 Dog.sound()，所以程序最终执行 Dog 的代码，输出 Woof。这张表叫虚函数表，调用时按方法对应的位置取地址，不必按名字一层层找父类。

换成 any Speaker，运行时怎么知道该调用哪个 speak()？

Speaker 规定有 speak()，Dog 负责提供实现。Dog 遵循 Speaker 时，编译器记录“Speaker.speak() 对应 Dog.speak()”，这张记录表叫协议见证表。speaker 声明为 any Speaker 时，程序仍能通过这张表找到 Dog.speak()。虚表处理父子类的重写，协议见证表处理类型怎样实现协议方法。

静态派发与 OC 消息派发，分别怎么找目标？

Dog 的 speak() 标记为 final，子类不能再改写；直接用 Dog 调用时，编译器已经能确定实现，不用再查表。Objective-C 的调用则把对象和 selector 交给运行时，由运行时找到 IMP，也就是实际方法代码的地址，再执行。Demo.run() 的 @objc dynamic 要求使用后一种方式。

5. async/await 和 GCD 有什么区别？await 会阻塞线程吗？

重点理解

回答总结

await 本身不会阻塞线程，它表示任务在这里可能挂起。 如果结果还没准备好，任务实际挂起时会让出线程，结果就绪后再接着执行。调用能立即完成时，任务也可以直接往下走。

async 表示函数可以挂起，await 让调用方能按操作的先后关系写代码并拿到结果。GCD 主要负责把工作提交给队列。用 DispatchQueue.async 提交后，调用方可以继续执行，结果通常通过回调传回来。

线程是否被占用，还要看正在执行的操作。在主 actor 上做耗时的同步工作，仍然会占用主线程。

代码示例（看注释与结果）

import Foundation
import Dispatch

// GCD：提交代码块，结果常通过回调传递
// completion 会在全局队列调用；@Sendable 让编译器检查使用的外部变量
func gcdName(completion: @escaping @Sendable (String) -> Void) {
    DispatchQueue.global().async {
        completion("小明") // 这里的回调不保证在主线程
    }
}

// async/await：用返回值表达后续结果
func asyncName() async throws -> String {
    try await Task.sleep(for: .milliseconds(10)) // 等待时暂停任务，不占住线程
    return "小明"
}
func demo() async throws {
    let name = try await asyncName() // 可能暂停任务，等 asyncName() 返回
    print(name) // 等调用返回后，继续执行
}
try await demo() // 把本题保存为独立 Swift 文件后，可以直接这样调用

进一步理解

await 等网络结果时，线程在做什么？

任务发出网络请求后，如果结果还没回来，可以在 await 处暂停。Swift 记下已经执行到哪里、后面需要哪些数据，线程就能先做别的工作。网络结果回来后，Swift 再安排任务接着执行。如果调用不需要等，任务也可以直接继续，所以看到 await 不代表一定暂停。

为什么 async 函数也可能让界面卡顿？

给函数加 async，只是允许任务等待时暂停，不会让每行代码都去后台执行。如果函数在主 actor 上做大量同步计算，主线程仍会一直算，界面就会卡。在主 actor 中创建 Task {} 也可能继续在主 actor 上执行，包一层 Task 并不能把计算移走。同步读文件或用信号量等待，同样可能占住线程。

GCD 的 async 与 Swift 的 async，为什么容易混淆？

DispatchQueue.async 的意思是“把这段代码交给队列，调用方先往下走”；Swift async 函数的意思是“执行途中允许暂停，等条件满足再继续”。后者让你在 await 后直接接着使用返回值，用 throws 处理错误，少写多层回调。具体在哪执行，仍要看队列、actor 和编译设置。

6. async let、TaskGroup、Task 有什么区别？怎么取消？

重点理解

回答总结

子任务数量固定时可以用 async let，需要运行时逐个添加时用 TaskGroup。 用 await 取得 async let 的结果。任务组按子任务完成的顺序产出结果。两种方式都由所在的作用域管理，离开作用域前会等子任务结束，父任务收到取消请求时也会把请求传给子任务。

直接创建 Task 得到的是非结构化任务。创建它的任务即使结束或被取消，它也可以继续运行。需要等它完成或请求取消时，可以通过创建时拿到的任务句柄来做。

取消是协作的。调用 cancel() 只是发出取消请求，任务可以检查状态后主动结束，也可以通过支持取消的 API 响应。等待任务结果时，如果任务抛了错，等待方也会收到这个错误。

代码示例（看注释与结果）

func fetch(_ id: Int) async throws -> Int {
    try Task.checkCancellation() // 已取消则抛 CancellationError
    return id
}
func loadPair() async throws -> Int {
    async let a = fetch(1) // 固定数量的两个子任务
    async let b = fetch(2)
    let values = try await (a, b)
    return values.0 + values.1
}
func loadMany() async -> Int {
    await withTaskGroup(of: Int.self) { group in
        for id in 1...3 {
            group.addTask { id } // 动态数量；结果按完成顺序收集
        }
        var sum = 0
        for await value in group { sum += value }
        return sum
    }
}
func demo() async throws {
    print(try await loadPair()) // 3
    print(await loadMany())     // 6
}
try await demo()

补充示例：下面创建一个含 Task.sleep 的非结构化任务，用返回的句柄 handle 请求取消，并等待任务退出。

let handle = Task {
    do {
        try await Task.sleep(for: .seconds(10)) // 等待期间收到取消请求时，会抛出 CancellationError
        try Task.checkCancellation()           // 若已取消，抛 CancellationError
        print("工作完成")
    } catch is CancellationError {
        print("收到取消，结束任务")
    } catch {
        print("其他错误", error)
    }
}
handle.cancel()
await handle.value // 等它实际退出；本例输出“收到取消，结束任务”

进一步理解

同时请求两份数据，为什么适合 async let？

页面固定要加载用户资料和订单，可以写两个 async let，再等待两份结果。要加载的数量由列表决定，就用 TaskGroup 在循环中添加子任务。这些子任务不能在对应代码块退出后还悄悄继续运行，退出前必须等它们结束。任务组先返回先完成的结果；需要保持列表顺序时，要把索引一起返回，最后按索引排序。

为什么 cancel() 之后还需要 await？

cancel() 把任务标记为已取消，但任务当前执行的代码不会被强行打断。任务检查 Task.isCancelled，或调用 Task.checkCancellation()，才知道该退出；Task.sleep 等 API 也会响应取消。await handle.value 则让调用方等到任务确实结束。任务已经完成时，再 cancel() 也不会撤回已得到的结果。

离开函数后，Task {} 为什么还可能继续运行？

Task {} 创建的是脱离当前作用域的“独立任务”：即使外层函数已经返回，或者当前父任务被取消了，它也不会自动停下来。因此需要自己用变量保存它返回的控制句柄 handle——调用 handle.cancel() 用来请求取消，调用 await handle.value 用来等待它跑完并拿到返回值。它虽然会继承创建位置的 actor 等上下文环境，但生命周期仍需要自行管理。

进阶补充：退出作用域时，子任务怎样结束？

离开代码块时，如果 async let 的结果还没被等待，Swift 会先请求取消这个子任务，再等它结束。普通任务组正常退出时会等剩余任务做完；要提前请求取消，可以调用 group.cancelAll()。withThrowingTaskGroup 的闭包向外抛错时，也会先取消并等待剩余子任务。任务如果一直不响应取消，等待它结束的代码也不能及时退出。

7. actor、@MainActor、Sendable 各自解决什么问题？

重点理解

回答总结

actor 用来保护多个任务都要访问的可变状态。 同一个 actor 在同一时刻只执行一段访问其隔离状态的代码。如果一个方法在 await 处挂起了，其他任务可以在这期间进入 actor 并修改状态。恢复后，要重新确认之前依赖的条件还成立。

@MainActor 让代码和状态由主 actor 管理。在 iOS 上，这些代码在主线程执行，适合更新界面和管理 UI 状态。耗时的同步工作仍会占用主线程。

Sendable 表示某种类型的值可以安全地在任务或 actor 之间传递或共享。如果类型内部有共享的可变数据，就要自己做好同步。

代码示例（看注释与结果）

actor Counter {
    private var value = 0
    func increment() -> Int {
        value += 1 // 没有 await，不会在加 1 的中途让另一个任务也来修改 value
        return value
    }
}
struct Snapshot: Sendable { let count: Int }

@MainActor
final class ScreenModel {
    private(set) var title = "0"
    func apply(_ snapshot: Snapshot) {
        title = String(snapshot.count) // 在主 actor 上修改用于显示的 title
    }
}
func demo() async {
    let counter = Counter() // actor 是引用类型，赋值给另一个变量后仍指向同一个 Counter
    let number = await counter.increment() // 请 Counter 执行 increment()，可能要等它安排执行
    let snapshot = Snapshot(count: number)
    let model = await ScreenModel()
    await model.apply(snapshot)
    print(await model.title) // 1
}
await demo()

actor Wallet {
    private var balance = 100
    func withdraw(
        _ amount: Int,
        authorize: @Sendable () async -> Bool
    ) async -> Bool {
        guard amount > 0, balance >= amount else { return false }
        guard await authorize() else { return false } // 等授权时可能暂停，其他提款也可能进来改余额
        guard balance >= amount else { return false } // 等待结束后，余额可能已变化，必须再检查
        balance -= amount // 重新检查到扣减之间没有 await
        return true
    }
}
// 若删掉第二次余额检查，两笔提款可能都通过第一次检查，最终把余额扣成负数。
// @Sendable 让编译器检查 authorize 使用的外部变量，async 允许等待时暂停。

let wallet = Wallet()
async let firstWithdrawal = wallet.withdraw(80) {
    try? await Task.sleep(for: .milliseconds(10)) // 模拟等待授权结果
    return true
}
async let secondWithdrawal = wallet.withdraw(80) {
    try? await Task.sleep(for: .milliseconds(10))
    return true
}
let withdrawals = await (firstWithdrawal, secondWithdrawal)
print([withdrawals.0, withdrawals.1].filter { $0 }.count) // 1：余额只够一笔
// 哪一笔成功不保证；第二次检查确保不会两笔都扣款。

进一步理解

actor 是怎样保护共享计数器的？

两个任务都给普通共享变量加 1，可能同时读到 0，然后都写回 1，少算了一次。Counter 把 value 保存在 actor 中，increment() 从读取到加 1、写回，中间没有 await，不会在这段过程里让另一个任务也来改 value。外部代码必须按 actor 的规则访问。actor 不需要为每个对象单独创建一条线程。

既然 actor 会串行访问，为什么提款还要检查两次余额？

余额是 100，两笔请求都想取 80。第一笔检查通过后 await 等授权，暂停期间第二笔也可能进来，看到余额仍是 100，也通过检查。等第一笔扣款后，第二笔继续执行时，之前检查的余额就已经不适用了。所以授权后要再检查，并在检查到扣款之间不再 await。允许任务暂停时执行同一 actor 中的其他工作，这种行为叫“重入”。

@MainActor 与 Sendable 为什么不能互相替代？

两者解决的问题完全不同，不能互相替代：@MainActor 管的是“代码在哪执行”——它强制要求 ScreenModel 中 title 等状态的读写都在主线程（主 actor）上排队执行，避免后台线程直接改界面；而 Sendable 管的是“数据能不能安全跨任务传递”——它向编译器证明像 Snapshot（内部只有不可变的 Int）这样的值在多个并发任务之间传递或共享时，不会出现“一边写一边读”的数据竞争。

进阶补充：Sendable 检查什么？

结构体的属性、枚举携带的数据都要符合相应的 Sendable 要求。普通类如果不依赖 actor 保护，常见做法是声明为 final，并只保存不可修改的 Sendable 属性。actor 可以安全地把引用传给其他任务，因为内部数据仍按 actor 的规则访问。@Sendable 用在闭包类型上，让编译器检查它捕获的内容；写 @unchecked Sendable 则表示由开发者自己保证安全，不会自动生成锁。

8. Swift 实例对象、类、元类的内部结构是什么？

进阶选学

回答总结

实例保存自己的数据，同一类的实例共用类的运行时信息。 实例里有自己的存储属性，原生 Swift 类实例的对象头还带有类型和引用计数相关的信息。类元数据告诉运行时实例多大、属性放在哪里、父类是谁，并提供查找方法所需的信息。

在 Objective-C 运行时里，类本身也是一个对象。类对象通过 isa 找到元类，运行时可以从元类查找类方法。Swift 的元类型用于在代码里表示类型本身，让类型也能作为值保存或传递。

代码示例（看注释与结果）

import Foundation
import ObjectiveC

class Person: NSObject {
    var age = 18
    @objc class func species() -> String { "Human" }
}
let person = Person()         // 创建实例，保存 age 等实例数据
let typeValue: Person.Type = Person.self // 表示 Person 类型的值，不会创建实例
print(type(of: person) == typeValue) // true

if let cls = object_getClass(person), // person 所属的类
   let meta = object_getClass(cls) {  // 再查类对象所属的类，得到 OC 元类
    print(class_isMetaClass(cls))     // false
    print(class_isMetaClass(meta))    // true
}
print(Person.species()) // Human

进一步理解

创建两个 Person，会把方法代码也复制两份吗？

每次 Person() 都创建一个对象，各自保存 age，也各有管理对象所需的对象头。两个对象可以共用 Person 的类元数据和方法代码。类元数据记录这个类的实例有多大、属性放在哪里、有哪些方法地址；对象头中的类型信息让 Swift 能找到这份记录。

Person.self 和 Person() 为什么不是同一种东西？

Person() 创建一个人，里面有这个人的 age；Person.self 表示“Person 这个类型”，不会创建人。可以用 Person.Type 的变量保存 Person.self，也可以把它传给需要类型的函数。Person.Type 还能保存 Person 的子类类型；Swift 把这种用于表示类型的类型叫“元类型”。

Swift 元类型与 Objective-C 元类有什么区别？

Objective-C 里类也是对象。object_getClass(person) 先得到 Person 类对象；再对这个类对象调用 object_getClass，就得到 Person 的元类，里面保存 Objective-C 类方法的信息。Swift 的 Person.Type 则是代码里用来声明类型值的写法，两者不是同一概念，也不能据此判断 Swift 类型方法一定通过 Objective-C 调用。

9. Swift 协议内部是什么？见证表、存在容器怎么理解？

进阶选学

回答总结

理解协议的运行时结构，可以先分清方法怎么找、值怎么存。 协议描述符记录协议有哪些要求。协议见证表记录某个具体类型用哪些实现来满足这些要求。通过协议调用这些方法时，Swift 就能从表里找到要执行的实现。

用没有类约束的普通 any 协议类型保存值时，Swift 会用一个固定大小的“打包盒”（即存在容器）来统一装下任意遵循该协议的值：盒子里既保存值本身（或它的堆内存地址），也记录着具体类型信息和协议见证表。只要值小到能放进盒子自带的缓冲区就直接存进去；放不下就另外分配一块内存保存，盒子里只记下地址。

类型元数据标识具体类型，并关联值见证表。值见证表告诉 Swift 值占多少空间、怎样复制和销毁。带协议约束的泛型也可以用协议见证表调用协议要求，同时按泛型参数的具体类型传递值。

代码示例（看注释与结果）

protocol Speaker { func speak() -> String }
struct Dog: Speaker {
    var age: Int
    func speak() -> String { "Woof" }
}
struct BigSpeaker: Speaker {
    // 常见 64 位 Apple 平台上占 32 字节，容器内部 24 字节放不下
    var a, b, c, d: Int
    func speak() -> String { "Big" }
}
let small: any Speaker = Dog(age: 1)
let large: any Speaker = BigSpeaker(a: 1, b: 2, c: 3, d: 4)
print(small.speak()) // Woof
print(large.speak()) // Big：调用方不必知道容器里的具体类型

func call<T: Speaker>(_ value: T) -> String { value.speak() }
// 输出 Woof：泛型函数直接接收 Dog，不用先装进 any Speaker 容器
print(call(Dog(age: 2)))
// 本例在常见 64 位 Apple 平台上为 40 字节，
// 不包括 large 容器外单独分配的 BigSpeaker 内存
print(MemoryLayout<any Speaker>.size)

进一步理解

只知道 any Speaker，为什么仍然能调用 speak()？

small 里存的是 Dog，large 里存的是 BigSpeaker，但变量都声明为 any Speaker。Swift 不只保存数据，还记下实际类型和 speak() 对应的实现。调用 small.speak() 时，就能用这些记录找到 Dog.speak()；复制或销毁 small 时，也知道该怎样处理里面的 Dog。保存这些内容的内存表示就叫“存在容器”。

协议见证表和值见证表，为什么要分开？

协议见证表用于调用协议方法，例如找到 Dog 的 speak()。值见证表用于复制、销毁某种类型的值；Swift 通过类型元数据找到它。协议描述符则记录协议本身规定了什么。简单说，一张表告诉程序“调用哪份方法”，另一张表告诉程序“怎样复制和清理这个值”，协议描述符列出要求。

值太大放不下，存在容器怎么办？

本例在常见 64 位 Apple 平台上，容器里用于直接放值的空间是 24 字节。Dog 只有一个 Int，可以放进去；BigSpeaker 有四个 Int，放不下，Swift 就把它保存到另一块内存，并在容器里记下地址。MemoryLayout 只计算容器自身的大小，不会再把那块单独分配的内存加进来。

别答错：泛型函数可以直接接收具体类型的值，不需要先把它存进 any 变量；协议值也不一定另分配一块堆内存。

进阶补充：为什么本例的容器是 40 字节？

本例在常见 64 位 Apple 平台上，容器有 24 字节用于存值，再用 8 字节保存类型元数据的地址、8 字节保存协议见证表的地址，共 40 字节。这里一个地址占 8 字节。协议如果有 AnyObject 等限制，Swift 可以采用其他保存方式，因此不是所有 any 类型都固定占 40 字节。

10. struct、class、enum 有什么区别？什么时候用？

基础优先

回答总结

选择 struct、class 还是 enum，先看数据该怎么用。 数据需要各自保存、各自修改时，用值类型的 struct。赋值或传参后，各自持有一份值。结构体如果保存了对象引用，复制该引用后仍然可能指向同一个对象。

需要多处使用同一个对象、区分对象身份，或者需要继承时，用引用类型的 class。赋值和传参传的是引用，指向同一个对象的地方都能看到它的状态变化。

需要表示几种互斥的状态时，用 enum。它也是值类型，每个值只属于其中一种情况，每种情况都可以带自己的数据。三种类型都可以定义属性和方法，也能遵循协议。

代码示例（看注释与结果）

struct Profile { var name: String }
var a = Profile(name: "小明")
var b = a
b.name = "小红"
print(a.name) // 小明：修改 b 不影响 a

class Account { var balance = 0 }
let x = Account()
let y = x
// let 不允许 x、y 改指向别的对象，但可以修改这个对象的 var 属性
y.balance = 100
print(x.balance) // 100：x 和 y 指向同一对象
print(x === y)   // true：比较是不是同一实例

enum State {
    case loading
    case success(String) // 关联值：本次成功附带的数据
    case failure(Int)
}
let state = State.success("加载成功")

进一步理解

值类型赋值后，为什么修改一份不会影响另一份？

执行 var b = a 后，a 和 b 各自保存一份 Profile。把 b.name 改成“小红”，a.name 仍然是“小明”。Swift 保证两份结构体的修改互不影响，但可以优化实际复制过程，不要求赋值时立即复制每个字节。

结构体里保存类对象，还会完全互不影响吗？

如果 Profile 的一个属性保存 Account 对象，复制 Profile 时，Swift 复制的是指向 Account 的引用，不会再创建一个 Account。两份 Profile 仍可能使用同一个账户，所以修改账户余额后，两边都能读到新余额。如果只是把 b 中保存 Account 引用的属性改为指向一个新的 Account 对象，a 中的该属性仍然指向原来的 Account 对象。

为什么修改结构体属性要写 mutating？

结构体和枚举的方法默认不能修改自己保存的属性。方法要改属性、给 self 重新赋值，或把枚举从一个 case 改成另一个 case，就要加 mutating，表示“调用这个方法会修改当前值”。调用方也要用 var 保存这个值。只修改属性所引用的 Account 对象、没有替换这个引用时，不需要 mutating。

枚举的关联值和原始值分别有什么用？

关联值是创建枚举值时传进去的数据，例如 success 后面的“加载成功”，每次可以不同。原始值是声明 case 时确定的固定值，可用 rawValue 读取。前者用来保存这次状态附带的数据，后者用来对应接口中的固定编号或字符串。

别答错：区分值类型和引用类型，先看赋值后修改会影响谁，不要直接判断它们一定放在栈还是堆。

11. Optional 是什么？if let、guard let、?? 和类型转换怎么用？

基础优先

回答总结

Optional 表示一个值可能存在，也可能不存在。 有值时包着原来的值，没有值时就是 nil。只在有值的分支里使用它，就用 if let。希望没有值时提前退出、有值时接着往下用，就用 guard let。

需要一个默认值时用 ??，左边是 nil 时才计算默认值。需要在对象有值时访问它的属性或方法，就用 ?.，链上遇到 nil 就返回 nil。

is 用来检查类型，as 用于编译器能确认成立的转换，as? 尝试转换，失败会得到 nil。强制解包和 as! 都要求调用方保证能成功，失败会触发运行时错误。

代码示例（看注释与结果）

let nickname: String? = nil
print(nickname ?? "游客")       // 游客
print(nickname?.count as Any) // nil：不会访问不存在的字符串

func greet(_ input: String?) {
    guard let name = input else {
        print("没有名字")
        return // 没有值就 return，后面的代码不再执行
    }
    print(name) // name 已经是 String，可以直接使用
}
greet("小明")

let value: Any = "Swift"
if let text = value as? String { // 转换失败得到 nil
    print(text.count) // 5
}
print(value is String) // true，只检查类型
// nickname!          // nil 没有值可取，这样写会崩溃，catch 不能处理

进一步理解

为什么空字符串与 nil 不能混为一谈？

昵称是 ""，说明拿到了一个 String，只是里面没有字符；昵称是 nil，说明没有拿到字符串。用户清空输入框时可能得到空字符串，接口没返回昵称时可以用 nil 表示。页面可以分别处理：空字符串提示重新填写，nil 则显示默认昵称。

用 ?? 会修改原变量吗？

表达式 nickname ?? "游客" 会返回用于显示的字符串。它不会修改 nickname。

as? 为什么经常与 if let 一起出现？

value 声明为 Any，编译器不知道里面一定是字符串，不能直接调用字符串的方法。value as? String 先尝试把它当作 String，成功时返回包含字符串的 String?，失败时返回 nil。接着用 if let 取出字符串，就能安全访问 count。只想知道类型是不是 String，用 is 即可。

12. 存储属性、计算属性、lazy、static 和 class 怎么区分？

基础优先

回答总结

存储属性把值保存下来，计算属性在访问时执行代码。 读取计算属性时走 getter，如果它可写，赋值时走 setter。lazy var 也是存储属性，第一次访问时才生成并存下初值，之后直接使用存下来的值。

想在属性被赋值时做处理，可以用 willSet 和 didSet，分别在写入前后执行。初始化器直接设置本类存储属性的初值时，这两个观察器不会执行。

static 和 class 声明的是属于类型的成员。 需要类型存储属性，或者想固定实现，用 static。类的类型方法或计算属性需要让子类重写时，用 class。

代码示例（看注释与结果）

struct Meter {
    var value = 1 {
        didSet { print("旧值", oldValue, "新值", value) }
    }
    var doubled: Int { value * 2 } // 计算属性，不单独保存结果
    lazy var history = [0, 1]      // 第一次访问才初始化，必须是 var
    static let unit = "米"         // 类型属性：Meter.unit
}
var meter = Meter()
meter.value = 3         // 旧值 1 新值 3
print(meter.doubled)    // 6
print(meter.history)    // [0, 1]
print(Meter.unit)       // 米

class Vehicle {
    static func category() -> String { "车辆" }
    class func name() -> String { "普通车" }
}
class Car: Vehicle {
    override class func name() -> String { "汽车" }
}
print(Car.name())       // 汽车
print(Car.category())   // 车辆：static 可以继承，但不能重写

补充示例：前面的 doubled 只有 getter，省略了 get { }。这里补上可读写计算属性与 willSet：

struct Temperature {
    var celsius = 0.0 {
        willSet { print("准备写入", newValue) }
        didSet { print("原来是", oldValue) }
    }
    var fahrenheit: Double {
        get { celsius * 1.8 + 32 }
        set { celsius = (newValue - 32) / 1.8 } // 改的是 celsius
    }
}
var temperature = Temperature()
temperature.fahrenheit = 212 // 准备写入 100.0；原来是 0.0
print(temperature.celsius)   // 100.0

进一步理解

存储属性与计算属性，读取时到底有什么不同？

Meter 的 value 直接保存数值。doubled 没有另外保存一个结果，每次读取它，Swift 都执行 value * 2，所以 value 改成 3 后，doubled 返回 6。计算属性也能处理赋值：给 fahrenheit 设置 212 时，setter 把它换算成 100，再写入 celsius。

lazy 为什么必须是 var？什么时候适合用？

有些对象创建比较费时，但页面不一定会用到，可以把属性声明为 lazy，等第一次访问时再创建。首次访问还要把创建结果存回属性，所以必须使用 var。后面再次读取时会直接返回已保存的值，不会因为其他属性变化而重新创建。

willSet 和 didSet 各能看到什么？

执行 meter.value = 3 时，Swift 先运行 willSet：value 还是旧值，newValue 是即将写入的 3。写入后再运行 didSet：value 已经是 3，oldValue 保存之前的值。它们适合记录变化或触发刷新；如果要把传入值换算后保存，使用计算属性的 setter 更合适。初始化器直接给本类型的存储属性设置初值时，不会调用这两个观察器。

static 和 class 为什么不通过实例访问？

每个 Meter 都有自己的 value，但“米”这个单位可以由所有 Meter 共用，所以写成 static let unit，用 Meter.unit 读取。Car 可以使用从 Vehicle 继承的 static category()，却不能替换它的实现。Vehicle 把 name() 声明为 class func，Car 就能用 override 改成自己的实现。

别答错：lazy 的值创建后就会保存下来，不会因为其他属性变化而自动重新计算。

进阶补充：lazy 与类型存储属性的线程安全

多个线程同时第一次访问同一个 lazy 属性时，Swift 不保证只创建一次。static 存储属性则保证初始化只执行一次。不过，后面如果多个任务要修改 static var，或修改 static let 指向的对象，仍要安排好访问顺序，不能同时随意读写。

13. Swift 初始化器有哪些？两阶段初始化是什么？

基础优先

回答总结

类的两阶段初始化，先把整个对象的存储属性准备好，再做额外设置。 第一阶段由各级指定初始化器给自己负责的存储属性设置初值。子类先初始化自己新增的属性，再用 super.init 交给父类的指定初始化器。进入第二阶段后，才能读取实例属性、调用实例方法或把 self 传出去。

convenience init 给调用方提供另一种创建方式。它用 self.init 调用同一个类的其他初始化器，这条调用链最终要走到本类的指定初始化器。

允许创建失败并返回 nil 时，用 init?。希望调用方知道失败原因，就让初始化器抛出错误。required 表示子类也要支持这个初始化器，可以直接继承，也可以按规则自己实现。

代码示例（看注释与结果）

class Vehicle {
    var name: String
    init(name: String) { self.name = name } // 指定初始化器
    convenience init() {
        self.init(name: "默认车") // 便利初始化器调用指定初始化器
    }
}
class Car: Vehicle {
    var seats: Int
    init(name: String, seats: Int) {
        self.seats = seats      // ① Car 先设置自己的 seats
        super.init(name: name)  // ② Vehicle 设置它负责的 name
        print(self.name)       // ③ 现在可以读取属性、调用实例方法
    }
}
let car = Car(name: "小车", seats: 4)

struct Age {
    let value: Int
    init?(_ value: Int) {
        guard value >= 0 else { return nil } // 年龄无效时不创建 Age，返回 nil
        self.value = value
    }
}
print(Age(-1) as Any) // nil

    required init(name: String) { // 父类规定：所有子类都要支持这个创建方式

    let storage: Int

        self.storage = storage
        super.init(name: name)
    }
    required init(name: String) { // 必须补上父类要求的创建方式；这里不写 override
        self.storage = 128       // 子类决定该方式下自己的属性如何初始化
        super.init(name: name)
    }
}
let phone = Phone(name: "手机") // 使用 required init(name:)，容量为 128
print(phone.name, phone.storage) // 手机 128

14. ARC 怎么工作？weak、unowned 和循环引用怎么处理？

基础优先

回答总结

ARC 根据强引用决定类实例什么时候释放。 编译器会在需要的地方插入增加和释放引用的操作。最后一个强引用消失时，对象会执行 deinit，然后被销毁。

weak 和 unowned 都不会延长对象的生命周期。对象可能先释放时用 weak，释放后读到的是 nil。能保证每次访问时对象都还在，才用 unowned，否则访问已释放的对象会触发运行时错误。

循环引用是强引用绕成一圈，每一方都被圈内的另一方持有，导致引用计数降不到零。可以按双方的生命周期，把其中一条引用改成 weak 或 unowned，也可以在合适的时机主动清掉强引用。

代码示例（看注释与结果）

final class Page {
    var onTap: (() -> Void)?
    func bind() {
        onTap = { [weak self] in // 闭包不阻止 Page 释放
            self?.refresh()     // Page 已释放就不调用
        }
        // onTap = { self.refresh() } // Page 保存闭包，闭包又强引用 Page，双方都无法释放
    }
    func refresh() { print("刷新") }
    deinit { print("Page 释放") }
}
func demo() {
    var page: Page? = Page()
    weak var observer = page
    page?.bind()
    page?.onTap?() // 刷新
    page = nil    // 本例没有其他强引用，Page 释放并执行 deinit
    print(observer as Any) // nil：Page 释放后，这个弱引用自动变成 nil
}
demo()

    func didRefresh()
}

}

}

    let owner = Owner()
    owner.card = Card(owner: owner)

    // 不要把 card 留到 owner 销毁之后再经它访问 owner
}

进一步理解

ARC 的“自动”体现在哪里？编译期与运行时各做什么？

Swift 开发者不需要手动调用 retain 和 release。编译器根据引用的使用情况插入这些操作，程序运行时再执行它们，对象也在运行时释放。ARC 依靠强引用计数判断能否释放对象，不会扫描出循环引用再自动拆开。

为什么外面的变量清空了，对象还没有释放？

Page 的 onTap 属性保存闭包，闭包又通过 self 保存 Page 的强引用。外部执行 page = nil 后，只是外部变量不再引用 Page；Page 和闭包还互相引用，所以仍然无法释放。把闭包里的 self 改成 weak，或在合适时机把 onTap 清空，就能断开其中一条强引用。

为什么 [weak self] 能打断环，guard let self 又有什么作用？

[weak self] 让闭包使用 Page 时，不负责让 Page 一直存在。Page 释放后 self 自动变成 nil，self?.refresh() 就不再调用。guard let self 会先检查 Page 是否还存在，存在就把它保存为一个强引用，供后续代码使用。如果后续长时间等待异步结果，Page 也可能跟着这个强引用保留更久。

weak 与 unowned 应该怎么选？

页面关闭后，网络回调仍可能到达，这时用 weak：页面已释放就跳过更新。unowned 要求每次访问时对方一定还存在，否则会崩溃。iOS 的 delegate 通常使用 weak；代理协议写 : AnyObject，表示只有类能遵循，才能把这种协议类型用作 weak 属性。

15. 闭包如何捕获变量？@escaping、@autoclosure 有什么用？

基础优先

回答总结

捕获让闭包能使用定义位置外层的变量。 默认捕获一个可变局部变量时，闭包和外部代码读写同一份变量。用捕获列表按值捕获时，闭包会记住自己创建时的值。值如果是类引用，保存的仍是指向原对象的引用。

闭包默认用强引用持有捕获的对象。如果对象也持有这个闭包，就可能形成循环引用。对象可能先释放时可以用 weak 捕获，能保证每次访问时对象都还在才用 unowned。

@escaping 表示函数返回后，传进来的闭包仍然可以被调用。@autoclosure 会把传入的表达式包装成一个无参数闭包，只有真正调用这个闭包时，表达式才会求值。

代码示例（看注释与结果）

func demoCapture() {
    var count = 1
    let readLive = { count }           // 读取外面的 count，外部修改后能读到新值
    let readSnapshot = { [count] in count } // 创建时保存当时的 1，不受后面 count 修改影响
    count = 2
    print(readLive())     // 2
    print(readSnapshot()) // 1
}
demoCapture()

func save(_ action: @escaping () -> Void) -> () -> Void {
    action // 允许返回，让调用者以后执行
}
let action = save { print("执行") }
action()

func log(_ enabled: Bool, _ text: @autoclosure () -> String) {
    if enabled { print(text()) } // 执行 text() 时才计算传入的表达式
}
log(false, String(1 + 2)) // 不执行 text()，也就不计算 String(1 + 2)

进一步理解

同一个 count，为什么一个闭包读到 2，另一个读到 1？

readLive 使用外面的 count，外部把 count 从 1 改成 2 后，readLive() 就返回 2。readSnapshot 写了 [count]，创建闭包时已经保存了当时的 1，之后仍返回 1。如果通过捕获列表按值保存的是类对象的引用，闭包保存的是创建时指向该对象的引用，不会另外创建一个类对象。

什么情况下，闭包参数需要标记 @escaping？

下载函数接收一个完成闭包，把它保存起来，然后先返回；下载完成后再执行这个闭包。闭包需要在函数返回后继续使用，这就叫“逃逸”，参数要写 @escaping。这个标记只允许闭包被保存或返回，不会自动让它异步执行，也不会自动把 self 改为弱引用。

@autoclosure 帮调用方省掉了什么？

普通写法需要传 { 表达式 }，@autoclosure 允许调用方直接传表达式，编译器会补上这层闭包。上面代码中的 log 先检查 enabled，只有为 true 才调用 text() 计算日志内容。enabled 为 false 时，连表达式都不用计算。函数调用 text() 几次，表达式就计算几次。

别答错：@escaping 允许闭包在函数返回后使用，不表示异步执行；@autoclosure 也不会自动切换到后台。

进阶补充：可选闭包参数

普通闭包参数默认只能在函数返回前使用，需要留到返回后再用时，加 @escaping。可选闭包参数 action: (() -> Void)? 本来就允许保存到函数返回后使用，不需要也不能再加 @escaping。两者都不会自动把捕获的 self 变成弱引用。

16. Array 是值类型，为什么复制不一定很贵？COW 是什么？

基础优先

回答总结

Array 赋值时可以先共用存放元素的空间，所以往往不用马上复制元素。 数组是值类型，两份数组的内容各自独立。一份数组要写入，而底层存储还被共用时，Swift 就会为它准备独立的存储并复制元素。这就是写时复制，也叫 COW。

如果存储已经独占，而且容量足够，就可以直接在原来的空间里写。数组的元素如果是类引用，复制元素时复制的是引用，两边仍可能指向同一个对象。

多个任务如果访问的是同一个可变数组变量，有一方写入时，仍要用同步或隔离来保护这份变量。

代码示例（看注释与结果）

let a = [1, 2, 3]
var b = a       // a、b 可以先使用同一块存放元素的内存
b.append(4)     // 先为 b 复制元素，再追加 4，不改动 a
print(a)        // [1, 2, 3]
print(b)        // [1, 2, 3, 4]

final class Item { var name = "旧" }
let first = [Item()]
let second = first
second[0].name = "新" // 改的是两份数组都指向的同一个 Item 对象
print(first[0].name) // 新：复制数组时，没有另外创建 Item

进一步理解

复制数组后，为什么修改对象属性，两边都会变？

first 和 second 的第一个元素都指向同一个 Item 对象。second[0].name = "新" 修改的是这个对象，所以通过 first[0].name 也会读到“新”。复制数组不会顺便复制类对象。如果是把 second[0] 换成另一个 Item，才只会改变 second 的数组内容。

有了 COW，是否就能放心并发修改数组？

COW 只负责在需要时复制元素，不负责安排多个任务谁先读、谁后写。两个任务同时读写同一个数组变量，仍可能出错，需要通过 actor、锁等方式控制访问。另外，追加元素时如果原来的内存已经放不下更多元素，即使没有其他数组使用它，也可能需要分配更大的内存。

自己实现 COW 时，修改数据前，要先确认保存数据的对象是否只有当前这一份强引用。能确认时直接修改；不能确认时，先把数据复制到新的对象，再修改新对象。isKnownUniquelyReferenced(_:) 可以做这项检查，但不会安排多个线程的访问顺序，不能代替锁或 actor。

17. map、compactMap、flatMap 有什么区别？

基础优先

回答总结

对序列来说，这三个方法都会逐项做转换，区别在于怎么收集结果。 map 保留每一项的转换结果。compactMap 接收可能返回 nil 的转换，跳过 nil，把有值的结果解包后收集起来。flatMap 则把每一项转换成一个序列，再把这些序列拼在一起，展开一层。

用在 Optional 上时，原来是 nil 就直接返回 nil。有值时，map 会把转换结果再包成一个可选值。如果转换本来就返回可选值，flatMap 会直接用这个结果。

代码示例（看注释与结果）

let input = ["1", "x", "3"]
let a = input.map { Int($0) }        // [Int?]
let b = input.compactMap { Int($0) } // [Int]
print(a) // [Optional(1), nil, Optional(3)]
print(b) // [1, 3]

let groups = [[1, 2], [3]]
print(groups.flatMap { $0 }) // [1, 2, 3]：把两个子数组的元素接起来

let text: String? = "x"
let nested: Int?? = text.map { Int($0) } // some(nil)
let single: Int? = text.flatMap { Int($0) } // nil：不在转换结果外面再包一层 Optional

进一步理解

把字符串转成整数，为什么 map 会保留 nil？

map 为每项保留一个结果，因此可以从 nil 的位置找到转换失败的输入。只需要有效结果时，用 compactMap。

flatMap 的“展开一层”是什么过程？

列表页要把多个分组的条目合成一个数组时，可以用 flatMap 按顺序收集各组的元素。

Optional 也有 flatMap，和拼数组是一回事吗？

text 是 String?，里面有 "x"。调用 text.map { Int($0) } 和 text.flatMap { Int($0) } 时，Optional.map 和 Optional.flatMap 都会执行闭包中的 Int("x")，转换失败得到 nil。Optional.map 还要在转换结果外面再包一层 Optional，所以得到 .some(nil)，类型是 Int??：原字符串存在，但数字转换失败。Optional.flatMap 直接返回转换得到的 nil，类型是 Int?。这里处理的是一个可选值，不是在合并数组。

别答错：数组的 flatMap 可以合并子数组，Optional.flatMap 避免多包一层可选值；去掉数组转换结果中的 nil 用 compactMap。

18. throws、try?、try!、Result 和 defer 怎么用？

基础优先

回答总结

错误在哪里处理，取决于哪一层知道失败后该怎么办。 函数用 throws 声明可能抛错，用 throw 抛出错误。调用方用 try 标记调用，可以用 do-catch 处理，也可以在自己的抛错函数里把错误继续传给上层。

只关心有没有拿到值时，可以用 try?，失败就得到 nil。能保证成功时才用 try!，实际抛错会触发运行时错误。需要把结果保存起来或交给别的代码处理时，用 Result，成功时带上结果值，失败时带上错误。

defer 用来登记收尾工作。执行过这条声明后，只要离开当前作用域，无论是正常走完、提前返回还是抛错，都要运行这段代码。同一个作用域里，后登记的会先执行。

代码示例（看注释与结果）

enum InputError: Error { case invalidNumber }
func parse(_ text: String) throws -> Int {
    guard let value = Int(text) else {
        throw InputError.invalidNumber
    }
    return value
}
do {
    let value = try parse("x")
    print(value)
} catch {
    print("输入错误", error) // 进入这里
}
print((try? parse("x")) as Any) // nil，舍弃错误原因
let result: Result<Int, InputError> = .failure(.invalidNumber)

func finish() {
    defer { print("最后") }
    defer { print("其次") }
    print("先执行")
}
finish() // 先执行 → 其次 → 最后

补充示例：用 switch 处理 Result，分别取出成功值或错误：

switch result {
case .success(let value):
    print("成功", value)
case .failure(let error):
    print("失败", error) // 失败 invalidNumber
}

进一步理解

try、try?、Result，应该根据什么选择？

parse("x") 无法得到整数，会抛出 invalidNumber。页面需要提示错误原因，就用 try 配合 do-catch；只需要判断是否成功，就用 try?，失败得到 nil。需要把结果交给回调、存进属性或稍后处理，可以用 Result 保存成功值或错误，再通过 switch 分别处理。try 只是标记可能抛错的调用，不会自己处理错误。

为什么把收尾代码写进 defer 更可靠？

函数打开文件后，可能在多个地方 return，也可能抛错。把关闭文件写进 defer，就不用在每个出口重复写关闭操作。程序执行到 defer 时先记下这段代码，离开当前代码块时再执行。多个 defer 后写的先执行；如果提前返回、没有执行到某个 defer，那一段就不会被记下，也不会执行。

为什么 try! 的失败不能交给 catch？

写 try! 就是告诉 Swift：“这次调用一定不会抛错。”实际抛错时，Swift 直接让程序崩溃，不会把错误交给外层 catch。网络失败、用户输入错误都可能正常发生，应让调用方处理，不能用 try! 假定成功。程序崩溃时，也不能指望 defer 一定执行。

别答错：不要用 try! 处理网络失败、用户输入等正常业务失败。

19. 泛型、Any、some、any 分别解决什么问题？

基础优先

回答总结

这几个写法主要区别在于谁决定具体类型，以及调用方知道多少。 泛型由调用方确定具体类型，可以用约束规定这个类型必须支持的操作，也能保留参数和返回值之间的类型关系。

返回值上的 some 由函数的实现方选择具体类型。普通函数的各个返回分支用同一种底层类型，调用方按声明里的协议来使用它。参数上的 some 是泛型参数的简写，具体类型由调用方决定。

any 协议类型可以装入不同具体类型的值，只要它们都遵循该协议，拿到值后就能通过协议接口来用。Any 可以装任意类型的值，需要使用具体类型的成员时，通常要先做类型转换。

代码示例（看注释与结果）

func identity<T>(_ value: T) -> T { value }
let number = identity(3) // 返回仍是 Int，不需要 as?
print(number + 1)        // 4

protocol Named { var name: String { get } }
struct User: Named { var name: String }
struct Book: Named { var name: String }
func make() -> some Named {
    User(name: "小明") // 这个函数始终返回 User
}
print(make().name)
var current: any Named = User(name: "小明")
current = Book(name: "Swift") // current 可以先保存 User，再改为保存 Book
print(current.name)           // Swift

func same<T: Equatable>(_ a: T, _ b: T) -> Bool {
    a == b // T 必须遵循 Equatable，因此可以使用 ==
}
print(same(1, 1)) // true；不能传 1 和 "1"

补充示例：Any 的类型转换与 some 参数。

let anything: Any = User(name: "小明")
if let user = anything as? User {
    print(user.name) // 小明：转换为 User 后，可以使用 User 的属性和方法
}
func showName(_ value: some Named) { // 类似 <T: Named>(_ value: T)
    print(value.name)
}
showName(User(name: "小明"))
showName(Book(name: "Swift")) // 参数类型由调用者选择

进一步理解

既然 Any 能装任何值，为什么还需要泛型？

identity 如果接收 Any、也返回 Any，调用方传入 3，拿回结果后还要转回 Int 才能做加法。改成 identity<T>(_: T) -> T，编译器就知道返回值与传入值类型相同。T: Equatable 表示 T 必须支持 ==，函数才能比较两个 T；where 也可以用来写这类要求。

some Named 与 any Named，谁决定里面的具体类型？

make() 声明返回 some Named，表示具体返回哪种类型由函数内部决定，且每次只能固定返回同一种（这里是 User）——同一个函数里不能在另一条分支改为返回 Book，调用方只需要知道结果有 Named 规定的 name。而 any Named 变量相当于动态容器，可以先保存 User，之后再改成 Book；[any Named] 数组也可以同时混装这两种值。

为什么隐藏类型后，不能直接使用所有专有成员？

Named 只规定 name，即使 User 还有 age，拿到 any Named 的代码也不能直接读 age，因为里面可能是 Book。要读 User 专有的属性，先用 as? User 尝试转换。some Named 同样只公开 Named 的接口，调用方不能因为知道函数内部用了 User，就直接访问 User 的其他成员。

别答错：返回位置的 some 由函数实现决定具体类型；参数位置的 some 由调用方决定具体类型。

进阶补充：any 与泛型约束

same<T: Equatable>(_: T, _: T) 中两个参数都是 T，所以调用方不能把 Int 和 String 一起传入。两个 any Equatable 变量却可能一个保存 Int、一个保存 String，不能直接用 == 比较。函数需要两个参数类型相同时，用泛型把这个要求写出来。

20. Codable 怎么把 JSON 转成模型？自动合成有什么坑？

基础优先

回答总结

读入 JSON 时，用 JSONDecoder 把数据解码成模型，模型要遵循 Decodable。 写出 JSON 时，用 JSONEncoder，模型要遵循 Encodable。Codable 是这两个协议的组合。

参与转换的属性类型满足相应要求时，编译器通常可以自动生成实现。用 CodingKeys 可以指定哪些属性参与转换，也可以指定属性对应的 JSON 字段名。

自动解码时，字段缺失或值为 null，可选属性会得到 nil，必需的非可选属性会解码失败。字段值的类型不对，即使属性是可选的，也会失败。

参与自动解码的 var 写了初值，缺字段时依然按解码规则处理。希望缺字段或遇到 null 时用默认值，就自己写 init(from:)，用 decodeIfPresent 读取，再用 ?? 补上默认值。

代码示例（看注释与结果）

import Foundation
struct User: Codable {
    let id: Int
    let name: String
    let nickname: String?
    enum CodingKeys: String, CodingKey {
        case id, nickname
        case name = "display_name" // Swift 属性名 ↔ JSON 字段名
    }
}
let data = Data(#"{"id":1,"display_name":"小明"}"#.utf8)
do {
    let user = try JSONDecoder().decode(User.self, from: data)
    print(user.name) // 小明
    print(user.nickname as Any) // nil：可选字段缺失
    let encoded = try JSONEncoder().encode(user)
    print(String(decoding: encoded, as: UTF8.self))
} catch {
    print("编解码失败", error) // 类型不匹配等错误进入这里
}

补充示例：Settings 自行实现解码，在缺字段或 null 时使用默认值 3：

struct Settings: Decodable {
    var retries: Int
    enum CodingKeys: String, CodingKey { case retries }
    init(from decoder: any Decoder) throws {
        let container = try decoder.container(keyedBy: CodingKeys.self)
        retries = try container.decodeIfPresent(Int.self, forKey: .retries) ?? 3
    }
}
for json in [#"{}"#, #"{"retries":null}"#, #"{"retries":"bad"}"#] {
    do {
        let value = try JSONDecoder().decode(Settings.self, from: Data(json.utf8))
        print(value.retries) // 缺键、null：都输出 3
    } catch {
        print("类型不匹配，仍然失败") // 字符串 "bad" 不能解为 Int
    }
}

别答错：可选属性允许字段缺失或为 null，但字段类型不对时，解码仍会失败。

进阶补充：属性初值与类继承

已有初值的 let 属性不能再次赋值，编译器自动生成的解码代码会保留这个初值。有默认值、又没有列进 CodingKeys 的属性，也可以保留默认值；这与需要从 JSON 读取的 var 属性不同。另外，子类直接继承父类的 Codable 编解码实现时，继承的实现只处理父类中参与编解码的属性，不会自动处理子类新增的属性；子类新增属性的编解码逻辑需要自行编写。
