1. struct、class、enum 有什么区别？什么时候用？

基础优先

面试总结（核心回答＋追问展开）

核心回答：struct 和 enum 是值类型，class 是引用类型。值类型赋值或传参后，修改一份值本身不会改变另一份；类的多个引用可以指向同一实例，因此能观察到共享状态的变化。独立的数据模型优先用 struct，需要对象身份、共享状态或继承时用 class，互斥状态及其附带数据用 enum。三者都可以遵循协议。

追问展开：值语义不等于深复制，也不规定一定存放在栈上：Array 可以共享缓冲区并在写入时分离；struct 中保存的类引用仍可指向同一对象。值类型方法修改自身属性、重新赋值 self，或切换枚举 case 时，需要 mutating；只修改所引用对象的内部状态则不需要。枚举原始值是声明时确定的固定值，关联值是创建枚举值时携带的数据。这里先讨论默认可拷贝的类型；进阶的 ~Copyable 表示取消默认可拷贝能力，这类值类型也能声明 deinit（销毁时执行的清理代码，见第 5 题），因此不能用有无 deinit 判断值类型或引用类型。

代码示例（看注释与结果）

struct Profile { var name: String }
var a = Profile(name: "小明")
var b = a
b.name = "小红"
print(a.name) // 小明：修改 b 不影响 a

class Account { var balance = 0 }
let x = Account()
let y = x
// let 固定的是引用，仍可修改对象的 var 属性
y.balance = 100
print(x.balance) // 100：x 和 y 指向同一对象
print(x === y)   // true：比较是不是同一实例

enum State {
    case loading
    case success(String) // 关联值：本次成功附带的数据
    case failure(Int)
}
let state = State.success("加载成功")

补充示例：mutating 是写在值类型方法前面的关键字，允许方法修改自身。原始值与关联值也用两个枚举对照：

extension Profile {
    mutating func rename(to newName: String) {
        name = newName // 修改结构体自身保存的属性
    }
}
b.rename(to: "小刚")
print(a.name, b.name) // 小明 小刚

enum HTTPStatus: Int {
    case ok = 200 // 原始值：声明时确定
}
print(HTTPStatus.ok.rawValue) // 200
// 前面的 State.success("加载成功") 是关联值：创建值时传入字符串

2. Optional 是什么？if let、guard let、?? 和类型转换怎么用？

基础优先

面试总结（核心回答＋追问展开）

核心回答：Optional 用类型明确表达“值可能不存在”，T? 就是 Optional<T>，它有 .some(value) 和 .none 两种情况，nil 表示后者，空字符串仍然是有值。解包就是确认有值再取出：if let 适合分支内使用；guard let 适合先排除失败情况，失败分支必须退出当前作用域，成功后绑定值可在后续使用。?? 提供默认值，?. 在有值时继续访问，否则返回 nil。

追问展开：类型检查用 is，结果是 Bool；as 用于编译期可以确认的转换，as? 尝试转换并返回可选结果，通常配合 if let 使用。! 强制解包和 as! 强制转换都要求开发者保证成功，失败会触发运行时错误，不能靠 do-catch 恢复。因此，面对可能缺失的数据和不确定的运行时类型，应先安全解包或尝试转换。

代码示例（看注释与结果）

let nickname: String? = nil
print(nickname ?? "游客")       // 游客
print(nickname?.count as Any) // nil：不会访问不存在的字符串

func greet(_ input: String?) {
    guard let name = input else {
        print("没有名字")
        return // guard 失败必须离开当前作用域
    }
    print(name) // name 已经是 String，可以直接使用
}
greet("小明")

let value: Any = "Swift"
if let text = value as? String { // 转换失败得到 nil
    print(text.count) // 5
}
print(value is String) // true，只检查类型
// nickname!          // 若执行会崩溃，do-catch 也救不了

别答错：guard let 绑定的变量可在后续作用域中使用；if let 绑定的变量通常只在对应分支中使用。

3. 存储属性、计算属性、lazy、static 和 class 怎么区分？

基础优先

面试总结（核心回答＋追问展开）

核心回答：存储属性保存状态，计算属性通过 getter（读取时执行的代码）和可选 setter（赋值时执行的代码）提供访问，本身不额外保存结果。lazy 是第一次访问才初始化的实例存储属性，必须声明为 var。static 声明类型成员，也就是通过 Meter.unit 这样的类型名访问的成员，在类中可以继承但不能重写；class 只用于类的类型方法和计算类型属性，允许子类重写，不能声明类型存储属性。

追问展开：willSet 和 didSet 是属性观察器，也就是赋值前后自动执行的回调。willSet 在写入前调用，属性仍是旧值，newValue 是即将写入的值；didSet 在写入后调用，oldValue 保存旧值。初始化器直接为本类型定义的存储属性设置初值时不触发观察器，不能扩大为初始化期间所有赋值都不触发。扩展不能添加实例存储属性，可以添加计算属性和方法，也可在类型及泛型限制允许时添加 static 存储属性。实例 lazy 不保证并发首次访问只初始化一次；存储型类型属性延迟初始化且只初始化一次，但之后的共享可变状态仍需同步。

代码示例（看注释与结果）

struct Meter {
    var value = 1 {
        didSet { print("旧值", oldValue, "新值", value) }
    }
    var doubled: Int { value * 2 } // 计算属性，不单独保存结果
    lazy var history = [0, 1]      // 第一次访问才初始化，必须是 var
    static let unit = "米"         // 类型属性：Meter.unit
}
var meter = Meter()
meter.value = 3         // 旧值 1 新值 3
print(meter.doubled)    // 6
print(meter.history)    // [0, 1]
print(Meter.unit)       // 米

class Vehicle {
    static func category() -> String { "车辆" }
    class func name() -> String { "普通车" }
}
class Car: Vehicle {
    override class func name() -> String { "汽车" }
}
print(Car.name())       // 汽车
print(Car.category())   // 车辆：static 可以继承，但不能重写

补充示例：前面的 doubled 只有 getter，省略了 get { }。这里补上可读写计算属性与 willSet：

struct Temperature {
    var celsius = 0.0 {
        willSet { print("准备写入", newValue) }
        didSet { print("原来是", oldValue) }
    }
    var fahrenheit: Double {
        get { celsius * 1.8 + 32 }
        set { celsius = (newValue - 32) / 1.8 } // 改的是 celsius
    }
}
var temperature = Temperature()
temperature.fahrenheit = 212 // 准备写入 100.0；原来是 0.0
print(temperature.celsius)   // 100.0

别答错：lazy 不保证并发首次访问只初始化一次；static let 的一次初始化也不意味着它引用的可变对象自动线程安全。

4. Swift 初始化器有哪些？两阶段初始化是什么？

基础优先

面试总结（核心回答＋追问展开）

核心回答：类的指定初始化器负责建立本类实例状态：先让本类新增的存储属性都有初值，再调用父类指定初始化器。便利初始化器通过 self.init 委托本类其他初始化器，最终到达本类指定初始化器。两阶段初始化先沿继承链自下而上完成属性初始化，再自上而下定制实例，目的是防止使用尚未完整建立的对象。

追问展开：第一阶段允许按规则写入初值，但结束前不能调用实例方法、读取实例属性或把 self 当成完整实例传出；修改继承属性则要等父类初始化返回。init? 用 nil 表示构造失败，throws 可携带具体失败原因，两者可以组合。required 是写在类的 init 前面的 Swift 关键字，表示“子类也必须支持用这一组参数创建对象”。例如父类声明 required init(name: String)，子类就必须支持 Child(name: "小明")。子类若能自动继承该初始化器，就不用重写；不能继承时，必须自己实现，并继续标 required。它是对子类的约束，不是额外调用步骤，下面有独立示例。结构体没有类继承，不使用 convenience 和 required。

代码示例（看注释与结果）

class Vehicle {
    var name: String
    init(name: String) { self.name = name } // 指定初始化器
    convenience init() {
        self.init(name: "默认车") // 便利入口复用指定入口
    }
}
class Car: Vehicle {
    var seats: Int
    init(name: String, seats: Int) {
        self.seats = seats      // ① 本类属性先有初值
        super.init(name: name)  // ② 父类完成自己的初始化
        print(self.name)       // ③ 完整 self 现在可用于读取和调用
    }
}
let car = Car(name: "小车", seats: 4)

struct Age {
    let value: Int
    init?(_ value: Int) {
        guard value >= 0 else { return nil } // 合法失败
        self.value = value
    }
}
print(Age(-1) as Any) // nil

补充：required 从哪里来？它不是上面 Vehicle 示例中已有的内容，而是另一条初始化语法：开发者把 required 写在父类的 init 前面，就要求子类也提供相同参数的创建方式。这里的“初始化入口”就是“可以怎样传参来创建对象”。看下面两个子类，一个直接继承，一个自己实现。

class Device {
    let name: String
    required init(name: String) { // 父类规定：所有子类都要支持这个创建方式
        self.name = name
    }
}

// 情况一：没有新增存储属性，也没有自己定义初始化器，自动继承
class BasicDevice: Device {}
let basic = BasicDevice(name: "基础设备") // 不必再写一份 init(name:)

// 情况二：自己定义了指定初始化器，不能再自动继承父类指定初始化器
class Phone: Device {
    let storage: Int
    init(name: String, storage: Int) {
        self.storage = storage
        super.init(name: name)
    }
    required init(name: String) { // 必须补上父类要求的创建方式；这里不写 override
        self.storage = 128       // 子类决定该方式下自己的属性如何初始化
        super.init(name: name)
    }
}
let phone = Phone(name: "手机") // 使用 required init(name:)，容量为 128
print(phone.name, phone.storage) // 手机 128

“可按规则继承”在这里具体指：子类没有自己定义指定初始化器，且新增存储属性都有默认值（或没有新增存储属性）时，会自动继承父类指定初始化器。BasicDevice 满足这个条件；Phone 自己定义了指定初始化器，因此需要补写 required init(name:)。required 可以修饰指定初始化器，也可以修饰便利初始化器；它表达的是对子类的要求。

5. ARC 怎么工作？weak、unowned 和循环引用怎么处理？

基础优先

面试总结（核心回答＋追问展开）

核心回答：ARC 是自动引用计数（Automatic Reference Counting），由编译器插入、运行时执行保留和释放等所有权操作，管理类实例的生命周期；没有强引用继续保活时，实例可以被销毁，它不是定时扫描的垃圾回收。weak 和 unowned 都不增加强引用计数：weak 必须是可选 var，目标释放后自动变成 nil；普通安全的 unowned 不自动清零，释放后经它访问会触发运行时错误，只适合能保证每次访问时目标仍存活的关系。

追问展开：循环引用的关键是内部强连接形成了环，清空外部变量仍不能释放，需要把其中一条关系改为弱引用，或在合适时机主动断开。常见例子是对象保存闭包、闭包又强捕获对象，以及拥有者与 delegate 相互持有；delegate（代理）是替另一个对象处理回调的对象；声明 weak var delegate 时，其协议要继承 AnyObject，表示只有类能遵循，这样才能使用弱引用。并非所有闭包都要 weak self，应先判断所有权关系；写 self 并不会弱捕获，guard let self 是把可选的弱引用 self 解包成当前使用的强引用，会在后续使用期间保活对象，跨长时间 await 也可能延长生命周期。unowned 可以是可选类型，但不会自动置 nil。

代码示例（看注释与结果）

final class Page {
    var onTap: (() -> Void)?
    func bind() {
        onTap = { [weak self] in // 闭包不再强持有 Page
            self?.refresh()     // Page 已释放就不调用
        }
        // onTap = { self.refresh() } // 若一直保存，会形成强引用环
    }
    func refresh() { print("刷新") }
    deinit { print("Page 释放") }
}
func demo() {
    var page: Page? = Page()
    weak var observer = page
    page?.bind()
    page?.onTap?() // 刷新
    page = nil    // 本例失去最后一条强引用，打印 Page 释放
    print(observer as Any) // nil：弱引用自动清空
}
demo()

补充示例：unowned 适合“每次访问时都能保证对方还活着”的关系；AnyObject 则是 weak 代理的类约束：

protocol RefreshDelegate: AnyObject {
    func didRefresh()
}
final class Loader {
    weak var delegate: (any RefreshDelegate)? // 不强持有代理
}

final class Owner {
    var card: Card?
}
final class Card {
    unowned let owner: Owner // 卡不负责让主人活着
    init(owner: Owner) { self.owner = owner }
}
func showCardOwner() {
    let owner = Owner()
    owner.card = Card(owner: owner)
    print(owner.card!.owner === owner) // true：此时 owner 仍然活着
    // 不要把 card 留到 owner 销毁之后再经它访问 owner
}

别答错：写 self.refresh() 不会自动弱捕获。guard let self 会在这次使用期间建立强引用；长时间 await 也可能延长对象存活。

6. 闭包如何捕获变量？@escaping、@autoclosure 有什么用？

基础优先

面试总结（核心回答＋追问展开）

核心回答：闭包可以捕获定义作用域中的值和变量，并带着捕获上下文一起使用。示例默认捕获可变局部变量 count 时，两个访问共享同一变量，所以能看到后续修改；[count] 则保存闭包创建时的值。若捕获的是类引用，保存的仍是引用，不会深复制对象。需要调整引用所有权时，使用 [weak self] 或满足生命周期约束的 [unowned self]。

追问展开：“逃逸”是指闭包被保存或返回，可能活到接收它的函数返回之后。直接写成 () -> Void 这类函数类型的参数默认非逃逸，只在本次调用有效期间使用；@escaping 允许保存、返回闭包并在函数返回后调用，但不代表一定晚执行，也不改变捕获强弱。可选闭包参数不受这一默认非逃逸限制，不额外标 @escaping。闭包是引用类型，可变局部变量可通过共享上下文保存；inout 允许函数在调用期间修改调用者传入的变量，调用时用 & 标记；逃逸闭包可能活得更久，不能直接捕获这个临时修改权限。只需要读取当时的值时，可显式捕获一个快照。@autoclosure 把表达式自动包装成无参闭包以延迟求值，是否调用、调用几次由函数实现决定，它与 @escaping 都不表示自动异步。

代码示例（看注释与结果）

func demoCapture() {
    var count = 1
    let readLive = { count }           // 捕获同一个可变局部变量
    let readSnapshot = { [count] in count } // 保存当前 Int 的值
    count = 2
    print(readLive())     // 2
    print(readSnapshot()) // 1
}
demoCapture()

func save(_ action: @escaping () -> Void) -> () -> Void {
    action // 允许返回，让调用者以后执行
}
let action = save { print("执行") }
action()

func log(_ enabled: Bool, _ text: @autoclosure () -> String) {
    if enabled { print(text()) } // 到这里才对表达式求值
}
log(false, String(1 + 2)) // 不调用 text，表达式不求值

补充示例：& 表示这次调用允许修改变量；[value] 保存当时的值，不会把 inout 的修改权限带出函数：

func increase(_ value: inout Int) {
    value += 1
}
var total = 1
increase(&total)
print(total) // 2

func snapshotReader(_ value: inout Int) -> () -> Int {
    // return { value } // 错误：返回的逃逸闭包不能直接捕获 inout
    return { [value] in value } // 只带走当时的 Int 值
}
let readTotal = snapshotReader(&total)
total = 9
print(readTotal()) // 2

别答错：@autoclosure 不保证只调用一次；调用次数由函数实现决定。

7. Array 是值类型，为什么复制不一定很贵？COW 是什么？

基础优先

面试总结（核心回答＋追问展开）

核心回答：Array 是值类型，但赋值不一定立即复制全部元素，因为标准库使用 COW，也就是写时复制。两份数组值可以先共享元素缓冲区（实际存放元素的一块存储）；写入时，若存储仍被共享就先分离再修改，独占时通常可以直接修改，扩容仍可能重新分配。这样既保留数组值的独立性，也减少无须修改时的复制开销。

追问展开：COW 不会深复制类元素：两份数组里的引用仍可能指向同一对象，修改该对象的属性会被双方看到。自定义 struct 也不会自动让整份值延迟复制，各属性遵守各自类型的复制规则；自己用类封装共享存储时，需在修改入口检查独占性并分离，例如使用 isKnownUniquelyReferenced：它返回 Bool，判断是否已知只有一个强引用持有该存储对象；若不能确认独占，就先复制出自己的存储。这里的“分离”指复制共享存储后，让当前值改用新存储。独占性检查不是线程同步工具，COW 也不允许无同步地并发修改同一个数组变量。String 的短字符串还可能内联存储，不能把所有值类型都想成只保存一个地址。

代码示例（看注释与结果）

var b = a       // 可以先共享底层元素存储
b.append(4)     // 修改 b，确保它有可独立修改的存储
print(a)        // [1, 2, 3]
print(b)        // [1, 2, 3, 4]

let second = first
second[0].name = "新" // 改的是元素引用指向的对象

8. map、compactMap、flatMap 有什么区别？

基础优先

面试总结（核心回答＋追问展开）

核心回答：对数组等序列，map 对每个元素做转换并保留每个转换结果；compactMap 转换后去掉 nil，并解包保留下来的值；flatMap 则把每个元素转换成序列，再拼接一层。比如把 ["1", "x", "3"] 转成整数，map 得到 [Int?]，保留转换失败的 nil；compactMap 得到 [1, 3]；把 [[1, 2], [3]] 用 flatMap 展开，得到 [1, 2, 3]。

追问展开：Optional 也有 map 和 flatMap：有值才执行转换，没值直接返回 nil。map 会把转换结果再包装一层，如果转换本身返回 Optional，就可能得到双层可选值；flatMap 接收返回 Optional 的转换，避免额外嵌套。以 String? 的 "x" 转 Int 为例，map 可得到 .some(nil)，flatMap 得到 nil。回答时先区分接收者是序列还是 Optional，不能把所有 flatMap 都解释成“过滤 nil”。$0 只是闭包第一个参数的简写。

代码示例（看注释与结果）

let input = ["1", "x", "3"]
let a = input.map { Int($0) }        // [Int?]
let b = input.compactMap { Int($0) } // [Int]
print(a) // [Optional(1), nil, Optional(3)]
print(b) // [1, 3]

let groups = [[1, 2], [3]]
print(groups.flatMap { $0 }) // [1, 2, 3]：拼接一层

let text: String? = "x"
let nested: Int?? = text.map { Int($0) } // some(nil)
let single: Int? = text.flatMap { Int($0) } // nil，无额外外层

9. throws、try?、try!、Result 和 defer 怎么用？

基础优先

面试总结（核心回答＋追问展开）

核心回答：throws 声明函数可能抛出错误，throw 真正抛出错误，try 标记可能抛错的调用，本身不处理错误。调用方可以 do-catch 捕获，也可以继续向外抛。try? 把失败转换为 nil 并丢弃错误原因；try! 假定不会抛错，实际抛错时触发运行时错误。Result 用 success 和 failure 把成功值或错误保存为一个值，适合返回、存储或传递处理结果。

追问展开：defer 适合资源释放等收尾：执行到声明处才注册，在之后正常结束、return 或 throw 离开当前作用域时执行，同一作用域按注册的逆序执行。崩溃时不能依赖 defer 清理；强制解包失败、try! 失败和 fatalError 也不能用 do-catch 恢复。业务上可预期的失败应走错误处理，不能用 try! 代替。Swift 6 的 throws(InputError) 读作“这个函数只抛出 InputError 类型的错误”，称为类型化 throws；本题 parse 使用的是普通 throws，不限定具体错误类型。

代码示例（看注释与结果）

enum InputError: Error { case invalidNumber }
func parse(_ text: String) throws -> Int {
    guard let value = Int(text) else {
        throw InputError.invalidNumber
    }
    return value
}
do {
    let value = try parse("x")
    print(value)
} catch {
    print("输入错误", error) // 进入这里
}
print((try? parse("x")) as Any) // nil，舍弃错误原因
let result: Result<Int, InputError> = .failure(.invalidNumber)

func finish() {
    defer { print("最后") }
    defer { print("其次") }
    print("先执行")
}
finish() // 先执行 → 其次 → 最后

补充示例：前面创建的 result 还没有被使用。用 switch 取出成功值或错误，才能看到“把结果存成值”的意义：

switch result {
case .success(let value):
    print("成功", value)
case .failure(let error):
    print("失败", error) // 失败 invalidNumber
}

func parseTyped(_ text: String) throws(InputError) -> Int {
    guard let value = Int(text) else { throw .invalidNumber }
    return value
}
print((try? parseTyped("3")) as Any) // Optional(3)

10. 泛型、Any、some、any 分别解决什么问题？

基础优先

面试总结（核心回答＋追问展开）

核心回答：泛型中的 T 是类型占位符，调用时由实参确定；例如 identity<T> 输入 Int 就返回 Int，输入 String 就返回 String，从而复用代码并保留类型关系。T: Equatable 表示 T 必须支持相等比较，where 可以补充更多限制。Any 可以装任意类型，但要先转换才能使用具体类型的专有接口。any P 表示“装着某个遵循协议 P 的值”，同一变量可以换装另一种遵循者。返回位置的 some P 则由函数实现决定具体类型，对外只展示协议能力，并保留这个隐藏类型的身份；参数位置的 some P 是泛型参数简写，由调用者选择类型。

追问展开：普通非泛型函数返回 some P 时，各返回路径必须对应同一底层类型；泛型函数的隐藏返回类型可以依赖泛型参数，对同一组实参保持一致。any P 隐藏的是调用处能直接使用的具体类型信息，并没有抹掉值的运行时类型。进阶边界：容器里的值遵循 P，不代表 any P 这个容器类型本身自动遵循 P；有些泛型调用会临时取出其中的具体类型来匹配参数，这叫“隐式打开存在值”。协议里用 Self 表示遵循类型自身，用 associatedtype 声明由遵循者确定的类型（见第 13 题），相关成员能否通过 any 调用仍受类型关系限制。存在容器见第 17 题；泛型专门化是编译器针对具体类型生成或优化代码，不能仅凭 some/any 关键字断言性能。

代码示例（看注释与结果）

func identity<T>(_ value: T) -> T { value }
let number = identity(3) // 返回仍是 Int，不需要 as?
print(number + 1)        // 4

protocol Named { var name: String { get } }
struct User: Named { var name: String }
struct Book: Named { var name: String }
func make() -> some Named {
    User(name: "小明") // 此普通函数底层始终返回 User
}
print(make().name)
var current: any Named = User(name: "小明")
current = Book(name: "Swift") // 同一变量可换成另一种遵循者
print(current.name)           // Swift

func same<T: Equatable>(_ a: T, _ b: T) -> Bool {
    a == b // 约束保证 T 支持相等比较
}
print(same(1, 1)) // true；不能传 1 和 "1"

补充示例：把 Any、参数位置的 some，以及 where 放回实际调用中看：

let anything: Any = User(name: "小明")
if let user = anything as? User {
    print(user.name) // 小明：转换后才能使用 User 的接口
}
func showName(_ value: some Named) { // 类似 <T: Named>(_ value: T)
    print(value.name)
}
showName(User(name: "小明"))
showName(Book(name: "Swift")) // 参数类型由调用者选择

func sameWithWhere<T>(_ a: T, _ b: T) -> Bool where T: Equatable {
    a == b // 与前面的 T: Equatable 表达相同约束
}
print(sameWithWhere(1, 1)) // true

别答错：some 的返回类型由实现决定，some 参数的类型由调用者决定；any 可保存不同遵循者，但不保证协议里的每一种类型关系都能通过它使用。

11. 为什么说 Swift 支持面向协议编程（POP）？

重点理解

面试总结（核心回答＋追问展开）

核心回答：Swift 的面向协议编程，是用协议描述能力、用协议扩展复用默认行为，再通过泛型约束或 any 协议类型组织调用。类、结构体和枚举都可以遵循协议，因此不必依赖共同父类，也能组合能力和替换实现。本题 show 只依赖 Named 约定的 name 和 greeting()，所以既能接收 User，也能接收 Robot，不需要分别写两套 show。协议描述要求，不直接为实例保存字段。

追问展开：协议要求就是写在 protocol 花括号里、遵循者必须满足的属性和方法；默认实现就是扩展提供的后备代码，遵循者没有自己实现时可复用。协议扩展也能添加未列入要求的辅助方法；需要通过协议接口根据遵循类型选择实现的方法，必须列入协议要求。编译器若保留一份通用的泛型函数代码，可通过“协议见证表”这份实现对照表找到具体方法；若针对具体类型优化，也可能直接调用目标方法（见第 16、17 题），所以 POP 不等于所有调用都动态查表。它是一种组织依赖和复用行为的设计方式，可以与类继承、面向对象及函数式写法结合使用。

代码示例（看注释与结果）

protocol Named {
    var name: String { get }
    func greeting() -> String // 放入协议要求，支持不同实现
}
extension Named {
    func greeting() -> String { "你好，\(name)" } // 默认实现
}
struct User: Named { var name: String }
struct Robot: Named {
    var name: String
    func greeting() -> String { "编号：\(name)" }
}
func show<T: Named>(_ value: T) {
    print(value.greeting()) // 依赖能力，不依赖 User 或 Robot
}
show(User(name: "小明"))  // 你好，小明
show(Robot(name: "R1")) // 编号：R1

图示说明

别答错：协议扩展不是给所有同名方法提供动态重写；需要多态调用的方法应列入协议要求，见下一题。

12. 协议扩展的方法为什么有时调用不到自己的实现？

重点理解

面试总结（核心回答＋追问展开）

核心回答：关键要看同名方法是否属于协议要求，也就是是否写在 protocol 的声明中。属于协议要求时，具体类型建立遵循关系，编译器记录“这个要求由哪个方法实现”，称为协议见证；any P 或泛型约束下的调用使用这份记录；只在扩展里新增的方法没有这个要求入口，在协议视角下按编译期可见的静态类型（变量声明或推断出的类型）和约束选择，而不是再去搜索实际对象的同名方法。因此示例中 value.hello() 调用 Person 的实现，value.bye() 调用扩展实现；直接用 Person 调用 bye() 才会选择 Person 的同名方法。

追问展开：想要通过协议接口多态调用，就把方法声明在协议中，扩展里仍可保留默认实现。不能因此说“扩展默认实现总会覆盖遵循者”。类继承还有一个边界：父类若直接使用协议扩展默认实现来建立遵循，子类只是新增同名方法，不会自动替换父类的协议见证。需要 override 行为时，应先让父类提供可重写的方法来满足协议要求，子类再重写该方法。

代码示例（看注释与结果）

protocol Greeter { func hello() -> String }
extension Greeter {
    func hello() -> String { "默认 hello" }
    func bye() -> String { "默认 bye" } // 不是协议要求
}
struct Person: Greeter {
    func hello() -> String { "自己的 hello" }
    func bye() -> String { "自己的 bye" }
}
let person = Person()
let value: any Greeter = person
print(person.bye())  // 自己的 bye：静态类型是 Person
print(value.hello()) // 自己的 hello：协议要求走遵循关系
print(value.bye())   // 默认 bye：仅扩展成员

func sayBye<T: Greeter>(_ value: T) -> String { value.bye() }
print(sayBye(person)) // 默认 bye：调用点只知道 Greeter 约束

补充示例：“子类同名方法不会替换父类已选定的默认实现”，用前面同一个 Greeter 协议对比：

class DefaultGreeter: Greeter {} // hello 采用协议扩展的默认实现
class ChildGreeter: DefaultGreeter {
    func hello() -> String { "子类 hello" }
}
let child = ChildGreeter()
print(child.hello()) // 子类 hello：直接用子类类型调用
let asProtocol: any Greeter = child
print(asProtocol.hello()) // 默认 hello：仍沿父类建立的协议遵循调用

class BaseGreeter: Greeter {
    func hello() -> String { "父类 hello" } // 父类自己实现协议要求
}
class OverridingGreeter: BaseGreeter {
    override func hello() -> String { "重写 hello" }
}
let polymorphic: any Greeter = OverridingGreeter()
print(polymorphic.hello()) // 重写 hello：可以沿类方法的重写关系调用

别答错：协议要求有默认实现，并不意味着遵循者的实现一定被忽略；本例 hello 就会调用 Person 的实现。

13. Swift 协议和 Objective-C 协议有什么区别？

重点理解

面试总结（核心回答＋追问展开）

核心回答：Swift 原生协议可以由类、结构体和枚举遵循，支持关联类型（协议先声明一个类型名称，由遵循者确定具体类型）、泛型约束以及协议扩展默认实现；Objective-C 协议面向对象，支持 required（必须实现）和 optional（可以不实现）的协议要求。这里的 required 说的是 OC 协议要求，不是第 4 题 Swift 初始化器前的 required 修饰符；Swift 的 @objc 协议未标 optional 的要求默认必须实现。Swift 通过 @objc 声明可与 OC 互操作的协议，只能由类遵循；@objc 表示把声明暴露给 Objective-C，协议成员必须使用 Objective-C 能表示的类型和签名，因此不能直接带入 Swift 关联类型等能力。

追问展开：默认实现与 optional 的区别在于：前者提供一份可执行的后备代码，后者允许对象根本不实现该方法，所以用 button.click?() 等方式检查方法是否存在后再调用。Swift 原生协议不能直接用 optional 修饰要求，Swift 协议扩展也不是 OC 协议的默认实现机制。原生协议要求的典型调用可经见证表，OC 协议的方法调用则走运行时消息查找。@objc 协议限制遵循者为类，不等于所有遵循者都必须直接继承 NSObject。

代码示例（看注释与结果）

import Foundation

protocol Drawable { func draw() }
extension Drawable {
    func draw() { print("默认绘制") } // 仍然是有实现的协议要求
}
struct Dot: Drawable {}
Dot().draw() // 默认绘制

@objc protocol Clickable: AnyObject {
    @objc optional func click() // 允许遵循者完全不提供方法
}
class Button: NSObject, Clickable {}
let button: any Clickable = Button()
button.click?() // 先检查方法是否存在；本例什么也不做

}

    typealias Item = Int // typealias 给已有类型起别名，这里明确 Item 就是 Int
    func load() -> Int { 42 }
}

// @objc 协议不能直接声明这样的 associatedtype

14. Codable 怎么把 JSON 转成模型？自动合成有什么坑？

基础优先

面试总结（核心回答＋追问展开）

核心回答：Codable 是 Encodable 与 Decodable 的组合，对这里的普通结构体，参与编码的属性满足 Encodable、参与解码的属性满足 Decodable 时，编译器可按规则自动生成相应方法，这就叫“自动合成”。JSONDecoder 把 JSON Data 解成模型，JSONEncoder 做反向转换；CodingKeys 指定字段选择和名称映射，Codable 本身也能配合其他格式的编码器使用。合成解码通常把可选字段缺失或 null 解为 nil，字段类型不匹配仍会抛错，可选并不代表忽略任意坏数据。

追问展开：默认值要区分情况：参与合成解码的 var 即使有初值，仍按字段类型解码，必填键缺失不会自动回退；已有初值的 let 不能再次赋值，合成解码会保留初值；未列入 CodingKeys 且有默认值的属性也可保留默认值。需要“缺失时用业务默认值”或特殊类型转换时，应自己编写 Decodable 要求的 init(from decoder:)：先取得按 CodingKeys 查找字段的容器，再读取每个字段；decodeIfPresent 配合 ?? 可处理缺键和 null，但类型不匹配仍会抛错。继承父类的 Codable 实现也不会让子类新增字段自动参与编解码。

代码示例（看注释与结果）

import Foundation
struct User: Codable {
    let id: Int
    let name: String
    let nickname: String?
    enum CodingKeys: String, CodingKey {
        case id, nickname
        case name = "display_name" // Swift 属性名 ↔ JSON 字段名
    }
}
let data = Data(#"{"id":1,"display_name":"小明"}"#.utf8)
do {
    let user = try JSONDecoder().decode(User.self, from: data)
    print(user.name) // 小明
    print(user.nickname as Any) // nil：可选字段缺失
    let encoded = try JSONEncoder().encode(user)
    print(String(decoding: encoded, as: UTF8.self))
} catch {
    print("编解码失败", error) // 类型不匹配等错误进入这里
}

补充示例：真正实现“缺字段或 null 时用默认值”，而不是只在属性上写初值。这个 Settings 只演示解码，所以使用 Decodable：

struct Settings: Decodable {
    var retries: Int
    enum CodingKeys: String, CodingKey { case retries }
    init(from decoder: any Decoder) throws {
        let container = try decoder.container(keyedBy: CodingKeys.self)
        retries = try container.decodeIfPresent(Int.self, forKey: .retries) ?? 3
    }
}
for json in [#"{}"#, #"{"retries":null}"#, #"{"retries":"bad"}"#] {
    do {
        let value = try JSONDecoder().decode(Settings.self, from: Data(json.utf8))
        print(value.retries) // 缺键、null：都输出 3
    } catch {

15. Swift 实例对象、类、元类的内部结构是什么？

进阶选学

面试总结（核心回答＋追问展开）

核心回答：以常见原生 Swift 堆对象为概念模型，实例包含对象头（运行时管理对象所需的信息）和实例存储属性；对象头关联类型元数据（描述这个对象是什么类型的信息）和引用计数状态。相同具体类的实例共享类元数据，其中保存大小、父类、字段布局和虚表（可重写方法的入口表，见第 16 题）等运行时信息，方法代码不会复制到每个实例中。对象头编码、属性在内存中的位置、对齐，以及引用计数旁表（某些管理信息使用的额外存储）受平台及运行时形式影响，示意图不能当作固定内存偏移表。

追问展开：在 Apple 的 Objective-C 互操作环境中，类元数据兼容 OC 类对象，类对象通过 isa（对象关联运行时类的关系，此处从类对象指向元类）关联 OC 元类；元类可理解为描述类对象的运行时类，OC 类方法信息属于它；Swift class func 仍要按自身派发规则判断，不能全部等同为 OC 消息。Person.Type 是可保存 Person 及其子类类型值的 Swift 元类型，Person.self 是一个类型值，这里的元类型是 Swift 类型系统概念，而 OC metaclass（元类）是 OC 运行时对象，两者是不同概念，也不是创建了额外的 Person 实例。MemoryLayout<Person>.size 测量的是引用表示大小，不是整个对象的堆分配大小。

16. Swift 方法调用如何实现？四种派发怎么区分？

重点理解

面试总结（核心回答＋追问展开）

核心回答：“派发”就是从一个方法调用确定最终执行哪一份实现。Swift 常见四种方法派发：静态派发在编译期确定目标；虚表派发根据对象实际类的方法表槽位（预先安排的表项）选择重写实现；协议见证表派发根据具体类型的协议遵循找到要求的实现；OC 消息派发根据接收者和 selector（运行时识别方法的名称标识）查找 IMP（该方法实现的函数指针）。判断时要同时看成员声明和调用视角：已知具体类型的值类型方法、final 方法（禁止子类重写）常可直接调用，可重写类方法通常走虚表，协议视角的要求调用通常经见证入口。

追问展开：虚表按槽位选择入口，不是每次按方法名搜索父类链；协议见证表对应“某个具体类型遵循某个协议”，仅扩展新增的方法没有协议要求入口。OC 消息派发通常先查缓存，再查本类和父类的方法，找不到还可能进入动态解析或转发；@objc 把方法暴露给 OC，dynamic 要求保留运行时动态派发；本例 @objc dynamic 在 OC 互操作下走消息派发，仅 @objc 或继承 NSObject 并不强制所有 Swift 调用都走消息。优化器若能证明最终目标，也可能省去虚表或见证表查询，直接调用方法，这称为“去虚化”，所以不能回答“struct 永远静态、class 永远虚表”，也不能把静态派发和 static 关键字等同。

代码示例（看注释与结果）

import Foundation
protocol Speaker { func speak() -> String }
class Animal {
    func sound() -> String { "Animal" }
}
class Dog: Animal, Speaker {
    override func sound() -> String { "Woof" }
    final func speak() -> String { "Hello" }
}
class Demo: NSObject {
    @objc dynamic func run() { print("Running") }
}
let dog = Dog()
print(dog.speak()) // final 已知目标，可直接调用
let animal: Animal = dog
print(animal.sound()) // Woof：典型虚表调用，找到 Dog 的重写
let speaker: any Speaker = dog
print(speaker.speak()) // 协议要求：典型见证表调用
Demo().run() // @objc dynamic：采用 Objective-C 动态派发

图示说明

别答错：不能说“struct 永远静态、class 永远虚表”：struct 经协议接口可走见证表，class 的 final 方法可直接调用。

17. Swift 协议内部是什么？见证表、存在容器怎么理解？

进阶选学

面试总结（核心回答＋追问展开）

核心回答：第 10 题的 any P 在运行时需要携带具体值、类型信息和调用所需的实现记录，这个组合称为“存在容器”。在此基础上区分四个角色：协议描述符记录协议身份和要求；协议见证表记录某个具体类型如何满足协议要求；类型元数据描述具体类型，并关联负责复制、销毁等值操作的值见证表；存在容器则承载 any P 的值和操作它所需的运行时信息。协议见证表解决“要求怎么实现”，值见证表解决“值怎么管理”，两者不能混用。

追问展开：ABI 是编译器与运行时对二进制布局和调用方式的约定；一个机器字在这里指一个指针大小，64 位环境通常为 8 字节。“非类限定”指协议没有通过 AnyObject 等约束只允许类遵循。普通非类限定存在值的典型 ABI 表示是三机器字的值缓冲区、具体类型元数据指针及所需协议见证表指针。值的大小和对齐（存储地址需满足的边界要求）合适时，直接放在容器自带的缓冲区里，称为内联；放不下则使用容器外的存储；在 64 位、一个普通方法协议的典型情况下共五个字，即 40 字节，但不能推广成所有 any 都固定 40 字节。类限定存在值（例如 P: AnyObject）可用“对象引用加所需见证表”的更紧凑表示，OC 协议、Error、标记协议（只标示性质、不提供普通方法要求的协议，例如 Sendable）等另有规则，不能照搬这个布局。保留通用实现、未针对具体类型优化的泛型，通常也使用元数据和见证表，却不要求先构造存在容器；布局知识用于解释成本，不用于业务代码手算偏移。

代码示例（看注释与结果）

protocol Speaker { func speak() -> String }
struct Dog: Speaker {
    var age: Int
    func speak() -> String { "Woof" }
}
struct BigSpeaker: Speaker {
    var a, b, c, d: Int // 示例：四个 Int，大于常见三字缓冲区
    func speak() -> String { "Big" }
}
let small: any Speaker = Dog(age: 1)
let large: any Speaker = BigSpeaker(a: 1, b: 2, c: 3, d: 4)
print(small.speak()) // Woof
print(large.speak()) // Big：调用方不必知道容器里的具体类型

func call<T: Speaker>(_ value: T) -> String { value.speak() }
print(call(Dog(age: 2))) // 泛型也可利用协议遵循；不要求先装进 any
print(MemoryLayout<any Speaker>.size) // 本例在 64 位 Apple 平台为 40：容器本身的大小，不包含外部存储

图示说明

别答错：不要为了使用协议去手算地址偏移；先掌握 any、泛型和调用行为，布局只作为进阶解释。

18. async/await 和 GCD 有什么区别？await 会阻塞线程吗？

重点理解

面试总结（核心回答＋追问展开）

核心回答：GCD 是 Grand Central Dispatch，也就是 DispatchQueue 这套队列调度 API；它用队列和代码块组织调度，async/await 用可挂起的异步函数表达任务中的执行流程，并与 throws、结构化并发、取消和 actor 隔离协作。任务是要完成的工作，线程是执行代码的资源，执行器负责安排任务在哪里执行。await 表示可能挂起：真正挂起时保存后续执行状态，让出执行资源，之后由执行器调度恢复，本身不会像信号量等待那样同步占住线程。它不保证一定挂起或切换线程，任务也不绑定某条固定线程。

追问展开：GCD 的 async 是提交工作后不等待完成，Swift 的 async 表示函数可以异步挂起，两者可以共存。异步函数里的同步重计算、同步 I/O、信号量等待仍会占用线程；Task {} 可能继承 MainActor，不能靠加 async 或 Task 就把重活搬走。执行位置需结合版本与设置：按 Swift 6.0/6.1 的通常规则，非 actor 隔离 async 在通用执行器运行；Swift 6.2 启用 NonisolatedNonsendingByDefault（改变非隔离异步函数默认执行隔离的编译选项）后，非隔离 async 默认遵循调用者隔离，@concurrent 可显式要求离开调用方 actor，但不保证固定后台线程。

代码示例（看注释与结果）

import Foundation
import Dispatch

// GCD：提交代码块，结果常通过回调传递
// @Sendable：闭包可能跨并发隔离使用，编译器会检查它捕获的值是否安全，见第 20 题
// 此处没有捕获外部可变状态；@Sendable 不表示这段闭包会自动异步执行
func gcdName(completion: @escaping @Sendable (String) -> Void) {
    DispatchQueue.global().async {
        completion("小明") // 这里的回调不保证在主线程
    }
}

// async/await：用返回值表达后续结果
func asyncName() async throws -> String {
    try await Task.sleep(for: .milliseconds(10)) // 模拟非阻塞等待
    return "小明"
}
func demo() async throws {
    let name = try await asyncName() // 当前任务可能挂起
    print(name) // 等调用返回后，继续执行
}
try await demo() // 单独 Swift 文件的顶层异步入口

别答错：不要在 Swift 并发任务里用信号量等待异步结果，这可能占住有限的工作线程。

19. async let、TaskGroup、Task 有什么区别？怎么取消？

重点理解

面试总结（核心回答＋追问展开）

核心回答：async let 适合数量固定的结构化子任务，TaskGroup 适合数量在运行时确定的子任务；父任务离开相应作用域前必须等待子任务结束，取消会沿结构化父子关系传播。Task {} 创建非结构化任务；返回的 handle 是任务句柄，也就是用来等待结果、请求取消的操作对象。这类任务生命周期不受创建作用域约束，也不会仅因创建者取消就自动取消，需要持有句柄并按业务主动管理。取消是协作式请求：用 Task.checkCancellation()、Task.isCancelled 或响应取消的 API 配合处理，cancel() 不等于任务已经结束。

追问展开：退出作用域的行为还要区分：未显式等待的 async let 会被取消并等待；普通任务组正常退出时等待剩余任务，不会仅因退出就取消，可用 cancelAll() 主动请求取消；使用 withThrowingTaskGroup 时，传入的任务组闭包（body）若以抛错方式退出，会取消并等待剩余任务；某个子任务抛错不等于所有兄弟任务立即自动取消，还取决于错误如何被取出和处理。Task {} 通常继承创建位置的 actor 隔离（在哪个 actor 的保护范围内执行）、优先级和任务局部值（沿任务调用链传递的上下文，例如追踪编号）；Task.detached 不继承该隔离和任务局部值，也不自动沿用当前优先级，但同样不保证新建线程。任务组结果通常按完成顺序取得，需要输入顺序时应携带索引并重排。

代码示例（看注释与结果）

func fetch(_ id: Int) async throws -> Int {
    try Task.checkCancellation() // 已取消则抛 CancellationError
    return id
}
func loadPair() async throws -> Int {
    async let a = fetch(1) // 固定数量的两个子任务
    async let b = fetch(2)
    let values = try await (a, b)
    return values.0 + values.1
}
func loadMany() async -> Int {
    await withTaskGroup(of: Int.self) { group in
        for id in 1...3 {
            group.addTask { id } // 动态数量；结果按完成顺序收集
        }
        var sum = 0
        for await value in group { sum += value }
        return sum
    }
}
func demo() async throws {
    print(try await loadPair()) // 3
    print(await loadMany())     // 6
    let handle = Task { try await fetch(4) } // 非结构化任务的句柄
    handle.cancel() // 请求取消；若已完成则不撤回结果
    _ = try? await handle.value // 等待它真正结束
}
try await demo()

补充示例：cancel() 发出请求，任务要主动检查才能响应。下面创建包含可取消等待的任务，随后立即请求取消；无论任务是否已经开始等待，都会在等待或检查处响应：

let cancellable = Task {
    do {
        try await Task.sleep(for: .seconds(10)) // 可响应取消的异步等待
        try Task.checkCancellation()           // 若已取消，抛 CancellationError
        print("工作完成")
    } catch is CancellationError {
        print("收到取消，结束任务")
    } catch {
        print("其他错误", error)
    }
}
cancellable.cancel()
await cancellable.value // 等它实际退出；本例输出“收到取消，结束任务”

20. actor、@MainActor、Sendable 各自解决什么问题？

重点理解

面试总结（核心回答＋追问展开）

核心回答：actor 是一种引用类型，可以把自己的可变状态保护起来，不允许外部任意并发读写；这种访问边界叫“隔离”，访问其隔离状态的代码串行执行；@MainActor 把声明隔离到全局主 actor，常用于 UI 状态，在 Apple UI 应用的常规环境中其执行器与主线程关联；Sendable 是一个协议，表示类型的值可以安全地跨隔离域（例如从一个 actor 传到另一个 actor）传递或共享。它们分别解决状态访问隔离、主 actor 隔离和值的跨域安全，Sendable 本身不会给对象自动加锁。

追问展开：“原子事务”在这里指检查到修改之间不被别的任务插入；actor 并不保证整个异步方法具备这一性质。await 真正挂起时，别的任务可以进入同一 actor 执行，这称为“重入”，其他任务可能修改状态，恢复后必须重新验证依赖条件，例如余额检查。普通 actor 不绑定专用线程，也不保证严格先进先出。同一隔离内调用同步方法无需 await，跨隔离调用通常需要；@MainActor 不能一概理解为主动调用任何同步函数都会自动跳线程，也不会移走同步重计算。结构体、枚举的相关成员需满足 Sendable 条件；普通非隔离类通常需 final、存储属性不可变且 Sendable 才能通过检查，全局 actor 类等另有规则，actor 自动满足 Sendable。@unchecked Sendable 的意思是“我自行保证线程安全，请跳过通常的遵循检查”，是开发者承担同步正确性的承诺，不能用来随意关闭检查。

代码示例（看注释与结果）

actor Counter {
    private var value = 0
    func increment() -> Int {
        value += 1 // 本段没有 await，检查与修改都在隔离内完成
        return value
    }
}
struct Snapshot: Sendable { let count: Int }

@MainActor
final class ScreenModel {
    private(set) var title = "0"
    func apply(_ snapshot: Snapshot) {
        title = String(snapshot.count) // 在主 actor 上更新 UI 状态
    }
}
func demo() async {
    let counter = Counter() // actor 是引用类型，赋值会共享同一实例
    let number = await counter.increment() // 跨 actor 可能需要等待调度
    let snapshot = Snapshot(count: number)
    let model = await ScreenModel()
    await model.apply(snapshot)
    print(await model.title) // 1
}
await demo()

补充示例：前面的 Counter.increment() 没有 await，所以不能展示重入。下面单独展示：等待授权期间余额可能变化，恢复后要再次检查。可传入会真正异步等待的授权函数：

actor Wallet {
    private var balance = 100
    func withdraw(
        _ amount: Int,
        authorize: @Sendable () async -> Bool
    ) async -> Bool {
        guard amount > 0, balance >= amount else { return false }
        guard await authorize() else { return false } // 可能挂起：其他提款可进入
        guard balance >= amount else { return false } // 恢复后重新验证
        balance -= amount // 重新检查到扣减之间没有 await
        return true
    }
}
// 若删掉第二次余额检查，两笔提款可能都通过第一次检查，最终把余额扣成负数。
// @Sendable 约束 authorize 的捕获安全，async 表示它可能异步挂起。

let wallet = Wallet()
async let firstWithdrawal = wallet.withdraw(80) {
    try? await Task.sleep(for: .milliseconds(10)) // 模拟等待授权结果
    return true
}
async let secondWithdrawal = wallet.withdraw(80) {
    try? await Task.sleep(for: .milliseconds(10))
    return true
}
let withdrawals = await (firstWithdrawal, secondWithdrawal)
print([withdrawals.0, withdrawals.1].filter { $0 }.count) // 1：余额只够一笔
// 哪一笔成功不保证；第二次检查确保不会两笔都扣款。
