一、类型与可选值

1. 类、结构体、枚举有什么差别？赋值之后谁和谁共享状态？

口述版

  • 类是引用类型。赋值复制的是引用，两个变量指向同一个实例，可以用 === 判断。可以继承，销毁时走 deinit。
  • 结构体、枚举是值类型。赋值之后各有一份存储，改其中一份，另一份不变。方法里修改自己的存储属性要 mutating。枚举表示一组互斥状态，不能继承。
  • 「各有一份」只到这一层。结构体的属性如果是类，复制走的是那个引用，两个结构体仍然共享同一个对象。
  • 默认用结构体。需要对象身份、继承，或者要在 deinit 里做销毁收尾，才用类。

解析

赋值或传参之后，改其中一个名字，另一个名字还能不能看见，取决于复制的是引用还是值。

类复制的是引用。var a = b 之后，两个变量指向同一个实例，改一边的属性，另一边看得到，也可以用 === 判断是不是同一个对象。类可以继承，也可以在 deinit 里做销毁时的收尾。

结构体和枚举复制的是值。赋值之后两边各有一份，改其中一份的存储属性，另一份不会变。方法里要修改自己这份属性，必须标 mutating。枚举用来表示一组互斥状态，不能继承，也没有一套可继承的存储属性布局。

「各有一份」指的是这一层。结构体的属性如果是类，复制走的是那个引用，两个结构体仍然共享同一个对象。

class Room { var name = "A" }
struct Note { var title = "A"; var room: Room }

let a = Room()
let b = a
b.name = "B"            // a.name 也是 "B"

var n1 = Note(title: "A", room: Room())
var n2 = n1
n2.title = "B"          // n1.title 仍是 "A"
n2.room.name = "B"      // n1.room.name 也是 "B"

放在栈上还是堆上，不决定上面的共享关系。小结构体常常在栈上；一旦放进类、逃逸闭包或 any 容器，就可以到堆上。位置变了，该共享的还是共享，该分开的还是分开。

2. 枚举的关联值和原始值有什么区别？

口述版

  • 原始值是 case 的固定编码，声明时就定好，所有 case 共用一种类型。用 init?(rawValue:) 还原，对不上得到 nil，不会崩溃。
  • Int 原始值省略时等于前一个 case 加 1。只有第一个 case 省略，才是 0。
  • 关联值是创建这个枚举值时附带的数据。不同 case 可以带不同的类型，运行时只处于其中一个 case。
  • 同一个枚举不能既声明原始值类型，又给 case 带关联值。

解析

原始值是 case 的常量，不是每个实例各自带的一份数据。所有 case 共用一种类型，声明时就定死。Int 原始值省略时等于前一个 case 加 1；只有第一个 case 省略才是 0。这是语言规则。还原必须走可失败初始化器，失败得到 nil，不会崩。

关联值到创建这个值时才放进去。不同 case 可以带不同的类型，运行时这个枚举值只处于其中一个 case。

enum Direction: Int {
    case north // 0，第一个省略才是 0
    case east  // 1，前一个加 1
    case south = 5
    case west  // 6，接前一个，不是回到 0
}
Direction(rawValue: 3) // nil，对不上不会崩

enum LoadState {
    case success(Data)
    case failure(Int)
}
let state = LoadState.success(Data())

同一个枚举不能一边写 : Int，一边又给 case 带关联值。原始值回答「这个 case 对应哪个固定编码」，关联值回答「这一次的值随身带了什么」。

3. 可选值是什么？接口边界怎么处理，什么情况下 ! 是合理的？

口述版

  • 可选值表示这个位置可以没有值。类型写成 Wrapped?，也就是 Optional<Wrapped>。
  • 它是枚举：.some 装着值，.none 表示没有。nil 是 .none 的写法，不是空指针这个语言概念。
  • 缺值是正常输入时，参数和返回值就用可选值。调用方用 if let、guard let、可选链或 ?? 处理。guard let 失败必须离开当前作用域。
  • ! 只放在前面已经证明有值、为空就代表程序写错的位置。JSON、网络字段、用户输入不属于这个位置。

解析

Optional<Wrapped> 只有两格：.some 里装着值，.none 表示没有。nil 是 .none 的写法，不是「空指针」这个语言概念。类的可选值底层经常用空指针表示没有值；结构体的可选值多数要另加标记，只有这个结构体自己有空余表示时才不用。

缺值是业务常态时，参数和返回值就该是可选值，调用方必须处理。guard let 失败必须离开当前作用域，所以后面的代码可以依赖绑定成功。某个分支已经证明有值、后面还有很长的代码，用 guard let 把可选值收掉，不要在后面反复 !。

struct Response { var name: String?; var title: String? }
func show(_ response: Response) {
    guard let name = response.name else { return }
    print(name)                         // 这里的 name 不是可选值
    print(response.title ?? "未命名")
}
let createdOutlet: String? = "ready"    // 创建流程已经保证有值
let outlet = createdOutlet!             // 只放在「如果是空，就是写错了」的位置

外部 JSON、网络字段、用户输入都不属于这个位置。「正常情况下都会有」不代表调用方永远不传空。最好的 ! 是让它不再出现。

4. is、as、as?、as! 分别做什么？

口述版

  • is：只检查是不是这个类型，得到 Bool，不做转换。
  • as：编译期已经能证明一定成功，例如子类转父类，以及 String 到 NSString 这种规定一定成功的桥接。
  • as?：失败是正常输入时用它。结果是可选值，失败得到 nil，不抛 Error，也不崩溃。
  • as!：另有证明、失败就代表程序写错了，才用它。JSON、协议容器和框架回调上的失败不要用它。

解析

这四者是一条阶梯：只问是不是，用 is；编译器已经能证明一定成功，用 as；失败是正常情况，用 as?；另有证明、失败就该崩，才用 as!。

class Animal {}
class Dog: Animal { func bark() {} }
let pet: Animal = Dog()

pet is Dog                 // true，原值不变
let dog = pet as? Dog      // Dog?，失败是 nil
let animal = dog! as Animal // 向上转，编译期知道一定成功
// pet as Dog              // 向下转编译器证明不了，不能写裸 as
let forced = pet as! Dog   // 失败就崩

is 不做转换。as 只接受编译期能证明的转换，包括子类转父类，以及语言规定一定成功的桥接，例如 String 到 NSString。向下转、转协议，失败是正常输入时用 as?，结果是可选值，不会抛 Error，也不会崩。

紧接着就要用那个类型时，直接 as? 绑定，少一次 is。JSON、协议容器和框架回调上的失败是数据问题，不是编程前提，不要用 as!。你写哪种，语义就是哪种，不要说成编译器有时会把 as? 变成 as。

5. throws、try?、try!、Result 怎么选？defer 什么时候执行？typed throws 适合用在哪？

口述版

  • 失败要交给直接调用方：函数标 throws，调用必须写 try，用 do-catch 处理。
  • 失败可以当成没有值：try? 把失败变成 nil，错误对象不再保留。
  • 失败代表程序写错了：try!。
  • 成功和失败要当成一个值保存、传给回调、稍后再打开：用 Result。它不会自动向外抛。
  • defer 在离开当前作用域时执行。执行到这条语句才会登记；之后 return、throw、break、continue 都会执行，后登记的先执行。fatalError、失败的 precondition 和真正的崩溃不展开栈，defer 不会执行。
  • typed throws 适合模块内部。公开接口继续用普通 throws。具体错误类型是兼容性承诺，以后增加 case 或换类型，会破坏调用方已经写死的穷尽处理。

解析

先分两路。失败要顺着调用栈交给直接调用方，用 throws，签名里看得见失败，调用方必须 try。成功和失败要当成一个值保存、传给回调、稍后再打开，用 Result。它不自动往外抛，谁拿着谁打开。

普通 throws 的错误类型是 any Error。throws(MyError) 之后，catch 可以直接拿到这个具体类型。公开接口一旦写出具体错误类型，增加 case 或换类型都可能破坏调用方已经写死的穷尽处理。这是兼容性承诺。

func use() throws {
    defer { print("1") }
    defer { print("2") }   // 离开时先 2 再 1；正常走完也会跑
    try work()             // return 和 throw 都会跑到 defer
}
let value = try? work()   // 失败变成 nil，错误对象没了
let forced = try! bundledResource() // 只有「失败代表程序写错」才这样写

defer 用来做必须成对的收尾：加锁解锁、开始结束、注册反注册。只有执行到这条语句才会登记；之后作用域正常结束，或者因 return、throw、break、continue 离开，都会跑它。fatalError、precondition 失败和真正的崩溃不展开栈，defer 不会跑。它不是「进程怎么死都会执行」的保险。throws 底层怎么传递错误是 ABI，面试讲到调用方看不看得见失败即可。

6. 指定初始化器、便利初始化器、required、可失败 init 各做什么？两阶段初始化是什么？

口述版

  • 指定初始化器（designated init）：把本类所有存储属性都初始化的那个入口。类和结构体靠它把属性填满，之后才能用 self。
  • 便利初始化器（convenience init）：只是另一个入口，最终必须横向委托给本类的指定初始化器，自己不能直接给存储属性赋值。
  • required init：声明「子类必须实现这个初始化器」。子类要么自动继承，要么显式写实现，不能漏。
  • 可失败初始化器（init?）：初始化可能不成功，用 return nil 提前退出，返回的是可选值，不抛 Error。
  • 两阶段初始化：第一阶段从下往上——本类先给自己的存储属性赋值，再调用 super.init；第二阶段从上往下——super.init 完成后，才能用 self、改属性和调方法。这样保证属性不会在没初始化完之前被读到。

解析

类和结构体都有指定初始化器，把存储属性全部填满，实例才算构造完。结构体没有继承，就没有 super.init 这套委托链，规则简单很多。类的规则复杂在继承：便利初始化器必须横向委托给同类的指定初始化器，指定初始化器纵向委托给父类的指定初始化器，环是不允许的。

class Vehicle {
    var name: String
    init(name: String) { self.name = name }      // 指定初始化器
    required init() { self.name = "车" }           // 子类必须实现
    convenience init(named n: String) {
        self.init(name: n)                        // 便利初始化器横向委托
    }
}
class Car: Vehicle {
    var wheels: Int
    init(name: String, wheels: Int) {
        self.wheels = wheels                       // 阶段一：先给本类属性赋值
        super.init(name: name)                     // 再调父类
        // 阶段二：现在才能用 self、改属性、调方法
    }
    required init() {
        self.wheels = 4
        super.init()
    }
}
let n = Int("x")                                   // init? 失败返回 nil

两阶段初始化的目的是安全：第一阶段还没轮到父类，子类不能读父类的属性；第二阶段父类已经就绪，才能用 self 做剩余工作。可失败初始化器失败时 return nil，调用方拿到可选值去判断。

二、属性、访问控制与泛型

7. 存储属性、计算属性、lazy、属性观察器有什么区别？扩展为什么不能加存储属性？

口述版

  • 存储属性参与实例布局，存在实例里。类和结构体可以有，枚举没有存储属性。
  • 计算属性没有自己的存储，读的时候计算，写的时候转交出去。只能用 var，不算实例大小。
  • lazy 仍是存储属性，第一次访问才创建，所以不能是 let。类型系统不保证线程安全，多个线程同时第一次访问，不保证只初始化一次。
  • willSet 在赋值前拿到 newValue，didSet 在赋值后拿到 oldValue。本类型的初始化器赋初值不触发。子类初始化器在 super.init 之后再给父类属性赋值，会调用父类的观察器。
  • 扩展不能加存储属性。存储属性会改变实例大小和偏移，已经编译出的布局对不上。计算属性、方法、下标可以加。

解析

这题按值存在哪、什么时候写入、写入时要不要通知来分。存储属性参与实例布局，下一次还能原样读到。计算属性没有自己的存储，读的时候现算，写的时候转交出去，不算实例大小。

struct Counter {
    var stored = 0
    var doubled: Int { stored * 2 }
    lazy var heavy = Array(repeating: 0, count: 1000)
    var observed = 0 {
        willSet { print("将变成", newValue) }
        didSet { print("原来是", oldValue) }
    }
    init() {
        observed = 1 // 本类型的初始化器赋初值，不触发观察器
    }
}

lazy 仍然占存储，只是第一次访问才创建，所以不能是 let。类型系统只保证它延迟初始化，不保证线程安全。多个线程可能同时第一次碰到它时，用锁、actor，或在外部显式初始化。

观察器是初始化完成之后的赋值通知。子类初始化器在 super.init 之后再给父类属性赋值，会调用父类的观察器。这是语言规则。

扩展可以加计算属性、方法、下标、嵌套类型和协议遵循。结构体和枚举的扩展可以加初始化器；类的扩展只能加便利初始化器，指定初始化器必须写在类型本体里。不能加存储属性。存储属性会改变实例大小和偏移，已经编译出的布局对不上。

8. static 和 class 修饰类型成员有什么区别？

口述版

  • static 和 class 都表示类型成员，通过类型访问，不通过实例。
  • static：类、结构体、枚举、协议、actor 都能用，存储属性和计算属性都可以。用在类上时，这个成员不能被重写，语义是 class final。
  • class：只能用在类上，只能修饰方法和计算属性，不能修饰存储属性。子类可以 override。actor 不能继承，所以没有 class 成员。
  • 结构体和枚举不能继承，只能用 static。类型上要存一份数据，也只能写 static 存储属性。
  • static 只让这一个成员不能被重写。要让整个类不能被继承，给类加 final。

解析

这题问的是类型成员能不能被子类换掉，不是整个类能不能被继承。想锁住整类，给类加 final。

class Node {
    static var count = 0
    static func make() -> Node { Node() }
    class func describe() -> String { "node" }
    class var title: String { "node" }
}
class Leaf: Node {
    override class func describe() -> String { "leaf" }
    // override static func make() 不行
    // class var count 也没有这种存储语法
}

static 可以修饰类、结构体、枚举、协议和 actor 的类型成员。出现在类上时，这个成员不能被重写，语义就是 class final。class 只能用在类上，修饰类型方法或计算类型属性，子类写 override class。actor 不能继承，所以也没有 class 成员。

9. 访问控制从宽到窄是什么？private 和 fileprivate 差在哪？

口述版

  • 从宽到窄：open、public、package、internal、fileprivate、private。不写就是 internal。这是编译期检查谁能看见这个名字，不是运行时再拦一层。
  • open：其他模块可以访问，也可以继承、重写。只能用在类和类成员上。
  • public：其他模块可以访问，但不能在其他模块继承或重写。本模块里仍然可以，除非另外标了 final。
  • package 是同一个 Swift package，不是同一个文件夹。internal 是当前模块。
  • fileprivate 是当前源文件里的所有类型。private 是当前声明，加上同一文件里这个类型自己的扩展。它不是只有这一对花括号。
  • 对外只读、对内可写，把 setter 的访问级别单独写窄，例如 private(set)。

解析

访问控制是编译器在检查谁能看见这个名字，不是运行时再拦一层，也不是编译器优化。package 从 Swift 5.9 起就是语言级别，对应同一个 package，不是同一个文件夹。

struct Account {
    private var pin = "1234"
    fileprivate var id = "a"
    private(set) var balance = 0
}
extension Account {
    func readPin() -> String { pin } // 同类型、同文件，private 看得见
}
struct Audit {
    func read(_ account: Account) -> String { account.id }
    // account.pin 看不见：private 不给同文件的其他类型
}

private 不是「只有这一对花括号」。public 也不是「任何地方都不能继承」，缺的主语是「其他模块」。

10. 泛型解决什么问题？它和 Any 有什么差别？

口述版

  • 泛型把类型做成参数。同一份实现可以复用，调用点的 T 仍是具体类型，约束在编译期检查，不是运行时再碰运气。
  • 约束写成 T: SomeClass、T: SomeProtocol。返回值和参数可以保持同一个 T。T: AnyObject 约束的是「必须是类」，它自己不是 Any。
  • Any 和 AnyObject 是类型擦除之后的结果。Any 可以装任意类型，AnyObject 只表示类实例。取出来时具体类型已经不在静态类型里，要再转换。
  • 协议里要等遵循者填写的类型，写成关联类型 associatedtype。它不是调用时再换的类型参数。

解析

泛型解决的是复用一份实现，同时把类型关系留在编译期。每次调用的 T 是一个具体类型，返回值、参数之间可以保持同一个 T。写错约束会编译失败，不是运行时再碰运气。

func first<T: Equatable>(_ items: [T], equalTo target: T) -> T? {
    items.first { $0 == target }   // T 在这个调用点是具体类型，== 编译期就查得过
}
let box: [Any] = [1, "a"]
let text = box[1] as? String       // 拿出来已经不知道原来是什么

Any 和 AnyObject 都是类型擦除之后的结果。前者装任意类型，后者只表示类实例。T: AnyObject 是泛型约束，约束的是「这个类型参数必须是类」，它自己不是 Any。T: SomeClass 约束的是继承关系。

协议里要等遵循者来填的类型写成关联类型，例如集合的元素。它不是调用时随便换的参数。where 给泛型或扩展加附加约束。

三、内存与闭包

11. ARC 是什么？strong、weak、unowned 怎么选？

口述版

  • ARC 在引用产生和失效时插入计数。最后一条强引用消失，纯 Swift 对象就进入 deinit。它不是垃圾回收。互相强引用时，环上的计数不会自己变成 0。
  • strong：默认。引用计数加 1，还有强引用时对象不会释放。
  • weak：不增加计数。对象释放后自动变成 nil，必须是可选的 var。运行时清成 nil 时不调用属性观察器。
  • unowned：也不增加计数，而且不是可选值。对象释放后这个引用不会被改成 nil，再使用会立刻触发陷阱。
  • 销毁之后访问应该变成「没有」，用 weak。被引用的对象一定活得更久，才用 unowned。不确定就用 weak。
  • 适用于类、actor、闭包，以及限定为类的协议。结构体和枚举没有引用计数。进了自动释放池的 Objective-C 对象要等池子排空，不是当场销毁。

解析

ARC 管类、actor、闭包，以及限定为类的协议（: AnyObject）。结构体和枚举没有这套计数。编译器在引用赋值和失效时插入记账：强引用加一，最后一条强引用消失就减到 0。纯 Swift 对象这时就进入 deinit；进了自动释放池的 Objective-C 对象要等池子排空，不是当场销毁。它不是过一会儿再来扫的垃圾回收。互相强引用时，环上的计数不会自己变成 0，环的那一条改成 weak，通常是不拥有对方的那一方。

class Owner {
    var child: Child?
    weak var delegate: OwnerDelegate?
    unowned let parent: Owner
    init(parent: Owner) { self.parent = parent }
}

需要把对象留住，用默认强引用。两边谁先销毁不确定，或者销毁之后访问应该变成「没有」，用 weak。它必须是可选的 var。运行时把 weak 清成 nil 时，直接写空，不调用 willSet / didSet。

unowned 的前提是被引用的对象一定活得更久，例如它拥有我、我不可能活过它。拿不准就用 weak。多一次可选绑定，比崩溃便宜。unowned 不是可选值，对象释放后继续使用会立刻陷阱。

12. 这段代码为什么循环引用？weak 和 unowned 怎么选？

口述版

  • 对象用属性强引用闭包，闭包又默认强引用 self，两边的 deinit 都不会发生。
  • 捕获列表写在参数列表前面：{ [weak self] in }。不写捕获列表，捕获的就是强引用。
  • 对象可能先释放，用 weak。对象释放后 self 变成 nil，里面用 self? 或 guard let self。
  • 闭包只被这个对象持有，而且不会被交给活得更久的一方，才用 unowned。逃逸闭包里写出 self，只是让捕获看得见，强弱不变，仍然是强引用。

解析

对象强引用闭包，闭包又强引用对象，两边的 deinit 都不会发生。捕获列表只决定这一次捕获是不是强引用。不写，抓到的就是强引用。逃逸闭包里要求你写出 self，只是让捕获看得见，不会把强弱改掉。

class Owner {
    var work: (() -> Void)?
    func start() {
        work = { self.doWork() }          // 属性强引用闭包，闭包强引用 self
    }
    func startSafely() {
        work = { [weak self] in self?.doWork() }
    }
    func doWork() {}
}

闭包存在属性、回调、定时器里，页面或对象可能先消失，用 [weak self]，里面用 self? 或 guard let self。闭包只被这个对象持有，而且不会被拷给更长寿的一方，对象释放前不可能再调用，才可以 [unowned self]。闭包一旦逃到对象外面，这个前提通常就不成立。

13. 闭包是引用类型吗？@escaping 改变了什么？为什么逃逸闭包不能捕获 inout？

口述版

  • 闭包是引用类型。赋给另一个变量，得到的是同一个闭包，不是再复制一份闭包体。
  • 默认捕获的是外面那个变量本身，不是创建时的一份拷贝。要留下创建时的值，写成 { [n] in n }。
  • 函数参数上的闭包默认不逃逸，函数返回后不能再调用。还可能在返回后调用，要标 @escaping。参数类型本身是可选闭包时，已经隐式逃逸，不必再标。
  • 逃逸闭包不能捕获 inout。inout 只在这次调用期间借用外面的变量，返回时必须写回并结束访问。函数返回后还会执行的闭包接不住这次借用。
  • @escaping 不改变捕获的强弱。类实例默认仍是强引用。可能成环时，要在捕获列表写 [weak self]。

解析

这题有三层：闭包这个值是不是引用，它能不能活过这次函数调用，它捕获的是一份快照还是外面那个变量。复制闭包变量，得到的是同一个闭包，不是把闭包体再复印一份。

var saved: (() -> Void)?
func run(body: () -> Void) { body() }
func store(body: @escaping () -> Void) { saved = body }

var n = 1
let seeLater: () -> Int = { n }
let snap: () -> Int = { [n] in n } // 创建时 n 是 1，留下的是 1
n = 2
seeLater()                    // 2，双方看见的是同一个变量
snap()                        // 1

func bump(_ value: inout Int, body: (inout Int) -> Void) {
    body(&value)              // 非逃逸，调用还在这次 inout 访问之内
}

函数参数的闭包默认非逃逸，例如 map 的变换，函数返回后不能再调用，所以可以捕获 inout。可选闭包参数是例外：(() -> Void)? 已经是隐式逃逸，不必再标 @escaping。@escaping 允许非可选的闭包参数活过这次调用。inout 是临时把外面那个变量的独占使用权借给你，返回时必须写回并结束访问。带出函数的闭包不能夹走这次借用。

类实例默认按强引用捕获。可能成环，要在捕获列表写 [weak self]。只是把 self. 写出来，仍然是强捕获。

14. map、flatMap、compactMap 有什么区别？

口述版

  • map：对每个元素做一次变换，一对一，返回元素个数不变。变换不能返回 nil。
  • compactMap：和 map 一样变换，但把返回的 nil 丢掉，是一对零或一。
  • flatMap：每个元素变换成一个序列，再把所有序列拍平成一个，是「变换 + 拍平」。Swift 4.1（SE-0187）把「过滤 nil」从 flatMap 拆成 compactMap 之后，flatMap 只负责拍平。
  • Optional 上的 map / flatMap：map 对 .some 里的值变换，.none 保持 .none；flatMap 的变换如果又返回可选值，能避免套成双层 Optional。

解析

三者都是泛型高阶函数，差别在「变换之后要不要去掉一些东西、要不要摊开一层」。

let nums = [1, 2, 3]
nums.map { $0 * 2 }                    // [2, 4, 6]，一对一

["1", "x", "3"].compactMap(Int.init)   // [1, 3]，Int.init 是 (String) -> Int?，nil 被丢掉
[[1, 2], [3]].flatMap { $0 }           // [1, 2, 3]，把内层数组拍平

let s: String? = "hi"
s.map { $0.uppercased() }              // "HI"?，.none 保持 .none
s.flatMap { Int($0) }                  // nil?，Int("hi") 失败，不会变成 Int??

能拿到 nil 的变换，想丢掉空值用 compactMap。想展开嵌套结构用 flatMap。历史上 flatMap 既拍平又丢 nil，容易混，所以拆开了；面试里被问到，先分清「拍平」和「过滤 nil」是哪一件事。

15. @autoclosure 是做什么的？和普通闭包参数有什么区别？

口述版

  • @autoclosure 把一个表达式自动包成闭包，调用点不用写 { }。看起来像传值，实际是延迟执行。
  • 好处是延迟求值：参数只在函数体里真正走到那个分支时才执行。assert、??、&& 就是「不一定会执行」的场合。
  • 代价是隐蔽：调用方看不出这里会延迟、可能不执行，也看不出这个闭包会被捕获或逃逸。
  • 默认是非逃逸。要让它在函数返回后执行，写成 @autoclosure @escaping。

解析

普通闭包参数要求调用方写出 { }，@autoclosure 让编译器替调用方把表达式包起来。两者的类型一样，差别只在调用点写不写花括号，以及值什么时候被求。适合「参数可能根本不会被用到」的场景，省掉一次不必要的计算。

func require(_ condition: @autoclosure () -> Bool,
             _ message: @autoclosure () -> String) {
    if !condition() { print(message()) }
}
require(1 > 2, "算错了")   // 不用写 require({ 1 > 2 }, { "算错了" })

let name = person.name ?? "未命名"   // ?? 的右边就是 @autoclosure，只有左边是 nil 才算

@autoclosure 不改变捕获规则：它还是闭包，还是会按闭包的方式捕获外面的变量。把它当成「省掉花括号的延迟求值」，而不是「不用闭包的传值」。

四、协议

16. 为什么说 Swift 是面向协议编程的？

口述版

  • 面向协议复用的是「有没有这套能力」，不是继承树上的位置。类、结构体、枚举只要完成协议要求，就能用这套 API。
  • 协议扩展可以给遵循者一份默认实现，后来的类型不用先继承一个父类。需要哪套能力，就遵循哪个协议。
  • 类仍然负责对象身份、继承和 deinit。需要这三样，才用类。

解析

面向协议复用的是「有没有这套能力」，不是「在继承树上的哪一层」。谁能把协议要求做完，谁就能用这套 API，不管它是类、结构体还是枚举。协议扩展给大多数遵循者一份默认做法，后来的类型不用先认一个父类。

protocol Named { var name: String { get } }
extension Named {
    func greeting() -> String { "Hi, \(name)" }
}
struct User: Named { var name: String }
User(name: "Lin").greeting()

大部分类型的实现相同，就把默认实现写在扩展里，并且放进协议要求。不放进要求，具体类型的同名方法不一定会被调用。类仍然是引用类型，身份、继承和 deinit 都是它的语言能力。这题是设计规则：默认实现最终走直接调用还是见证表，由它是不是协议要求决定。

17. Codable 是什么？Encodable/Decodable 怎么自动合成？自定义 key 怎么处理？

口述版

  • Codable 是 Encodable 与 Decodable 的组合（协议组合）。实现了它，类型就能被 JSONEncoder/JSONDecoder、PropertyListEncoder 等编解码。
  • 自动合成：当所有存储属性都是 Codable 时，编译器自动生成 init(from:) 和 encode(to:)，不用手写。
  • 自定义 key：字段名和 JSON key 对不上时，写 enum CodingKeys: String, CodingKey 做映射。Optional 属性在 JSON 里缺失时解码成 nil，不会失败；非 Optional 缺失才抛错。
  • 手动实现：默认策略不够用（日期格式、key 动态、字段需要转换）时，手写 init(from:) 和 encode(to:)。
  • 有继承时自动合成不会跨继承，子类要自己处理父类属性——这是常见坑。

解析

Codable 本身是协议组合，不是一个新协议。编译器能为结构体、枚举、类做自动合成，前提是每个存储属性都可编码。对不上的 key 用 CodingKeys 映射，枚举的 case 名是属性名，原始值是 JSON 里的 key。

struct User: Codable {
    var id: Int
    var displayName: String
    var nickname: String?
    enum CodingKeys: String, CodingKey {
        case id
        case displayName = "display_name"
        case nickname
    }
}
let data = try JSONEncoder().encode(User(id: 1, displayName: "Lin", nickname: nil))
let user = try JSONDecoder().decode(User.self, from: data)

字段名完全一致时连 CodingKeys 都不用写。nickname 是 String?，JSON 缺这个 key 会解码成 nil 而不是报错。子类继承一个 Codable 父类时，编译器不会自动把父类属性也编进去，要自己调 super.encode(to:) 或手写整个实现。

18. Swift 协议和 OC 协议有什么区别？

口述版

  • Swift 原生协议：类、结构体、枚举都能遵循。可以有关联类型和默认实现，不能写 optional。调用走见证表，按要求的下标取实现。
  • @objc 协议：遵循者必须是类。可以写 optional，不能有关联类型。调用走 objc_msgSend，按方法名查找。
  • 要给一批遵循者同一份默认做法，用协议扩展。要兼容 Objective-C 的可选回调，才给协议和方法标 @objc optional，调用前按「可能没有」处理。
  • 默认实现一定存在。没有默认实现，缺少这个方法就不通过编译。optional 方法可以不实现。

解析

两套协议的差别，来自两套「按协议找实现」的机制。Swift 原生协议为每个「类型 + 协议」生成见证表：左边是协议要求，右边是这个类型的实现，调用时按下标取。Objective-C 协议没有这张卡，调用变成 objc_msgSend，拿着方法名（选择子）去类里按名字找。

protocol Drawable {
    func draw()
}
extension Drawable {
    func draw() {}          // 默认实现一定存在
}
@objc protocol Clickable: AnyObject {
    @objc optional func click() // 可以不实现，调用前要知道它可能没有
}

必须跟现有 Objective-C 委托、可选回调兼容时，协议和方法标 @objc，遵循者用类，调用 optional 前按可选方法处理。不要用 OC 的 optional 来模拟「给一批遵循者一个默认做法」。

19. some 和 any 差在哪？

口述版

  • some 背后是一个具体类型。返回位置上，调用方看不见这个名字，非泛型函数的每条返回路径必须是同一种。
  • 参数上的 some P 就是泛型简写。类型由调用方每次决定，同一次调用里仍是一个具体类型。
  • any 是存在类型，具体类型被擦掉。同一个变量前后可以装不同的遵循者，这些类型不必有继承关系。调用协议要求时查见证表。
  • 类型固定、不需要把不同具体类型放进同一个值，用 some。要放进同一个数组或变量，用 any。

解析

先问两件事：具体类型是谁定的，调用方能不能把不同的具体类型装进同一个值。类型固定而且不需要擦掉，用 some；每次可能是不同遵循者，又要放进同一个值，用 any。

protocol Greeter { func hello() -> String }
struct Pirate: Greeter { func hello() -> String { "Ahoy" } }
struct Robot: Greeter { func hello() -> String { "Beep" } }

func one() -> some Greeter { Pirate() }
// func mixed() -> some Greeter { Bool.random() ? Pirate() : Robot() } // 两条路径不是同一种类型

func greet<T: Greeter>(_ value: T) {}
func greetSome(_ value: some Greeter) {} // 参数上的 some 就是这种泛型简写

var crowd: [any Greeter] = [Pirate(), Robot()]

返回位置的 some P 是不透明类型：调用方不能点名底层类型，也不需要先擦成 any 再返回。非泛型函数整个函数只有一个底层具体类型，每条路径都必须相同。泛型函数的底层类型可以跟着类型参数变，同一组类型参数下各条路径仍必须是同一种。参数位置的 some P 由调用方在每次调用时决定。两次调用可以是两种类型，同一次调用里就是一个 T。

any P 是存在类型。同一个变量前后可以装不同的遵循者，这些类型之间不必有继承关系。调用协议要求时通过见证表。要 Pirate 和 Robot 放进同一个数组，就得用它。

五、方法调用

20. Swift 方法调用是如何实现的？

口述版

  • 派发方式有三种：静态派发、虚表派发、消息派发。看这次调用能不能在编译期定死唯一函数。
  • 静态派发：编译期就知道跳到哪个函数，直接调用，也最有机会被内联。结构体和枚举上的直接调用，类里的 final、private、static，以及协议扩展里不是协议要求的方法。
  • 虚表派发：类里还能被重写的实例方法。从对象开头的类指针找到类，按下标取出函数；子类重写，换的是这一格。协议要求走另一张见证表，同样是固定槽位。
  • 消息派发：没有固定槽位，走 objc_msgSend，按方法名找。标了 dynamic 的成员，以及重写了 Objective-C 方法的成员。只加 @objc 是暴露给 OC，Swift 这边的调用不会因此改成消息派发。继承 NSObject 也不会。

解析

Swift 按调用点能确定多少，选择派发方式。能在编译期定死唯一函数，就静态派发。类里还有子类能换实现，就虚表派发，运行时查一次固定下标。要交给 Objective-C 运行时按名字找、还允许换实现，才消息派发。

静态派发。编译期已经把函数地址写进调用点，这是最快的一条，编译器还可以把短函数嵌进调用点，那是内联，不是另一种派发。结构体和枚举没有子类能替换方法，直接拿具体类型调用时就是静态派发。把它装进 any P 再调用协议要求，就改查见证表。final、private、static 的类成员不能被重写，语言规则允许绑到唯一实现。

struct Point {
    var x: Int
    func shifted(by dx: Int) -> Point { Point(x: x + dx) } // 静态派发
}
final class FinalCar {
    func run() { } // 整个类不能被继承，方法是静态派发
}
class Car {
    final func vin() -> String { "fixed" } // 这个方法不能被重写
    private func log() { }                 // 文件外不能重写
}

虚表派发。类要支持子类换掉方法，每个类带着一张表，一格对应一个可重写的实例方法。调用时从对象开头的类指针找到类（继承 NSObject 时，这根指针就是 isa），再按下标取出函数。子类重写，复制这张表并换掉对应的那一格。class 修饰的类型方法还能被子类重写，同样不走静态派发。目标要到运行时才知道，调用点通常不能内联。协议要求用的是见证表：类型遵循协议时生成，左边是协议要求，右边是这个类型的实现。通过 any P，或泛型还没被特化时，按下标取。泛型在看得到实现、被特化之后，可能变成静态派发，那是优化，语言不保证。

class Animal {
    func sound() { print("Animal") } // 虚表派发
}
class Dog: Animal {
    override func sound() { print("Woof") } // 换掉虚表里的这一格
}
let animal: Animal = Dog()
animal.sound() // 查 Dog 的虚表，输出 Woof

消息派发。dynamic 强制这个成员走 objc_msgSend。运行时拿着方法名查缓存和方法列表，没有再问父类，所以可以交换实现、做 KVO。缓存只是加快查找，不改变这条规则。只加 @objc 是把声明暴露给 OC：OC 那边按名字发消息，Swift 这边的调用仍可以是静态派发或虚表派发。继承 NSObject 同样不会让普通 Swift 方法自动改成消息派发。正在重写一个 Objective-C 方法时，因为父方法已经是 dynamic，这个重写才会跟着走消息派发。

class Demo: NSObject {
    func overridable() { }                 // 虚表派发
    @objc func exposed() { }               // OC 能调用；Swift 这边不因此变成消息派发
    @objc dynamic func swizzleable() { }   // 消息派发，运行时可以换实现
}

六、并发

21. Swift async/await 和 GCD 有什么区别？await 会不会堵住当前线程？

口述版

  • await 只在挂起点挂起当前任务。挂起之后，这条线程可以执行别的任务，不会停在原地阻塞等待。
  • 没有遇到 await 的代码是同步的，会一直占用当前执行器。主 actor 的执行器是主线程，所以主 actor 上这段同步代码会卡住界面。
  • GCD 是把闭包提交到队列。异步提交不阻塞提交线程。sync、信号量、Thread.sleep 和锁上的阻塞等待会占住线程。
  • 不要在异步函数里用信号量把等待改成阻塞。合作线程池的线程有限，线程被占住后，其他任务没有线程可跑，严重时还会自己等自己。

解析

先分清挂起的是谁。await 只在挂起点挂起任务，不会让线程在那里空转等待。挂起之后，这个线程可以执行别的任务。没有遇到 await 的代码是同步的，占用当前执行器。主 actor 的执行器就是主线程，所以主 actor 上的同步重活会卡住界面。

func refresh() async {
    let data = await fetch()   // 挂起的是这个任务，线程可以去干别的
    decode(data)               // 这里没有 await，会一直占着当前执行器
    await updateUI(data)
}

GCD 是把闭包投进某个队列。异步提交不会阻塞提交线程；sync、信号量、Thread.sleep 和锁上的死等会占住线程。这些东西放进 Swift 并发的合作线程池里，会把线程占死，其他任务没有线程可跑，严重时还会自己等自己。想把老的回调包成 async，用 continuation，不要在异步函数里用信号量把等待改成死等。

看到卡顿，先看当前执行器上有没有一段没有 await 的重活，而不是先怪 await 本身。

22. actor 和类有什么差别？赋值之后谁和谁共享状态？

口述版

  • actor 和类一样是引用类型。赋值复制的是引用，两个变量共享同一个实例。
  • 差别在隔离，不在会不会拷贝。没有遇到 await 时，只有当前任务能访问这份隔离状态。类没有这层隔离，多个任务同时改是数据竞争。
  • 遇到 await，当前任务挂起并让出，别的任务可以进入并修改同一份状态。await 前后不是同一段临界区。
  • actor 隐式遵循 Sendable。引用可以交给别的任务，但状态仍然只能通过这个 actor 的隔离方法修改。

解析

这题的差别不在「会不会拷贝」。actor 和类赋值都是复制引用，共享同一个实例。类没有隔离，多个任务同时改同一个类的属性，是数据竞争。actor 的隔离状态同一时间只允许一个任务访问，这是语言保证，不是约定俗成的加锁风格。

actor Cache {
    private var items: [String: Data] = [:]
    func get(_ key: String) -> Data? { items[key] }
    func load(_ key: String) async -> Data {
        if let hit = items[key] { return hit }
        let data = await fetch(key) // 这里让出 actor，别的任务可以进来
        items[key] = data
        return data
    }
}

actor 不是「从函数入口锁到出口」。一到 await，当前任务挂起并让出，别的任务可以进入并修改同一份状态。隔离方法里只要写了 await，就不要假设前后中间没有别人改过状态。缓存、计数器和「先检查再写入」都按这个来设计：挂起前读到的状态，恢复之后可能已经变了。

actor 自动遵循 Sendable。别的任务可以持有这个引用，但不能绕过隔离直接改里面的状态。编译器不会把类自动改写成「整段方法持有锁」；让出是语义的一部分。

23. async let、TaskGroup、Task、Task.detached 分别是谁的子任务？

口述版

  • async let、任务组：当前任务的子任务。取消会顺着父子关系传下去。离开作用域时如果还没等完，先取消，再等它们结束。父任务不是发出取消就立刻返回。
  • Task { }：不是子任务。它继承当前 actor、优先级和任务局部值，所以在主 actor 上创建就留在主 actor。外层取消不会自动取消它，要自己保存句柄并 cancel()。
  • Task.detached：也不是子任务，而且不继承 actor、优先级和任务局部值。

解析

先问它是不是当前任务的子任务。是子任务，取消会顺着父子关系传下去，离开作用域还要把它等完。Task { } 和 Task.detached 都不是子任务，外层取消不会自动带到它们身上。编译器不会把一个普通的 Task { } 自动改成子任务，也不会在函数返回时替你 cancel()。

func fetch(_ id: String) async -> String { id }
func load() async {
    async let left = fetch("a")     // 子任务
    async let right = fetch("b")
    _ = await (left, right)         // 不 await 就离开：先取消，再等它们结束
}
func group() async {
    await withTaskGroup(of: String.self) { group in
        group.addTask { await fetch("a") } // 组里添加的都是子任务
    }
}
let handle = Task { await fetch("c") }    // 不是子任务，要自己 handle.cancel()
Task.detached { await fetch("d") }        // 也不继承 actor、优先级、task local

固定几件可以并行、并且必须跟着当前任务一起结束的事，用 async let。子任务数量要运行时才知道，用 withTaskGroup。要脱离当前作用域继续跑，例如界面发起一个之后还能自己取消的加载，用 Task { }，把返回的句柄存下来，离开时 cancel()。明确不要继承优先级、actor 和任务局部值，才用 Task.detached。

async let 和任务组会沿用优先级和任务局部值。子任务理会取消，就可以提前结束；父任务不是发完取消就立刻返回。

24. Sendable 保证什么？@unchecked Sendable 在承诺什么？

口述版

  • Sendable 表示这个值可以跨隔离域传递，不会因此产生数据竞争。这是编译期检查，运行时不会加锁，也不会把类变成值类型。
  • 结构体和枚举的成员都是 Sendable 时就可以遵循。传过去的是副本。成员里有可变类，就不能直接遵循。
  • 类要让编译器认可，必须是 final，存储属性不可变且为 Sendable，父类本身也是 Sendable。NSObject 不是 Sendable，所以它的子类只能标 @unchecked Sendable。
  • @unchecked Sendable 关掉的是编译器检查，不是数据竞争。同步要自己用锁或者 actor 保证。这个保证不成立，同时修改还在。

解析

Sendable 是编译期的通行证。满足条件才能跨隔离域传递。它不会在运行时加锁，也不会把类变成值类型。值类型跨任务传递的是副本，所以成员都是 Sendable 时，结构体和枚举可以遵循。成员里藏着可变类，就不能随手盖章。

struct Point: Sendable { var x: Int; var y: Int }

final class Token: Sendable {
    let value: String
    init(_ value: String) { self.value = value }
}

final class Counter: @unchecked Sendable {
    private let lock = NSLock()
    private var value = 0
    func next() -> Int {
        lock.lock()
        defer { lock.unlock() }
        value += 1
        return value
    }
}

actor 隐式遵循 Sendable。能传的是引用，改仍然要进 actor。类要让编译器认可，必须是 final，存储属性不可变且为 Sendable，父类本身也得是 Sendable。final 的 NSObject 子类即使全是 let，编译器也不认，只能 @unchecked。还有 var 又没有同步，编译器就不认。传的是引用，所以条件比值类型严。

@unchecked Sendable 关闭的是检查，不是关闭数据竞争。给一个到处都是 var 的类加上它，报错没了，同时修改还在。

25. @MainActor 保证的是什么？界面卡顿时先看什么？

口述版

  • @MainActor 把这段代码隔离到主 actor，由主线程执行。这是隔离规则，不是性能优化。
  • 它不估算这段要跑多久，也不插入挂起点，同步函数不会因此变成异步。同步代码在主线程上执行期间，界面会卡住。
  • 界面卡顿时，先看主线程上有没有耗时计算、同步 I/O，或者在锁和信号量上的阻塞等待。
  • 两个 await 之间没有挂起点，这段同步代码会一直占用主线程。耗时计算放到不隔离在主 actor 上的函数里做完，再 await 回主 actor 更新界面。

解析

@MainActor 是全局 actor。标在类型或函数上，表示这些代码隔离在主 actor，由主线程执行。这是隔离规则，不是「通常会这样」的优化。它不把重活改成并行，也不插入挂起点。编译器会在跨越主 actor 边界时安排切换，不会估算函数要跑多久，也不会自动把慢函数搬离主线程。

@MainActor
func show(_ items: [Item]) {
    view.items = items          // 碰界面，留在主 actor
}
func prepare(_ raw: Data) async -> [Item] {
    decode(raw)                 // 重活不要只靠加上 @MainActor
}

碰界面、UI 对象和主线程限定的 API，隔离到 @MainActor。函数体里有重计算，把重计算放到不会隔离在主 actor 上的函数里，算完再 await 回主 actor 更新界面。

卡顿时的顺序：先看主线程有没有长计算、同步 I/O，或者锁和信号量上的阻塞等待；再看解码、压缩、大列表加工有没有被标进主 actor；最后才看刷新频率这些表现层问题。同步部分不挂起，就一直占着主线程。

七、加分题

26. 为什么 Array、String、Dictionary、Set 是值类型？copy-on-write 怎么发生？自定义结构体为什么不会自动有？

口述版

  • 它们是值类型，保证的是值语义：赋值或传参之后，修改这一份，另一份观察不到。
  • copy-on-write 是标准库的实现：赋值时先共用同一块缓冲区；要修改，并且这份缓冲区还有其他引用，才复制一份再改。只剩自己持有时，可以在原来那块上改。
  • 这是 Array、String、Dictionary、Set 自己实现的。编译器不会给自定义结构体自动做唯一性检查，赋值时直接拷贝各个存储属性。
  • 短 String 没有共享缓冲区，字符嵌在值里。缓冲区容量不够时，即使引用唯一，也会重新分配。

解析

语言保证的是值语义：赋值、传参之后，修改这一份，另一份观察不到。copy-on-write 是标准库为了让这份语义便宜，用在这四个类型上的实现。编译器不会看见结构体就自动插入唯一性检查。

用到堆缓冲区时，变量里存的是这块内存的地址，元素在里面。赋值复制的是地址，两边地址相同，读和单纯赋值可以很便宜。要修改并且这个地址还有别人拿着，才新开一块内存，把元素复制过去，换成新地址再改。只剩自己拿着，才可以在原来那块上改；容量不够时，即使引用唯一，Array 的 append 仍会新分配。短 String 走小字符串优化，字符嵌在值里，赋值复制的是值本身，没有共享缓冲区。别人还拿着时却不复制，就会破坏值语义。这不是「编译器也许会优化掉复制」。

自定义结构体赋值，拷贝的是它的各个存储属性，没有自动的「整份结构体唯一化」。要给自己的大块缓冲区做延迟复制，就用一个类握住数据，修改前看强引用是不是只剩这一份。

final class Storage {
    var items: [Int]
    init(_ items: [Int]) { self.items = items }
}
struct Queue {
    private var storage = Storage([])
    mutating func append(_ n: Int) {
        if !isKnownUniquelyReferenced(&storage) {
            storage = Storage(storage.items)
        }
        storage.items.append(n)
    }
}

27. 协议扩展里写了方法，为什么有时调用不到类型自己的实现？

口述版

  • 方法写进协议要求：见证表里有这个槽。类型自己写了，就填自己的实现；没写，才填扩展里的默认实现。
  • 方法只写在扩展里：没有这个槽，按调用点看见的静态类型直接调用扩展，不会去查见证表。
  • 所以静态类型是 any Greeter 时，hello 走到 Pirate 的实现，bye 仍是扩展里的默认实现。静态类型已经是 Pirate 时，可以直接调用 Pirate 自己的 bye。
  • 希望通过协议类型调用时仍然执行每个类型自己的版本，就把方法写进协议要求。只是某个具体类型的便利函数，才可以只写在扩展里。

解析

调用时编译器手里有没有一个固定槽位，决定它会不会去查见证表。写进协议要求的方法有槽位，类型自己写了就填自己的，没写就填扩展里的默认实现。只写在扩展里的方法是按当时看见的静态类型直接调用的。

protocol Greeter {
    func hello() -> String
}
extension Greeter {
    func hello() -> String { "Hello" }
    func bye() -> String { "Bye" } // 不是协议要求
}
struct Pirate: Greeter {
    func hello() -> String { "Ahoy" }
    func bye() -> String { "Arr" }
}
let pirate = Pirate()
pirate.bye()                 // "Arr"，静态类型就是 Pirate
let g: any Greeter = Pirate()
g.hello()                    // "Ahoy"，要求在见证表里
g.bye()                      // "Bye"，按 any Greeter 直接调扩展

希望通过协议类型调用时仍然执行每个类型自己的版本，就把方法写进协议要求，默认实现可以放在扩展里。这个方法只是给某个具体类型用的便利函数，不需要被动态替换，才可以只写在扩展里。静态类型已经是具体类型时，编译器可以直接调用那个类型的方法；会不会再内联，是优化。

28. 什么是条件遵循？[String] 为什么可以是 Sendable？

口述版

  • 条件遵循是编译期规则：where 里的约束满足，这个遵循才存在。Array 只有 Element: Sendable 时才遵循 Sendable。
  • String 满足，所以 [String] 满足。元素是普通可变类时，数组也不满足，编译失败。
  • 这是类型上的遵循关系，不是运行时再检查每个元素，也不会临时补一张见证表。
  • Sendable 表示这个值可以跨隔离域传递，不会因此数据竞争。值类型传过去的是副本。它不是运行时的锁。

解析

条件遵循是编译期规则：where 里的约束满足，这个遵循才存在；不满足，就好像没有写过这个遵循。标准库的数组是 Element: Sendable 时才遵循 Sendable。

extension Array: Sendable where Element: Sendable {}
let titles: [String] = ["a"]   // String 满足，[String] 就满足
// let views: [UIView] = []    // 元素不是 Sendable，数组也不是

[String] 能跨任务传递，是因为 String 这个类型已经满足，传过去的是值的副本。不是运行时检查了每个元素再决定让不让传。约束满足时，这个具体数组类型的遵循关系就参与普通的见证表派发；不满足就编译失败。编译器不会在运行时临时补一张表。

Sendable 是标记协议，不是一把运行时的锁。它表示值跨越并发隔离域不会因此数据竞争。元素是普通可变类时，不要把数组标成可以传递；先把类收成不可变且满足条件，或者把共享状态关进 actor。
