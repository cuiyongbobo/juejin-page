一、类型与可选值

1. 类、结构体、枚举有什么差别？赋值之后谁和谁共享状态？

  • 类是引用类型。赋值复制的是引用，两个变量指向同一个实例，改一个，另一个也看得到。类可以继承，可以写 deinit，可以用 === 比较是不是同一个对象。
  • 结构体和枚举是值类型。赋值之后各有一份，改其中一份不影响另一份。它们不能继承。方法要改自身的属性，得标 mutating。
  • 结构体里如果放了一个类，拷贝结构体时拷走的是那个引用，两个结构体仍然共享同一个类实例。
  • 结构体没有自己写 init 时，编译器会生成按成员初始化的方法。类不会按成员生成；所有存储属性都有默认值、又没有自己写 init 时，类才会有一个无参数的 init()。
  • 值语义看的是赋值之后各有一份。结构体可以在栈上，也可以放进类、闭包，或者 any 盒子里。
  • 不需要继承、对象身份或 deinit 时，优先用结构体。需要这三样里的任意一样，再用类。

2. 枚举的关联值和原始值有什么区别？

  • 原始值：每个 case 对应一个同类型的固定值，比如 Int 或 String。整型原始值可以不写，编译器从 0 开始递增。用 init?(rawValue:) 还原，对不上就是 nil。
  • 关联值：case 可以带上当时才知道的数据，不同 case 的数据类型可以不一样。
  • 同一个枚举不能既声明原始值类型，又给 case 带关联值。
  • 一组互斥状态用带关联值的枚举来表达，比堆一串可选属性更不容易出现非法组合。
enum LoadState {
    case success(Data)
    case failure(Int)
}
enum Direction: Int {
    case north // 0
    case east  // 1
}

3. 可选值是什么？接口边界怎么处理，什么情况下 ! 是合理的？

  • 可选值是枚举 Optional<Wrapped>。有值是 .some，没有值是 .none。nil 就是 .none。
  • 缺值是正常情况，用 if let、guard let、可选链，或者 ?? 给默认值。guard let 不通过就离开当前作用域，后面的代码可以把绑定出来的值当成已经有了。
  • ! 只用在当前代码已经能确定它一定有值的地方。接口上传进来的数据，缺了很常见，不要用 ! 去赌它一定有。
  • 缺值说明程序已经违反了自己的前提，就让它尽早失败，比如 precondition。

4. is、as、as?、as! 分别做什么？

  • is 只判断是不是某个类型，得到 Bool。
  • as 用在编译器已经知道一定能转的时候，比如子类转成父类。
  • as? 尝试转换，失败得到 nil。
  • as! 认定一定能转，失败就崩。外部数据和不确定的类型不要用它。

5. throws、try?、try!、Result 怎么选？defer 什么时候执行？typed throws 适合用在哪？

  • 错误还要往外抛，用 throws。失败可以当成没有，用 try?，错误被丢掉，变成 nil。只有确定失败就是程序写错了，才用 try!，否则会直接崩。
  • 想把成功和失败当成一个普通值存起来，或者传给别人，用 Result。
  • defer 在离开当前作用域时执行，正常返回和抛出错误离开作用域时，defer 都会执行。同一个作用域里写了多个，后写的先执行。
  • typed throws 让 catch 直接拿到具体错误类型。公开接口一旦把错误类型写死，以后多一种失败就要改调用方，所以对外多半仍用普通 throws。模块内部的函数，或者泛型闭包，更适合用 typed throws。

二、属性、访问控制与泛型

6. 存储属性、计算属性、lazy、属性观察器有什么区别？扩展为什么不能加存储属性？

  • 存储属性自己保存值。计算属性没有自己的存储，读的时候走 getter，要改就再提供 setter。
  • lazy 是存储属性，第一次访问时才创建，所以只能写成 var。多线程同时第一次访问，可能创建多次。需要线程安全时，不要靠它。
  • willSet 里能拿到即将写入的 newValue，didSet 里能拿到旧的 oldValue。初始化器里给本类型自己声明的属性赋初值，不会触发观察器。
  • 扩展可以加计算属性、方法和协议遵循，不能加存储属性。存储属性要占实例的一块内存，扩展加进去，已经创建出来的实例对不上原来的布局。

7. static 和 class 修饰类型成员有什么区别？

  • static 可以修饰类、结构体、枚举和协议上的类型成员。用在类上时，子类不能重写。
  • class 只能修饰类的类型方法和计算类型属性，子类可以重写。它不能修饰存储属性。
  • static 管的是这一个成员，不是把整个类标成 final。

8. 访问控制从宽到窄是什么？private 和 fileprivate 差在哪？

  • open：其他模块可以访问，也可以继承和重写。只用于类，以及类里可以重写的成员。
  • public：其他模块可以访问，不能继承，也不能重写。
  • package：同一个 package 里可以访问。
  • internal：默认级别，当前模块可以访问。
  • fileprivate：当前源文件可以访问。
  • private：当前声明可以访问，同一文件里这个类型自己的扩展也可以。
  • 一个类型对外的访问级别，不能宽于它用到的那些类型。setter 可以单独设得比 getter 更严。

9. 泛型解决什么问题？它和 Any 有什么差别？

  • 泛型把类型参数化。同一套逻辑可以用于多种类型，调用的地方仍然做类型检查。
  • T: P 表示必须遵循这个协议。只要引用类型，写 T: AnyObject。T: SomeClass 表示必须是这个类或它的子类。
  • Any 什么都能装，用的时候已经不知道原来的类型。AnyObject 只表示类实例。泛型在每次调用处仍是一个具体类型。
  • 协议里的类型参数写成关联类型。where 用来加更细的约束。
  • 编译器有时会按具体类型生成专门的函数。这是优化，语言不保证每次都会这样做。
func first<T: Equatable>(_ items: [T], equalTo target: T) -> T? {
    items.first { $0 == target }
}

三、内存、闭包与拷贝

10. ARC 是什么？strong、weak、unowned 怎么选？

  • 类和 actor 用 ARC。强引用计数到 0 就立刻 deinit，没有垃圾回收那种停顿。
  • 属性默认是强引用，会把对象留住。
  • weak 不增加计数。对象释放后，weak 引用自动变成 nil，所以必须是可选的 var。ARC 把 weak 引用置为 nil 时，不会走属性观察器。
  • unowned 也不增加计数，但不会变成 nil。只有确定对象活得比这次引用久才用。对象没了还去访问，会直接崩。
  • weak 和 unowned 只能用在类、actor，以及限定为类的协议上。结构体和枚举没有引用计数。
  • 谁先释放不确定，用 weak。生命周期绑在一起、被引用的对象一定更久，才考虑 unowned。

11. 这段代码为什么循环引用？weak 和 unowned 怎么选？

  • Owner 强引用闭包，闭包一创建又把 self 强抓住。两边互相持有，谁都释放不了。
  • 捕获列表写在闭包参数前面，用来改这次捕获的引用方式。[weak self] 不增加计数，self 先释放就变成 nil。
  • unowned 也不增加计数，但不会变成 nil。只有确定对象活得比闭包久才用，对象没了还去访问会直接崩。
class Owner {
    var work: (() -> Void)?
    func start() {
        work = { self.doWork() } // 强捕获 self，Owner 和闭包互相持有
    }
    func startSafely() {
        work = { [weak self] in self?.doWork() }
    }
    func doWork() {}
}

12. 闭包是引用类型吗？@escaping 改变了什么？为什么逃逸闭包不能捕获 inout？

  • 闭包是引用类型。赋值传出去的是同一个闭包，它会抓住外面的变量。抓住类实例时，默认是强引用。
  • 闭包参数默认不逃逸，函数返回后就不能再调用。@escaping 允许把它存起来，等函数返回之后再执行。
  • inout 只在这次调用期间指向外面那个变量。函数一返回，这个指向就作废了。
  • 逃逸闭包可能活得比函数久，不能抓住 inout。不逃逸的闭包出不了函数，所以可以捕获 inout。

13. 为什么 Array、String、Dictionary、Set 是值类型？copy-on-write 怎么发生？自定义结构体为什么不会自动有？

  • 它们做成值类型，是为了赋值、传参之后各改各的，不共享一块可变状态。
  • 赋值时先共用底层那块数据，并没有马上拷走。等到要改，并且这块数据还有别人在用，才复制一份再改。只剩自己这一份，就原地改。
  • 自己写的结构体没有 copy-on-write，赋值就是把属性拷走。要做成改的时候才复制，得自己用一个类拿着那块数据，改之前用 isKnownUniquelyReferenced 看还有没有别人在用：有就先复制，没有就原地改。
final class Storage {
    var items: [Int]
    init(_ items: [Int]) { self.items = items }
}
struct Queue {
    private var storage = Storage([])
    mutating func append(_ n: Int) {
        if !isKnownUniquelyReferenced(&storage) {
            storage = Storage(storage.items)
        }
        storage.items.append(n)
    }
}

四、协议

14. 为什么说 Swift 是面向协议编程的？

  • 结构体和枚举也能遵循协议，想复用代码，不必先写个类去继承。
  • 协议扩展可以给默认实现，已有的类型也能事后补上一个能力。
  • 需要什么能力就组合什么协议。要分清是不是同一个对象、要继承，或者要在销毁时做事（deinit），再用类。

15. Swift 协议和 OC 协议有什么区别？

  • 原生 Swift 协议，结构体和枚举也能遵循，还可以有关联类型和默认实现，但不能写 optional 方法。
  • OC 的 optional 要求协议和方法都暴露给 OC，遵循者必须是类。Swift 里想做成可有可无，一般拆成小协议，或者在扩展里给一个默认实现。
  • 找方法的方式也不一样。Swift 协议靠一张方法表（witness table）找到实现；标了 @objc 的协议靠 Objective-C 按方法名去找，结构体和枚举也不能遵循它。

16. some 和 any 差在哪？

  • some P 背后是一个具体类型。调用方看不见，编译器看得见。用在返回值上时，每条路径都必须返回同一种类型，编译器往往能直接调到具体类型的方法，一般也不用再套一层盒子。
  • 用在参数上的 some P 就是 <T: P> 的简写，调用方决定具体类型。
  • any P 是一个盒子，每次可以装不同的遵循类型。调用时要先查方法表才能找到实现，值太大还会被挪到堆上。不需要把具体类型藏起来时，优先用 some。
func one() -> some Greeter { Pirate() }
func anyOne() -> any Greeter { Pirate() }

17. 协议扩展里写了方法，为什么有时调用不到类型自己的实现？

  • 写进协议要求里的方法，调用时会查方法表，所以能调到类型自己写的实现。
  • 只写在扩展里、协议没要求的方法，编译器按当时看到的类型直接调用，不会再去找类型自己的同名方法。
  • 所以示例里 g 的类型是 any Greeter 时，hello() 是 "Ahoy"，bye() 却是扩展里的 "Bye"。把 bye 补进协议要求，才会调到 Pirate 的版本。
protocol Greeter {
    func hello() -> String
}
extension Greeter {
    func hello() -> String { "Hello" }
    func bye() -> String { "Bye" } // 不是协议要求
}
struct Pirate: Greeter {
    func hello() -> String { "Ahoy" }
    func bye() -> String { "Arr" }
}
let g: any Greeter = Pirate()
g.hello() // "Ahoy"，查方法表，调到 Pirate
g.bye()   // "Bye"，按 any Greeter 直接调扩展

18. 带关联类型的协议为什么往往不能直接写成 any？主关联类型解决了什么？

  • 关联类型还没定成一个具体类型时，协议方法里用到它的地方就不知道是什么类型。Swift 5.7 之前，这种协议不能写成 any。
  • 现在可以写 any Collection，但元素是什么类型已经不知道了，很多用到元素类型的方法就调不了。比如 any RangeReplaceableCollection 不能直接 append，编译器不知道该往里放什么。
  • 主关联类型就是把最常用的那个类型写在尖括号里。any Collection<String> 把元素定成 String，用到元素类型的那些方法才能用。方法参数如果要求必须是这个具体类型自己（Self），通过 any 还是调不了：盒子里到底是哪种类型，调用的人不知道，传不进一个对得上的值。

19. 什么是条件遵循？[String] 为什么可以是 Sendable？

  • 条件遵循就是：类型参数符合要求，外层类型才遵循相应的协议。
  • Array 只有在 Element: Sendable 时才是 Sendable。Sendable 表示这个值可以交给别的任务，不会因此数据竞争。
  • String 可以安全地交给别的 actor 或任务，所以 [String] 可以。元素是普通的可变类时，数组也不行。
extension Array: Sendable where Element: Sendable {}

五、方法调用与对象布局

20. Swift 方法调用是如何实现的？

  • 编译的时候就能确定调哪个函数的，直接跳过去，编译器还可能把函数体嵌到调用的地方。结构体、枚举、标了 final 的方法，以及协议扩展里多出来的方法，都是这样。
  • 类里可以重写的方法走一张方法表（虚表）。调用时从对象开头找到这张表，按下标取出函数。子类重写，就是把表里这一格换成自己的函数。
  • 协议要求的方法走另一张表（witness table）。类型遵循协议时生成这张表，每个要求对应一个实现，调用时按下标去取。泛型有时会被编译器按具体类型改成直接调用，那只是优化，语言不保证。
  • 标了 dynamic，或者重写了 Objective-C 的方法，会走 objc_msgSend。它拿方法名去缓存和方法列表里找函数，找不到再问父类。只加 @objc 时，从 Swift 里直接调用仍可能走类的虚表。

21. Swift 协议的内部结构是什么？

  • 协议自己不占对象的内存。编译出来的是一份说明：叫什么、继承了谁、要求有哪些方法、属性和关联类型。
  • 类型一遵循，就生成一张方法表（witness table）。每个要求占一格，指向这个类型自己的实现；类型没写的，就指向扩展里的默认实现。
  • 所以调协议方法，不是在协议上找函数，而是拿这张表，按下标跳过去。

22. 把协议当成类型（any P）时，运行时里面有什么？

  • any P 在运行时是一个盒子（existential container），里面有三样东西：一小块放值的空间、这个值的类型信息、协议的方法表。类型信息用来拷贝和销毁这个值，方法表用来找该调哪个函数。
  • 值不大（不超过三个指针那么大）就直接放在这块空间里；太大就放到堆上，空间里只留一个指针。
  • 调用协议方法都要先查这张方法表。编译器不知道盒子里具体是什么类型，不能直接跳到那个函数。

23. Swift 实例对象、类、元类的内部结构如何？

  • 实例在堆上。开头是指向它的类的指针，接着是引用计数，后面才是存的那些属性。
  • 类在运行时就是一份说明。里面记着父类是谁、实例有多大、属性放在哪、方法表在哪。另外还有一份编译时写好的描述，里面是类名、有哪些属性和方法。
  • 纯 Swift 类没有单独的元类。实例方法和类方法都记在这份运行时说明上。
  • 只有继承 NSObject 才有元类。实例靠开头的 isa 指针找到自己的类，类再靠 isa 找到元类。最顶上那个元类的 isa 指回自己，它的父类是 NSObject。实例方法记在类上，类方法记在元类上。

六、并发

24. Swift async/await 和 GCD 有什么区别？await 会不会堵住当前线程？

  • await 挂起的是当前任务，线程不会干等，可以转去跑别的任务。
  • GCD 是把闭包提交到队列。sync、信号量，或者在锁上干等，才会一直占着线程。
  • 别在异步函数里用信号量把 await 改成死等。Swift 用来跑这些任务的线程不多。线程都堵在等待上，别的任务就没线程可跑，严重时还会自己等自己，谁也继续不了。

25. actor 和类有什么差别？赋值之后谁和谁共享状态？

  • actor 也是引用类型。赋值之后还是同一个 actor，两边看到的是同一份状态。
  • 它里面能改的数据，同一时间只让一个任务碰。没遇到 await 时别人进不来；执行到 await，这个任务先停下来，别的任务才能进来改。
  • 类没有这层隔离。多个任务可以同时改同一个类的属性。
  • actor 自动遵循 Sendable，可以把这个引用交给别的任务。交出去的是引用，里面的状态仍然只在这个 actor 上改。

26. async let、TaskGroup、Task、Task.detached 分别是谁的子任务？

  • async let 和 TaskGroup 创建的是当前任务的子任务。它们离开当前作用域就会被取消，父任务取消时也会一起取消。
  • Task { } 不是子任务。它沿用当前 actor、优先级，以及任务上带着的局部值（task local），但外层任务取消或者函数返回，都不会自动取消它。要停就自己留着这个 Task，调用 cancel()。
  • Task.detached 也不是子任务，而且不沿用当前 actor、优先级和任务上的局部值。

27. 取消为什么是协作式的？页面已经消失，请求为什么还在跑？

  • 取消只是把任务标成已取消，不会把正在跑的代码掐断。
  • 任务要自己看 Task.isCancelled，或者走到会检查取消的接口，比如 Task.checkCancellation()，才会停。同步死循环不看这个标记，就会一直跑。
  • 页面里另外 Task { } 出来的任务没有父子关系，页面没了也不会把它一起取消。要停，就在离开页面时自己 cancel()。

28. Sendable 保证什么？@unchecked Sendable 在承诺什么？

  • Sendable 表示这个值可以跨 actor、跨任务传，不会因此数据竞争。值类型传过去的是副本。
  • 属性都是 Sendable 的结构体和枚举可以遵循它。actor 自动遵循。类一般要是 final，属性还得是不可变的 Sendable。
  • @unchecked Sendable 是你自己打包票：编译器不再检查。你得自己保证不会有两处同时改它，比如把它关在 actor 里，或者自己加锁。保证错了，数据竞争还在。

29. @MainActor 保证的是什么？界面卡顿时先看什么？

  • @MainActor 保证这段代码在主 actor 上执行，也就是跑在主线程上。
  • 界面卡的时候，先看主线程上有没有很重的计算、有没有在干等，以及有没有本来可以放到别的 actor 上做的事。
  • @MainActor 只管代码在哪跑，不会把重活自动变成异步。标上 @MainActor 之后，照样可以堵主线程。

30. actor 重入是什么？await 之后写缓存为什么会写错？

  • actor 只保证没停在 await 上的时候，只有一个任务在跑。一到 await，当前任务先让开，别的调用就能进来改同一份数据。
  • 先看到缓存里没有，再去下载，回来不管中间发生了什么都写入，可能盖掉这段时间里已经写好的结果。两个调用都发现没有缓存，还会各下载一遍。
  • 把正在下载的 Task 放进缓存。后来的调用发现已经在下了，就等这一次的结果，不要再下一遍。
actor ImageCache {
    private var cache: [URL: Data] = [:]
    func image(for url: URL) async throws -> Data {
        if let cached = cache[url] { return cached }
        let data = try await download(url) // 停在这里等的时候，其他调用可以进来
        cache[url] = data // 可能盖掉这段时间里已经写好的结果
        return data
    }
}

31. 怎么把 completion 或 delegate 桥成 async？调用方不再等待时怎么结束？

  • 只回调一次，用 withCheckedContinuation；会失败就用 withCheckedThrowingContinuation。拿到结果后必须刚好调用一次 resume：一次都不调，等结果的任务会一直停着；调两次，运行时直接报错。
  • 会回调很多次，用 AsyncStream。取消或者对象释放时调用 finish，把这条流结束掉。
  • 调用方不再等了，原来的回调不会自己停。取消时要把这个回调注销掉，可以放在 withTaskCancellationHandler 里做。

32. Swift 6 语言模式把什么变成了编译错误？它和编译器版本是一回事吗？

  • Swift 6 语言模式把数据竞争从警告变成编译错误。一份能改的数据被不同的 actor 或任务一起用，又没有标 Sendable，也没有关在某个 actor 里，就编不过。
  • 编译器版本和语言模式是两回事。Swift 6 编译器仍可以按 Swift 5 模式编译某个 target，这时同样的问题多半还是警告。
  • 有个例外：一个值就算没有标 Sendable，只要编译器能证明把它交给别的任务之后，当前代码不再用，就允许传过去。

33. Swift 6.2 之后，一个 nonisolated async 函数默认跑在哪？@concurrent 做什么？

  • 没开 NonisolatedNonsendingByDefault 时，nonisolated async 还是会跑到公共的并发线程池上，这是 6.2 之前的行为。
  • 打开 NonisolatedNonsendingByDefault 之后，这种函数默认留在调用它的那个 actor 上，不再自己跑到线程池里。Xcode 的 Approachable Concurrency 会打开这个开关。
  • @concurrent 用来明确说：离开调用方，放到并发线程池里跑。这样参数和返回值就必须能安全地交给别的 actor 或任务。NonisolatedNonsendingByDefault 开没开，同一段 nonisolated async 函数跑的地方不一样。
