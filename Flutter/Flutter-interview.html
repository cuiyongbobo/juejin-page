Flutter 面试题整理

建古
2022-02-23 21,972 阅读14分钟

修订说明（2026-10-23）：本页已按当前 Flutter / Dart 语义修订原文答案，重点校正 Widget / Element / State、async-await、渲染线程、Isolate、mixin、Framework / Engine 分层等概念；原文未作答的题目也补充了简要答案。

1. Dart 语法中 dynamic、var、Object 三者的区别

  • var：让编译器推断静态类型。推断完成后，这个变量的静态类型就固定了；变量本身仍可重新赋值，但只能赋兼容类型的值。
  • Object：所有非空 Dart 对象的根类型。静态类型检查仍然生效；要调用具体子类成员，通常需要类型判断或显式转换。
  • dynamic：表示绕过大多数静态类型检查，类型错误推迟到运行时发现；可以赋任意值，包括 null，但牺牲编译期安全性。
  • 更准确地说，var 的“类型不可变”指静态类型不可变，不是指对象或变量值不可变。

2. const 和 final 的区别

相同点：二者声明的变量都只能被赋值一次。

主要区别：

  • final：运行时确定后不可再赋值，可以用于实例变量；它修饰的是变量绑定，被引用的对象本身可能是可变的。
  • const：编译期常量，值必须由常量表达式组成；const 对象是深不可变的，例如 const [] 不能添加或修改元素。
  • Dart 不允许实例字段声明为 const；类中的常量字段通常写作 static const。
  • const 构造函数要求类的实例字段都是 final，且构造参数满足常量表达式条件，用于创建编译期规范化的常量对象。

3. Dart 中 ?? 与 ??= 的区别

  • a ?? b：如果 a 为 null，表达式返回 b；否则返回 a。
  • a ??= b：如果 a 为 null，才把 b 赋给 a；表达式返回赋值后的结果。

4. 什么是 Flutter 里的 Key？有什么用？

Key 用于在 Widget 树、Element 树和语义树中标识对应的节点，帮助 Element 树在复用或移动节点时判断状态是否应该保留。

  • LocalKey：作用于同一父节点下的同级节点比较，常见子类包括 ValueKey、ObjectKey、UniqueKey。当同级列表的顺序、数量发生变化时，key 能让 State 与正确的逻辑节点保持关联。
  • GlobalKey：全局唯一，可以跨子树移动并保留 State / context，也能用于访问对应的 State、Widget 或 BuildContext，但滥用会增加复杂度和成本。

5. Flutter 中的 GlobalKey 是什么，有什么作用

  • GlobalKey 是全局唯一 key，可以在 Widget 树中唯一标识一个 Element。
  • 通过它可以获取 currentState、currentContext、currentWidget。
  • 当对应 Widget 被移动到别的父节点时，GlobalKey 有机会保留其 State，而不是销毁后重建。
  • 适合少量需要跨组件访问 State 的场景；不应把它当作常规状态管理方案。

6. main() 和 runApp() 的作用分别是什么？有什么关系？

  • main() 是 Dart 程序入口。
  • runApp() 负责初始化 Binding，并把传入的 Widget 作为根 Widget 挂载到 Flutter 视图上，从而启动 Widget / Element / RenderObject 树。
  • 典型写法是在 main() 中调用 runApp(const MyApp())。

7. 什么是 Widget？有哪几类？生命周期有什么区别？

Widget 是不可变的 UI 配置描述，不只是“UI 组件”。Flutter 会把 Widget inflate 成 Element，再由 Element 管理 State 和 RenderObject。

StatelessWidget 和 StatefulWidget 是最常见的两类状态组织方式，但并不是 Widget 体系仅有的两类；还有 InheritedWidget、RenderObjectWidget、ParentDataWidget 等。

  • StatelessWidget：没有单独的 State 对象，构建只依赖构造参数、InheritedWidget 等输入；输入变化后由父级重建。
  • StatefulWidget：由 Element 创建并持有 State；调用 setState() 会把当前 Element 标记为 dirty，下一帧重新执行 build。Widget 本身不会“自己重建”。

State 常见生命周期：

  1. createState()
  2. initState()：插入树时一次初始化；末尾必须调用 super.initState()。
  3. didChangeDependencies()：依赖的 InheritedWidget 变化时调用。
  4. build()：生成 Widget。
  5. didUpdateWidget()：父级传入的 Widget 配置变化且 Element 被复用时调用。
  6. setState()：标记需要重新 build。
  7. reassemble()：热重载时调用，主要用于调试。
  8. deactivate()：Element 从树中移除或移动时调用。
  9. dispose()：永久销毁前释放资源；自己的释放逻辑完成后必须调用 super.dispose()。

8. 简单说一下 Flutter / Dart 中的 async 和 await

  • async 标记的函数被调用时会立即返回 Future；函数体内的代码异步执行。
  • await 是挂起点：它会暂停当前 async 函数的后续代码，把控制权交回事件循环；被等待的 Future 完成后，再恢复执行后续代码。
  • await 不阻塞当前线程或 isolate，也不等于“结束当前函数”；它只是挂起当前函数的后续执行。
  • async 函数中可以没有 await，也可以有多个 await。

9. Future 和 Stream 有什么不一样？

  • Future<T>：表示一个稍后完成的值，只能完成一次，结果可以是成功值或错误。
  • Stream<T>：表示一段时间内连续产生的事件序列，可以发出多个数据事件、错误事件和完成事件。
  • Future 适合一次请求；Stream 适合日志、网络状态、传感器、WebSocket 等持续数据。

10. Widget、Element、RenderObject、Layer 都有什么关系？

  • Widget：不可变配置，描述 UI 应该是什么样。
  • Element：Widget 在树中的实例化结果，是树上的持久节点；负责生命周期、状态管理、diff / reconciliation，并持有当前 Widget。
  • State：StatefulWidget 对应的可变状态，由 Element 创建和持有，不是由 Widget 直接管理。
  • RenderObject：负责布局、绘制、命中测试等渲染相关工作。
  • Layer：绘制阶段生成的合成层描述；Layer Tree 会被提交到 raster 线程做合成和光栅化。RepaintBoundary 可以隔离重绘范围。
  • Element 并不是绝对“不会被重建”。当新旧 Widget 的 runtimeType 和 key 匹配时，Element 可以复用并更新；不匹配时旧 Element 会被 deactivate / unmount，再创建新的 Element。

11. 简述 State 的生命周期

createState → initState → didChangeDependencies → build；运行中可能反复出现 setState / build，依赖变化时调用 didChangeDependencies，父 Widget 更新且 Element 复用时调用 didUpdateWidget；最后在移除或销毁时经过 deactivate，再到 dispose。

12. 简述 Flutter 中自定义 View 的流程

  • 优先组合已有 Widget，保持声明式和可维护性。
  • 需要自绘时使用 CustomPaint，实现 Painter / hitTest 等逻辑。
  • 需要自定义布局或渲染协议时，实现 RenderObjectWidget 与对应的 RenderBox / RenderObject，覆写 performLayout、paint、hitTest 等。
  • 同时考虑语义、无障碍、事件命中、parent data、性能和重绘范围。

13. flutter_boost 的优缺点和内部实现

flutter_boost 主要用于混合栈方案，把 Flutter 页面嵌入原生导航容器，并通过路由映射和消息机制同步原生与 Flutter 的页面栈。

  • 优点：便于已有原生 App 渐进式接入 Flutter；复用原生导航、转场和容器能力。
  • 缺点：引入额外路由、生命周期和引擎管理复杂度；需要处理多引擎 / 容器复用、内存、插件和页面状态同步等问题。
  • 内部通常涉及原生容器管理、FlutterView / engine 复用、路由映射、页面生命周期通知和原生-Flutter 通信。

14. Flutter 的渲染机制

  • 平台 / 显示系统产生 VSync 等帧信号，触发 Flutter 调度。
  • UI 线程执行 Dart 代码，完成 build、layout、paint 的对象构建，生成 Layer Tree。
  • Raster 线程接收 Layer Tree，进行图层合成与光栅化，并把 GPU 命令提交给 GPU。
  • IO 线程负责图片解码等耗时资源准备，避免阻塞 UI / raster。
  • 历史上 Flutter 主要使用 Skia；较新版本引入并推进 Impeller，以减少着色器编译卡顿等问题。具体渲染后端取决于 Flutter 版本和平台配置。

15. Flutter 和 Native 的优缺点

  • Flutter 优点：跨平台 UI 一致性好、开发效率高、热重载体验好、复杂 UI 性能通常接近原生。
  • Flutter 缺点：包体积增加、平台差异和插件依赖仍需处理、部分强平台能力要通过原生集成。
  • Native 优点：系统 API、性能调优、无障碍、包体积和平台深度集成更直接。
  • Native 缺点：多端维护成本更高，UI 复用能力弱。

16. Flutter 支不支持 120Hz？

支持，但实际刷新率取决于设备屏幕、操作系统显示模式、Flutter Engine / 平台配置以及每帧是否能在 8ms 左右完成。需要确保没有强制固定帧率、平台模式正确，且 UI / raster 线程没有长时间阻塞。

17. 状态管理熟悉哪些？

  • 局部状态：setState、父组件向子组件传参、InheritedWidget。
  • 常用方案：Provider、Riverpod、BLoC / Bloc、Redux、MobX、signals 等。
  • 选择时应关注依赖方向、可测试性、粒度和团队熟悉度，避免为简单页面引入过重方案。

18. Flutter / Dart 多线程怎么处理？

  • Dart 的并发模型以 isolate 为核心；isolate 之间没有共享可变对象，需要消息通信。
  • 短小耗时任务可使用 compute 或 Isolate.run；更复杂任务可使用 Isolate.spawn。
  • UI isolate 不应执行长同步计算、大文件解析、图片压缩等任务，否则会掉帧。
  • 平台线程相关逻辑通过平台通道、Task Runner 或平台 API 调度处理。

19. Flutter 中大图片上传怎么处理？

  • 先压缩、缩放或转换格式，减少网络流量和内存占用。
  • 大文件使用分片 / multipart 上传，并支持进度、取消、断点续传和重试。
  • 压缩、哈希、分片等耗时操作放到后台 isolate。
  • 上传过程用 Stream 或状态管理展示进度；完成后清理临时文件并处理平台差异。

20. await for 如何使用？

await for 用于异步遍历 Stream。每当一个事件到达，就执行一次循环体；Stream 完成后，循环结束，后续代码继续执行。循环体内可以使用 break 提前退出，也应注意在循环外取消订阅或关闭资源。

await for (final event in stream) {
  print(event);
  if (event == 'stop') break;
}

21. Stream 有两种订阅模式

  • 单订阅 Stream：只能有一个监听者，事件按顺序推送，适合一次读取的数据源。
  • 广播 Stream：可以有多个监听者，事件会同时分发给所有活跃订阅，适合网络状态、主题切换等通知型数据。

22. build 方法中的 BuildContext 是什么？

BuildContext 是 Element 对外暴露的接口。Widget 的 build 方法通过 context 与 Element 树交互，例如向上查找 InheritedWidget、NavigatorState、Theme 等。依赖查找发生在 Element 树上，不是同时遍历 Widget 树。

23. Flutter 打包 Web、移动端、桌面端的过程

  • Web：flutter build web，产出静态资源，由浏览器加载；可选 renderer。
  • Android：flutter build apk 或 flutter build appbundle，包含 Dart AOT 产物、资源、so 和原生打包结果。
  • iOS：flutter build ios / Xcode archive，产出 app / ipa。
  • 桌面端：配置对应平台后使用 flutter build macos / windows / linux。
  • 共同点：编译模式通常为 release / AOT，随后处理资源、插件、图标、签名、混淆和平台产物。

24. Dart 是值传递还是引用传递？

更准确的说法是：Dart 按值传递对象引用。函数参数得到的是引用的拷贝，因此修改对象字段会影响外部对象；但在函数内重新给参数赋值，不会改变外部变量。

25. Dart 是弱引用还是强引用？

普通对象引用默认是强引用。Dart 也提供 WeakReference 和 Finalizer，可用于缓存或清理辅助资源，但它们不改变普通引用的默认语义。

26. get / set 方法如何实现？

Dart 使用 getter / setter 声明：

class Temperature {
  double _celsius = 0;

  double get celsius => _celsius;
  set celsius(double value) {
    assert(value >= -273.15);
    _celsius = value;
  }

  double get fahrenheit => _celsius * 9 / 5 + 32;
}

27. Flutter 如何与 Android / iOS 原生通信？

  • BasicMessageChannel：双向消息传递，可通过 codec 支持结构化数据、二进制数据等，不限于字符串。
  • MethodChannel：方法调用和方法返回值 / 错误。
  • EventChannel：原生向 Dart 持续推送事件流。
  • 平台通道实现不保证线程安全。原生侧应把调用调度到正确线程或 Task Runner；Dart 侧通常在 root isolate 调用。

28. 简述 Flutter 的热重载

  • 热重载依赖 debug / JIT 模式下的增量编译，把修改后的 Dart 库推送到运行中的 VM。
  • Flutter 会更新代码并触发 widget 树 reassemble / rebuild，尽量保留 State。
  • 它不是简单的 repaint，也不是完整重启。
  • 无法覆盖所有修改：例如 main()、initState() 已执行过的初始化逻辑不会自动重跑；全局变量、枚举、泛型结构、Native 代码或不兼容状态可能需要热重启甚至冷启动。

29. 怎么理解 Isolate？

Isolate 是 Dart 的并发执行单元，类似 actor 模型：每个 isolate 有自己的执行栈和对象堆，没有共享可变 Dart 对象，因此不需要传统锁来保护共享字段。isolate 之间通过 SendPort / ReceivePort 传递消息。Dart VM 中 isolate 可以被调度到不同线程并行执行。

30. Dart 的作用域

Dart 没有语言级 public / protected / private 关键字。库内默认公开；以下划线开头的名称是库私有。类内部可通过命名参数、私有字段和 getter / setter 控制访问方式。包级别公开性由库导出控制。

31. Dart 的 .. 表示什么？

.. 是级联操作符，用于对同一个对象连续执行操作，并返回原对象，而不是返回某个方法的结果。Dart 还有空安全版本 ?..。

32. Dart 是不是单线程模型？是如何运行的？

更严谨地说，一个 isolate 是单线程执行模型；一个 Flutter App 可以同时存在多个 isolate。每个 isolate 有自己的事件循环、微任务队列和事件队列。当前同步代码执行完后，先清空微任务队列，再处理事件队列中的下一个事件，如此循环。

33. Dart 如何实现多任务并行？

  • Dart 不能通过共享内存多线程编程实现并行，而是通过多个 isolate 并发执行。
  • Isolate.run / compute 适合“传任务、返回结果”的场景；Isolate.spawn 适合长期运行的独立 isolate。
  • isolate 之间通过 SendPort / ReceivePort 消息通信，传递的数据需要序列化或转移。
  • “Dart 没有多线程”这个说法不准确：VM 可以把多个 isolate 调度到不同底层线程并行执行；只是没有共享可变内存的传统线程模型。

34. Dart 异步编程中的 Future 是什么？

Future 表示一个异步任务的最终结果。创建 Future 后调用立即返回，调用者可以先继续执行或通过 await 等待结果。每个 isolate 的事件循环优先执行当前同步代码，再清空微任务，然后处理事件队列。

35. 说一下 mixin 机制

  • mixin 是一种横向复用代码的机制，通过 with 混入多个行为。
  • 它不是多重继承，也不是接口实现；方法冲突按线性化顺序处理。
  • mixin 声明不能有生成式构造函数，可以用 on 约束被混入类的父类型。
  • 不要说“Dart 为了支持多重继承引入 mixin”；Dart 恰恰不支持类的多重继承。

36. 介绍 Flutter 的 Framework 层和 Engine 层

  • Framework：Dart 编写的应用开发框架，包含 Widgets、Rendering、Animation、Gestures、Painting、Material、Cupertino 等层次。
  • Engine：主要由 C++ 编写，包含 Dart 运行时、文本排版、图形绘制、平台事件等能力，并向 Framework 暴露 dart:ui 这类底层接口。
  • dart:ui 是 Framework 与 Engine 交互的底层库，不是整个 Flutter Framework。应用通常导入 package:flutter/material.dart 等库，而不是只导入 dart:ui。
  • Engine 的渲染后端历史上主要是 Skia，新版本逐步使用 Impeller；不能简单说“Framework SDK 被封装为 dart:ui”。

37. 简述 Flutter 的线程管理模型

  • Embedder 负责创建平台线程、UI 线程、Raster 线程、IO 线程，并把它们作为 Task Runner 提供给 Engine；Engine 要求相关线程在生命周期内保持稳定。
  • Platform Task Runner：处理平台消息、插件、事件输入等。
  • UI Task Runner：执行 Dart root isolate、build、layout、生成 Layer Tree。
  • Raster Task Runner：合成与光栅化 Layer Tree，提交 GPU 命令。
  • IO Task Runner：图片解码、资源读取等耗时 IO。
  • 新 isolate 由 Dart VM 调度，不应简单说由 Flutter Framework 统一管理。

38. 介绍 Flutter 的整体架构

  • Embedder：操作系统适配层，负责 surface、线程、事件、插件容器等平台集成。
  • Engine：Dart VM / runtime、文本、图形、平台能力，并通过 dart:ui 暴露给 Framework。
  • Framework：Dart 编写的 Widget、Rendering、Animation、Gestures、Material / Cupertino 等开发库。

39. Future 和 Isolate 有什么区别？

  • Future 表示一个异步任务稍后的结果，仍运行在当前 isolate 的事件模型中；适合 IO、网络请求、定时器等非阻塞异步任务。
  • Isolate 是独立并发执行单元，有自己的堆内存，没有共享可变状态；适合 CPU 密集计算或需要并行的任务。
  • isolate 之间通过 port 消息通信；isolate 是抽象概念，VM 可能将其调度到不同线程，但 isolate 不等价于线程。

40. 什么是 Navigator？MaterialApp 做了什么？

Navigator 是 Flutter 的路由栈管理 Widget，维护 Route 的入栈、出栈、替换和转场。MaterialApp / WidgetsApp 会创建必要的 Navigator 配置。Navigator.of(context) 会沿 Element 树向上查找最近的 NavigatorState，再调用 push / pop 等方法。
